# Findings & Decisions

## Requirements
- Keep existing project, asset, model, and provider data intact.
- Implement editable source intervals and adjacent cut review before decorative transitions.

## Research Findings
- Existing `shots.duration` is a planned integer duration (1-30 seconds) and `selected_asset_id` points to one candidate. There is no source in/out interval.
- `render.ts` trims every source from time zero and clones the last video frame to pad short sources. Export selects only shots with assets, silently skipping missing shots.
- Shot changes clear image and video references in `App.tsx`. Seedance modes are model-configurable, so continuity handoff can use existing first-frame/reference modes.
- Existing 60-second sample has obvious resets at roughly 25, 35, and 40 seconds; the workflow needs cut inspection and reshooting, not a blanket transition effect.

## Technical Decisions
| Decision | Rationale |
|----------|-----------|
| Use a separate timeline clip record | Planned shots and actual edited intervals have different lifecycles. |
| Keep one timeline clip per selected shot initially | Current UI has a shot-ordered storyline; this introduces real source editing without a disruptive multitrack rewrite. |
| Represent edit points in milliseconds | Fractional cuts are needed for action timing; `shots.duration` stays the planned integer duration. |
| Video clip bounds use probed source duration; still images may display for 0.2–30 seconds | Prevent frozen video padding while allowing intentional stills. |
| AI planner emits varied durations and shot boundary states | The user's 60-second target is for the whole work, not a per-shot constant. |

## Issues Encountered
| Issue | Resolution |
|-------|------------|
| Workspace has no Git repository | Review modified files directly; preserve existing root planning files. |
| Local asset endpoint did not support HTTP byte ranges | Add partial responses so video seeking to a nonzero in-point can load without fetching a full large file. |
| Container duration can exceed video-track duration | Validate cuts against actual video-frame coverage to avoid a frozen tail in export. |
| Timeline edit coordinates stopped at 600000 ms | Permit safe integer positions through the source duration; validate the cut length and media bounds separately. |

## Implementation Notes
- The media endpoint now supports single byte ranges (200/206/416 and HEAD), allowing browser seeking into large local video files. A live range request returned `206` and exactly two bytes.
- Video duration checks now use the actual picture track. A regression with one second of video and two seconds of audio rejects a 1.5-second video cut instead of exporting a frozen tail.
- Accurate picture-track probing remuxes the video track once per file and caches by path, size, and modification time. The first probe of a large file can temporarily consume disk space and block the local server while FFmpeg scans it; the operation has a 120-second timeout.
- Frame extraction now seeks before input decoding, so comparing frames deep into a long source avoids decoding from its beginning.

## Runtime Check
- Ego Lite TaskSpace 19 played the existing 12-clip project across the first two cuts. The clock and active shot advanced from 01 to 03; playback continued to shot 07 without a media error and paused cleanly. No model or provider request was made.
- The legacy project still has twelve five-second source selections. Existing generated footage is unchanged; continuity must be reviewed and poor shots regenerated by the user.
