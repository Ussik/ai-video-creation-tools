## 现场事实与故障

当前轮的 5 条模型请求均为 completed，但下一步检查点仍保存 initial_started，恢复台账 blockers 为 0。旧质量 grant 已在上一轮独立复核阶段，当前清单则有 2 条新的质量意见。原界面在 blockers 为空时只刷新并关闭弹窗，未改变残留标记，因此反复空转。

历史标记没有本次新增的精确 intent 身份与可信本地拒绝事件。缺少台账、相同错误文案或现在能够复现门禁拒绝，都不能单独证明原尝试从未发送。新程序将此状态显示为 inconsistent / inspect_conflict，保留原标记与成果，不伪造 not_sent。

## 实现

- 在派发前持久化唯一 intent_id，绑定输入 hash、初始输入 hash 与初始/纠正阶段。只有代码持有且已持久化的派发前拒绝证明才能释放精确匹配的 marker。
- 派发日志、许可消耗与同步观察回调在同一事务中完成；拒绝回滚，不把本地未发出误记成远端未知。已发送、已受理、预算中断及完成落库冲突继续保留保护。
- 为准入结果增加私有审计；使用事实前重新验证台账、后台回答、派发链接与迟到事件。旧 marker、伪造事实、错误 run/hash 或过期事实都不能清理未知状态。
- background 路径仅清理本尝试在可信拒绝窗口新建的 creating，并与拒绝审计同事务；旧 creating 和 accepted 不受影响。
- 本地 revalidate 运行在 completed-only 域。没有保存回答时明确暂停，不创建新的 initial_started / correction_started，也不触发模型或额外格式纠正。
- 独立复核产生新意见后关闭并归档旧质量轮。新一轮需要精确范围与独立用量确认；新轮确认不能绕过 unknown、no_progress 或 uncertain，也不能借用无关旧恢复许可。
- GET 恢复详情保持只读，独立表达完整保存回答与未知请求。其他任务的未知不会遮住可本地复用的完整回答；同一检查点的未知纠正仍受保护。
- 正式 POST /request-recovery/reconcile 仅做版本检查、事务 CAS、幂等及独立审计，不启动模型、不建新执行或许可、不自动校验。完整回答由后续独立的“重新校验保存回答”按钮处理，避免审计完成但校验前重启导致动作被吞。
- 恢复弹窗不再因空列表关闭；显示具体状态与下一步。新的本地事实可用时，不再显示旧普通续接的“没有需要人工处理的未知请求”或付费预算提示。已完成本地校验后读取实际状态，防止旧按钮重复空转。
- 四处严格私有检查点 schema 兼容可选 intent_id，旧检查点仍可读取。新轮私有历史不进入公开分析响应。
