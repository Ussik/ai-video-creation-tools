# 分集重新设计的场次身份恢复

## 问题与证据

2026-11-12 的分集重新设计任务已生成完整正文与三场候选（45、55、50 秒），但三场均遗漏 `source_scene_id`。任务因此在正文步骤完成后被 `validateWorkflowScenes` 拦截。原正文、已有场次和制作引用保持不变。

场次数量相等不代表对应关系正确。不能通过位置、标题或词语相似度替场次分配旧 ID，也不能放宽保留全部已有场次的要求。

## 实现

- `validateWorkflowScenes` 为缺少已有场次覆盖提供专用错误码。仅分集重新设计、缺少关联且候选数量足够时进入恢复；未知、跨集、重复 ID 及其他业务错误继续失败。
- 完整候选先保留。另一个只读模型步骤只提交旧 ID 与未绑定候选索引的对应提案、双方逐字引文和理由。已有合法关联锁定，新增场次保持无 ID。
- 提案必须逐项覆盖所有缺失旧 ID，且候选索引不可重复。旧场遗漏、被合并或无法确定时明确返回 unresolved，不触发强制重配。
- 独立模型任务阅读完整新旧正文、场次和提案，逐项复核所有旧场。真实引文和完整 ID 覆盖均不能代替剧情身份判断；语义拒绝停止本轮。
- 只有独立复核通过才给候选副本补 ID。正文、时长、顺序及其他字段原样保留，之后仍执行既有完整性审查、来源版本检查和创作者确认流程。
- 身份核对与完整正文审核分工明确：允许重新设计的场内细节、对白或节拍变化不等同整场消失。独立复核仅报告核心旧场不存在、无关匹配、无法一对一保留的合并、身份歧义四类问题；具体原稿保真要求仍由完整审核执行。复核合同版本使旧复核失效，成功映射无需重做。
- 映射和复核使用分别持久化的步骤，哈希绑定完整输入。失败步骤不记为成功，重试复用正文；合法提案被语义复核拒绝时保留提案，重试仅复核该提案。历史整集断点也可进入恢复。
- 实际续跑发现第二个问题：服务端扩充合同后，`workflow` 的属性顺序与重新解析顺序不同，导致恢复指纹和正文断点同时失配。恢复指纹现在固定序列化顺序；旧指纹仅在字段值完全等价时兼容，其余来源、模型和规则输入仍按当前状态重算。正文恢复仅查找四种历史合同扩充顺序及其精确完整 prompt，命中后沿用原输入顺序和原 prompt，保留已有正文及步骤哈希。
