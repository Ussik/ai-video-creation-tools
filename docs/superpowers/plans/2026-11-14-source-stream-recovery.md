# Source Stream Recovery Implementation Plan

> **For agentic workers:** Implement the tasks below in parallel with separate file ownership; perform one integrated review after focused tests.

**Goal:** Recover failed read-only source analysis without discarding validated work or replaying requests whose outcome is unknown, and reduce format-repair calls.

**Architecture:** Keep the current LangGraph orchestration. Make terminal stream failures durable and distinct from uncertain dispatches, select existing checkpointed synthesis tasks by output complexity, and apply only lossless source-contract normalization before validation.

**Tech Stack:** TypeScript, LangGraph, Zod, SQLite, Node test runner, existing Langfuse OTLP exporter.

**Spec:** User-approved optimization discussion in this chat, 2026-11-14.

## Global Constraints

- Work directly on the primary main checkout; preserve all pre-existing uncommitted changes.
- No model changes, reduced quality requirements, discarded source facts, real task resumption or paid model calls during implementation verification.
- Preserve full-source understanding, complete coverage and independent final quality review.
- Unknown accepted requests retain their dispatch barrier; partial text is never a valid result.
- Use existing dependencies and task/checkpoint structures; bound retries to one per model step.

## Review Focus

- Explicit terminal SSE failure after visible text versus unknown connection loss.
- Repeated continuation blocked before dispatch must not erase prior uncertain state.
- Cancellation and background response polling retain their original identities.
- Dense short source and interrupted subtasks reuse complete results only.
- Conflicting field aliases, unknown fields and malformed JSON cannot silently lose facts.
