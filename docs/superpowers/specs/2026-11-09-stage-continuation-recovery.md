# 阶段生成异常与语义单元冲突恢复

修复两张截图中的实际生成失败：上游 `bad_response_body` 删除钩子接续断点，以及模型重复使用已接收单元 ID 并改写正文后反复撞同一冲突。已有代码和审读分页修复保持兼容。

- 已校验的完整文档、场次和语义单元在普通提供商报错、断线、取消、鉴权失败后仍保存。停止本轮与删除合法成果是不同操作；错误本身不授权删除断点。内容过滤只回退当前响应新增的内容与诊断，保留先前干净响应的合法成果；首个响应被过滤且没有先前成果时不保留可采用断点，不得把已被过滤的当前响应升级为合法候选。
- 正常完整生成仍只需一次请求。真实输出超限仍启用原有接续；不把 `bad_response_body` 伪装成长度错误，不自动重放工具或写操作。
- 已保留单元不可改写。同 ID 不同正文的候选不进入可采用内容；保存具体冲突诊断，在同次执行中有限纠正，后续继续也读取诊断。
- 纠正请求携带完整来源、既有成果和已保留单元，明确保留 ID 及下一未完成输出范围，要求从未完成内容继续。不能自动改名后接纳冲突内容，也不能跳过冲突后采用 `complete:true`。拒稿正文与场次的精确重交即使换 ID 也不得接纳，当前目标的历史拒稿在显式核对后仍保持该限制；不作语义相似判断。目标确已完整时，可以通过显式核对待处理冲突后结束，不能强迫模型凭空新增条目才允许完成。
- 无进展或重复冲突停止本轮并保留断点；真实进展可以继续。用户取消优先。旧 v1 断点仍能继续；文稿、请求或配置身份变化仍不复用旧断点。
- 实际上游约 8K 额度与这两处程序修复独立。不得按模型名字注入不明渠道参数或修改用户模型设置；本次隔离测试不等于真实网关额度验收。

## 完整单元字段异常的恢复补充

场景设计的真实失败响应返回 HTTP 200、1,082 输出 token，却因接续单元未通过契约而停止；失败原单元未持久化，不能断言具体坏字段。可用合成数据确定性复现：已有合法正文后，下一完整单元漏 `scenes` 会直接失败，绕过字段纠错。

- 先保留合法前缀，再隔离保存整页原始对象、合法后缀及具体字段诊断，不丢弃或跳过异常单元。
- 对完整正文且仅元数据有误的单元，最多请求一次字段补丁。响应契约没有正文/场次字段；采用时从冻结原件还原，已有合法 ID/标题保持原样。
- 修复只允许补齐合法 ID/标题、为全剧文档明确补空 `scenes`、逐项确认移除已知保存元数据。不能删除未知创作字段、补写空正文、丢弃非空场次或改变场次语义。
- 修复失败、取消和过滤后保留干净断点；显式继续先处理待修页，不先重新生成正文。相同异常页在同次执行中只尝试一次修复。
- 完成标志与冲突确认必须再次通过当前完整契约。字段修好不等于任务完成；缺失/错误外层字段仍需后续合法完成响应。
- 旧 v1 断点兼容默认空待修页；历史多栏目断点只将待修页分给原 target，无目标的待修原文禁止推测归属。

## 2026-11-10：混合空结构与历史断点

实际道具功能任务的完整诊断包含一项 `scenes` 缺失，以及另一项 `id/title/content` 缺失。原页已被下一任务的项目单一工作区覆盖，只能用等形数据复现，不能声称实际空场次数组已得到证实。

- 对非分集文档，仅精确 `{scenes:[]}` 可进入空结构确认。必须由一次受限补丁按原候选 ID/顺序逐项确认移出，不能拼成前一个单元，不生成正文；任何身份字段、正文、未知字段、非空场次或分集模式都不能沿此路径被丢弃。
- 含空结构的响应即使原 `complete:true` 也不能结束目标。确认后保留审计与合法正文，再请求合法的接续/完成响应。审计按页哈希、位置、目标幂等记录，最多 200 项，不算语义进展。
- 错误主文案应指出页内实质性阻断，不能只截取前两条字段错误掩盖缺正文；完整字段路径继续作为技术诊断保存。
- 项目工作区切换身份前事务性归档旧断点，按精确身份或调用方明确列出的兼容身份恢复。兼容迁移消费实际旧副本；清除当前任务不能恢复其同身份或兼容旧副本，其他身份历史仍保留。不得修改正式文档、原稿或数据库结构。
