# 由模型选择创作技能

自动选技由模型理解当前任务、上下文及可用技能说明，再通过 Function Calling 提交选择。原先的关键词、正则匹配已移除。用户可以用自然语言提出要求，不需要固定句式或技能名。

## 使用

创作入口默认显示「模型自动选择」。输入文字、打开技能面板和预览配置都不会触发选技模型请求；发送实际任务后才选择。

- 导演对话：模型在现有工具循环中调用 `load_creation_skills`，提交环节、技能 ID 和简短理由，然后读取规则、执行已授权操作。
- 提示词整理、视觉设定、分镜及独立生成接口：执行前用当前文本模型调用 `select_creation_skills`，校验选择并加载规则，再执行原来的内容生成。
- 执行活动或结果中展示实际加载的技能和简短理由。这是适用理由，不是模型内部思考过程。
- 手动选择优先，空选 `[]` 表示本次仅用基础规则；「恢复模型自动选择」移除手动覆盖。图片／视频提示词保留浏览器中已有的手动记忆。

## 决策与校验

目录只包含当前环节已安装、已启用的技能，并提供名称、说明和版本。项目或全局默认作为参考，模型可以选择更适合的技能或不使用外部技能；默认空选不锁住自动模式，手动空选才是锁定。

第一项作为主技能，后续是必要的辅助技能，最多合计六项。程序校验 ID、启用状态、适用环节、重复项及数量。模型必须给出有效选择；失败或持续返回无效选择时终止本次执行，不静默回退到关键词匹配或默认技能。

同一导演工具会话中，环节首次加载的选择被冻结；后续不能改换该环节的技能。已选 ID 同步到本轮持久任务恢复记录；中断后沿用原选择与生成检查点，所选资源规则变化时拦截过期恢复。自动选择不写入项目或全局默认。

技能选择与创作／修改／保存授权分别处理。只读查询无需加载创作技能；模型选到技能不构成生成媒体或保存草稿的许可。审稿技能不能替代需要返回改写正文的整理接口。项目事实、明确要求和应用输出契约始终优先于外部技能。

## 实现与验证

- `backend/src/modules/skills/model-skill-selection.ts`：独立入口的模型选择、原生工具调用和校验。未注入原生选择器的库调用方使用模型结构化输出选择，仍由模型判断。
- `backend/src/modules/script/script-document-tools.ts`：导演工具目录、加载、手动锁定、当前会话冻结及创作前检查。
- `web/src/features/skills/useCreativeSkills.ts`：自动阶段省略 ID，只提交手动覆盖。
- `packages/shared/src/skills/skill-recommendation.ts`：仅保留任务上下文类型，已无关键词分配代码。

验证使用模拟模型响应，覆盖 Responses 与 Chat Completions 的真实工具传输格式、非法选择修正、手动空选、非默认选择、无配置写入及前端请求。没有使用真实付费模型或生成媒体。

技能规则资料的读取仍沿用原有机制；部分第三方参考文件／执行脚本尚未完整接入。选技能力不代表这些外部执行能力已补齐，也不代表完成了真实成片质量对比。

本轮验证结果：前端相关测试 66/66，模型选择／导演核心测试 141/141，完整构建通过。另一次独立接口及分镜／视觉回归 127 条中，125 条在沙箱内通过；本地模拟服务监听用例在放宽沙箱后通过，剩余一条为此前已复现的视觉年龄刷新失败（预期 32、实际 21）。浏览器已实看导演「模型自动选择」按钮和选择说明，未发送真实任务。
