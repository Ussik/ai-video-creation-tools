# 剧本对话的原文资料策略

> 实现核对：2026-10-22，代码基线 `9ba5a25`。正文长度、位置及资料包阈值按 JavaScript UTF-16 长度计算；token 容量另行估算。

当前优化覆盖普通原文查询及其原生工具调用、长稿全剧理解中后续人物批次的资料选择，以及候选稿修订分析、确认修订后的目录增量重分析。完整原稿仍保存在数据库，语义目录、全剧理解和原文位置辅助定位；模型的前一次阅读不会自动成为后一次请求的记忆。

## 请求范围

| 请求 | 当前处理 |
| --- | --- |
| 明确的称呼出现位置、指定集原话或局部事实查询 | 满足条件时提供全局背景、相关原文及相邻连续章节；通过原生工具补读 |
| 全剧、大纲、结局、身份、关系、伏笔、因果、创作或修改 | 使用完整有效稿 |
| 代词追问、混合要求、无匹配、目录未通过检查或选中范围过大 | 使用完整有效稿 |
| 阶段生成、文档修改、待确认草稿、最终独立审读 | 保留现有完整资料与确认保存流程 |
| 长稿整合的首批人物发现、全剧概览、时间线、伏笔、不确定事项和身份归并 | 使用完整有效稿 |
| 长稿整合的后续已知人物批次 | 满足证据包条件时提供相关逐字原文；资料不足时只将该批转为全文核实 |

普通查询局部路由由服务端规则决定，只接受完整匹配的只读事实问题，不让用户或模型自行声明切换模式。最新消息最多 500 字符、至多 4 个字面目标；选中正文超过 20,000 字符、覆盖全文，或资料包长度不小于全文时均保留全文。

普通查询的局部模式只有在分析完成、质量检查通过、分析版本匹配且原文目录覆盖完整时启用。查询目标必须有原文命中；目录漏记的称呼仍通过原文命中定位。补入相邻章节后会保留连续场次，区间合并去重。目录、全局摘要、结局摘要只作为定位线索，资料包明确标记 `coverage.complete_source:false`。

普通查询处于局部模式时仅开放读取函数，后端也拒绝模型返回的写入函数。最新用户原话、已确认画风、创作决定和原有对话窗口继续传递。资料不足时可以搜索、分段读取，或调用 `read_full_source_document` 补入同版本完整有效稿。补读全文仍然只回答本次查询，不构成修改授权。

## 版本和分页

- `source_version` 标识本轮有效稿，包含文件名、正文和替换时间；同内容重新上传也会更换版本。
- `analysis_source_version` 是现有语义分析标识，保留原有公式及检查点兼容性，不能当作读取版本。
- 工具会话固定组装请求时的有效稿版本；模型省略版本参数时，后端仍使用会话版本。
- 更换、移除或新增原稿后，旧会话不能继续读取旧位置。局部模式在模型请求前后也会检查版本；直接回答时换稿同样返回冲突。
- `search_source_document` 是字面搜索，返回 `total_matches`、`truncated`、`next_cursor`。游标绑定项目、查询及版本；下一页使用相同查询和版本。
- `match_offset/match_length` 是精确命中位置，`offset/excerpt` 是带上下文的摘录；偏移均对应当前有效稿的 UTF-16 位置，搜索每页允许 1–20 条结果。
- 搜索零命中不能推导“全剧不存在”。称呼出现不能单独证明两个名称属于同一人。
- 分段读取的 `complete` 只表示已到稿件末尾；`complete_source` 只有本次读取覆盖整份原文才为真。

## 观察与回退

处理记录显示本轮采用完整剧本还是相关原文，以及选入的原文字数。工具记录显示实际读取范围和搜索结果数量，不记录原文正文。现有模型请求指标继续记录输入用量、字节数和耗时；成本比较需要累计整条任务链的所有请求。

设置服务端环境变量 `VIDEO_STUDIO_SCRIPT_TARGETED_CONTEXT=0` 可回退到原有全文请求。未设置时启用保守的局部资料策略。普通查询不支持原生工具时继续使用原有路径，不模拟工具。

## 人物批次的原文资料包

长稿仍按原有条件进入分任务整合：原文超过 32,000 字符或目录超过 80 节。首批人物发现和概览读取全文，通过校验后，后续每批最多 12 个目录姓名才有机会缩减输入；短稿保持原有全文整合。

资料包根据目标姓名及首批已验证别名在全文的字面出现、角色目录、章节与事件摘要、伏笔线索、首批人物的来源引用和结局章节选择原文，再补齐相关集、相邻章节和连续场景。各区间包含原始偏移、章节 ID 和逐字正文，合并重复范围；摘要只用于定位和解释，不能证明未读章节的人物身份。完整目录继续提供。内部资料包的 `source_version` 是文件名与正文的语义指纹，`analysis_source_version` 用于对照分析版本；这里不涉及原生工具会话使用的上传时间版本。

版本不符、目录不完整、缺少首次全文结果、泛称、同名或身份疑义、别名缺少原文支持、跨章节边界的字面匹配，均保持全文。资料包正文超过 24,000 字符或达到全文 75% 时也使用全文，不截断证据。

局部输出必须显式返回 `needs_full_source`。模型提出资料不足、引入包外姓名或别名、引用未提供正文的章节、遗漏目标或未通过人物证据校验时，该候选不保存，只对当前批次发起全文核实。网络错误、超时和用户停止不会因此扩大读取范围。格式修正、网络重试与全文核实共享同一批次的截止时间和最多 3 次请求额度。最终独立审读继续读取完整原文及完整结果。

名字或别名有交集的不同人物记录，统一通过完整原文核实后再归并，允许保留同名的独立人物。完全相同的重复记录直接去重；描述长度符合格式不再被当作身份可以合并的依据。

新建全剧整合任务使用 `source-story-parts-v4` 身份，按预计输出量规划时间线、伏笔和不确定事项；匹配 `source-story-parts-v3` 的旧检查点按原来的每 12 章布局继续，旧全文成功任务重新校验后可复用。此版本与总分析管线 v6、人物资料包 `script-character-context-v3` 是不同层的身份。新局部结果额外绑定原文、目录、目标、概览、首次人物结果与策略指纹；不匹配只使依赖它的批次失效。全文核实开始前保存转换标记，失败恢复时直接继续全文；已验证的全文成功结果不因关闭局部策略而重复请求。诊断与上次失败信息不进入语义哈希。

完整人物批次在一次修正后仍遗漏目标姓名时，自动将该批拆为每组最多 3 个姓名的全文核实任务；小组仍遗漏时再拆为单个姓名。每个小任务独立遵守截止时间及最多 3 次请求的限制，完成后保存检查点。旧版已保存的同类遗漏错误也直接采用此恢复方式，“继续处理”复用已完成的小任务和其他批次。只有全部小任务完成、聚合结果通过原批次的来源与覆盖校验后，才保存原批次结果；单人仍遗漏、格式或证据错误、网络失败不会被当成成功，也不会无限拆分。首批人物发现仅由其第一个小任务继承，最终仍通过全文核实重复身份并独立审读。

处理记录会显示人物批次读取相关原文还是完整原文，以及实际选入字数。`VIDEO_STUDIO_SCRIPT_CHARACTER_CONTEXT=0` 可单独关闭人物资料包；`VIDEO_STUDIO_SCRIPT_TARGETED_CONTEXT=0` 同时关闭普通查询与人物批次的局部策略。

## 候选稿修订的目录复用

候选稿补齐直接读取完整当前文稿，不先生成修订请求不会使用的目录；修订完成后，私有新稿分析可采用相同的保守目录复用规划。可复用基线来自当前有效稿的已持久化 `ready` 分析，或与当前上传、有效稿、模型配置严格绑定的 `source-proposal-base` 检查点，且必须通过全文覆盖、原文证据及独立质量核对校验。新稿仍保持为待确认的私有候选。

私有候选分析存于 `source-proposal`；通过核对的候选分析另保留为后续候选的 `source-proposal-base`，因此同一已授权方案的连续修订和服务恢复可复用兼容基线。普通阶段检查点清理保留这两类记录；替换、重新上传或移除原稿清除它们。若同内容分析已完成且配置匹配，优先直接采用；否则只沿用逐字不变的候选目录页，重新整合新稿全文并做全文独立核对，再核对阶段设定。

候选草稿、私有分析和正式文档保持独立：用户明确确认保存且来源版本仍匹配，才提交有效稿修订和阶段文档；保存时可直接采用已通过核对的同内容私有分析。目录复用条件与一次受控完整重建规则同下节，累计用量不因新候选版本或继续操作清零，见[用量控制](script-analysis-cost-control.md)。

## 确认修订后的增量重分析

修订仍须明确确认保存，上传原稿及历史修订继续保留。确认时，只有旧分析已经完整完成、独立核对通过，且具有可核对的模型配置指纹，才在同一数据库事务中保存上一版本的目录复用依据。保存修订或外层事务回滚时，这份依据也随之回滚。已完成并通过核对的同内容私有候选分析仍优先直接采用；没有这类候选时才尝试增量处理。

复用范围由两份实际全文比较得出，不相信替换说明或模型声明的修改位置。当前用共同前缀、共同后缀围成一个保守改动区间；相隔较远的多处修改会将中间内容一并纳入。区间超过 8,000 个 UTF-16 字符或较短稿件的 20% 时使用完整重分析。受影响章节、相关整集、相邻章节和连续场景链均失效。

只有新稿标准目录页能精确对应完整旧章节、整页正文完全相同、所有证据逐字匹配，才可沿用为候选。页前和页后的未改动内容都可参与；长度变化后的后缀位置与证据偏移按实际差值重算，旧连续单元 ID 不沿用。候选按正常页顺序追加，已保存目录始终构成连续前缀。需要重新生成的页继续读取新稿全文。

沿用的是候选目录，旧版全剧理解、人物批次任务、综合结果与核对结论均不跨版本继承。目录完成后重新整合全剧，并以完整新稿独立核对全部结果，特别检查远处修改对旧人物身份、关系、事件解释和伏笔的影响。第一次核对发现实质问题时，自动丢弃全部沿用目录，结合核对证据完整重建目录、全剧理解和独立核对一次；再次发现问题则正常停止，保留结果供用户重试。网络失败、超时和用户暂停不会触发这次语义重建。

复用依据绑定项目、不可变上传版本、修订 ID、新旧正文指纹、目标稿件的内容及时间版本、模型、配置与分析流水线。执行恢复时重新读取模型配置，每次模型请求前后也检查配置；执行中发生变化时拒绝采用返回结果。复用页记录、章节事实或累计数损坏，以及复用依据缺失、失配或开关关闭时，恢复到完整重分析。旧的无配置指纹分析保留原有兼容性，但不能成为增量复用依据。

复用依据存于独立的 `source-revision-base` 检查点，不复制旧稿全文，旧正文从已提交的修订记录重建。普通阶段候选清理保留它；原稿新增、替换或删除会清除它及私有原文候选。配置指纹及复用记录不返回前端公共分析接口。处理进度说明已沿用的目录页以及仍需新稿全文核对的状态。设置 `VIDEO_STUDIO_SCRIPT_INCREMENTAL_ANALYSIS=0` 可关闭增量复用；已经通过核对的同内容私有候选仍按既有流程优先采用。

## 核对问题的修补与恢复

普通分析的独立核对发现遗漏或误读时，保存完整目录、全剧信息和问题证据，并停止等待用户继续。继续时依据同一份完整原文和当前分析，逐项修补问题，不清空已经完成的目录和全剧整合。每项修补只允许修改指定分析字段或数组条目，必须核对修改前的值；章节位置、长度、连续关系和原稿正文不由修补输出改写。人物与事件证据由真实原文句段 ID 提取，不能自行编造引用。

每项修补通过目录覆盖、证据和全剧引用校验后，连同进度原子保存。修补途中失败、暂停或服务中断，继续时复用已保存的修补；全部修补后独立核对中断，只继续核对。修补完成不能直接发布为已完成，仍须完整原文与完整分析的独立核对通过。新一轮核对发现的问题作为新一轮修补处理，每次执行的模型修正与重试有明确额度，不自动无限循环。

无法可靠定位问题、必须改变章节边界或无法安全定点修改时，修补任务须返回明确的重建状态和原因。服务记录该轮核对依据，执行一次受控重建并显示原因，避免继续按钮反复尝试同一项无法完成的局部修补。重建中断后复用已保存的新目录页，不再次清空；重建后的独立核对若仍有问题则停止，不自动循环重建。空补丁、格式错误和网络失败不能触发这一回退。

修补进度绑定核对结果、问题列表和当前分析指纹，源文件、模型或配置不兼容时不沿用。旧版已经开始完整重建的任务继续保留已完成的新目录页；旧程序已经清空的上一轮分析无法凭本次修复恢复。确认修订后沿用旧目录的特殊流程仍保留前述一次完整重建；结构或证据检查点损坏时也按原有校验规则重建必要结果。修补检查点不返回公共接口，界面只显示可恢复状态、已完成的问题数和当前步骤。

## 实现位置与验证边界

普通查询路由：`backend/src/modules/script/script-chat-source-context.ts`；人物资料包及批次恢复：`script-character-source-context.ts`、`script-source-story-parts.ts`；目录规划：`script-source-map-reuse.ts`；候选与已确认修订的来源绑定分别在 `script-source-proposal-reuse.ts`、`script-source-revision-reuse.ts`（均位于 `backend/src/modules/script/`）。工具分页与读取版本见同目录 `script-source-documents.ts`、`script-source-identity.ts`。

本次更新核对实现和现有测试范围，未重新运行真实模型，也未重新测量性能。

本地回归通过临时数据库和模拟模型协议验证原文选择、两个原生工具协议、搜索分页、版本冲突、补读全文及写入保护。人物批次另覆盖跨集称呼、目录漏记、结局与连续场景、局部证据边界、身份归并、失败恢复、取消、共享额度及旧检查点兼容。它们不代表真实模型质量、耗时或成本已经达标。

增量分析另覆盖事务回滚、连续修订、上传替换、前后缀与证据位置移动、暂停和服务恢复、配置变化、复用记录损坏及一次完整重建。模拟长稿验证可减少目录模型请求；尚未以真实提供商测量质量、实际用量和耗时改善。
