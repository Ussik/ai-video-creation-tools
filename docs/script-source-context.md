# 已有剧本：上传、分析与修订

有现成剧本时，在项目创作对话的输入区菜单选择“上传剧本文件”。上传后可查原文、整理大纲，或逐阶段生成创作资料；原稿分析与正式文档分开保存。

**确认修订前，草稿不会覆盖当前有效稿。确认后，后续创作使用修订后的有效稿，上传时的原稿正文仍可追溯。**

## 先分清这四份内容

| 内容 | 用途 | 何时改变 |
| --- | --- | --- |
| 上传原稿 | 保留上传时提取的正文，供追溯 | 主动替换或移除原稿时 |
| 当前有效稿 | 后续讨论、生成与原文工具读取的依据 | 确认原稿修订后 |
| 分析资料 | 剧情目录、人物、事件、伏笔等检索资料 | 分析、修补或重新分析时 |
| 待确认草稿 | 拟采用的阶段文档及可能的有效稿修订 | 生成或编辑草稿时；确认后才正式采用 |

尚无修订时，当前有效稿就是上传原稿。分析完成不会自动把大纲、人物或分集正文保存成正式文档。

```mermaid
flowchart LR
    A[上传原稿] --> B[当前有效稿]
    B --> C[查原文或生成草稿]
    C --> D[检查并确认保存]
    D --> E[正式项目文档]
    D -->|包含原稿修订| B
```

## 1. 上传并检查正文

1. 在创作对话输入区菜单选择“上传剧本文件”，上传一份剧本。
2. 点击输入区上方的文件名，打开“原剧本”预览，检查提取后的正文、章节和对白。
3. 如需换稿，菜单中的入口会变为“替换原剧本文件”；确认后建立新的来源版本。

| 支持格式 | 限制 |
| --- | --- |
| `.txt`、`.md`、`.markdown`、`.docx`、`.pdf` | 单文件不超过 10 MiB，界面提示为 10 MB |
| 提取后的正文 | 不超过 100,000 个 UTF-16 长度单位；不等于 token 数 |

扫描版 PDF 若无法提取正文，请先转成可读取的文字文件。上传后先看预览，避免把提取不完整的正文交给后续创作。

**你会看到：** 文件名、正文长度和分析状态。已选择可用文本模型时，上传可同时启动后台分析；否则先保存原稿，选好模型后点击“开始分析”。

## 2. 运行原稿分析

点击“开始分析”，观察“全文分析 → 全剧整合 → 质量核对”三个步骤。界面显示实际完成的部分与当前任务，单步耗时不能推算剩余时间。

点击文件名打开预览后，可按页签查看：

| 页签 | 能看到什么 | 建议怎样检查 |
| --- | --- | --- |
| 原剧本／当前有效稿 | 后续创作所读取的正文 | 核对版本和文字是否正确 |
| 上传原稿 | 已有修订时，查看上传时的正文 | 与有效稿对照改动 |
| 剧本地图 | 分段目录、人物及事件证据 | 展开原文，核对人物与事件位置 |
| 全剧信息 | 全剧概要、人物、时间线、伏笔与结局 | 回查列出的剧情段落，纠正误读 |

**你会看到：** 完成后出现“剧本地图已准备”。处理中已出现的目录只是部分成果；仍以各步骤状态判断是否全部完成。

## 3. 基于原文提问和创作

尽量写出姓名、集数、原话或明确的交付目标。以下示例只说明操作方式：

| 目标 | 可以这样输入 | 结果范围 |
| --- | --- | --- |
| 查出现位置 | “林晚在哪几集出现？” | 只读查询，必要时补读原文 |
| 查对白 | “第 2 集林晚说了什么？” | 返回与问题有关的原文信息 |
| 理清全剧关系 | “核对林晚和姐姐的关系变化，依据原文说明。” | 使用完整有效稿核对 |
| 忠实整理大纲 | 在“分阶段生成”选择“整理原稿大纲 · 仅概要设计” | 一份待确认大纲 |
| 整理完整设计资料 | 选择“完整大纲设计 · 9 栏”并说明要求 | 约定范围内的设计草稿 |

普通原稿大纲直接依据完整有效稿生成与核对，不等待整套分析完成。原稿没有揭示的信息和开放结局如实保留；上传不代表授权另写故事。

只读问答不会修改原稿。生成阶段文档、补齐设定或修订已有文档，仍按[阶段创作流程](model-intent-workflow.md)预览并确认保存。

## 4. 检查修订并确认保存

明确说明要修改哪些内容，例如：

> 将林晚的职业改为急诊医生，同步相关人物文档与原稿中直接冲突的描述。保留主线、结局和其他角色。

1. 在草稿中检查本次阶段文档和具体决定。
2. 若草稿含“文稿修订 · 当前有效稿”，同时核对这份拟修订正文。
3. 接受修改后确认保存；不接受时继续调整或放弃草稿。

**你会看到：** 含原稿修订的草稿会说明保存后将同时更新有效稿和本阶段文档。确认前，两者与正式内容保持分离。

仅补齐候选文档时，默认不扩写原稿。已确认的修订会成为新的有效稿；后续分析只在条件匹配时复用未变化部分，仍需核对整篇新稿。

再次上传或替换文件会建立新来源版本，旧分析不能直接套用。即使文件内容相同，重新上传后的读取位置和旧草稿也须重新校验。

## 5. 继续未完成的分析

| 状态 | 建议操作 | 已有结果怎样处理 |
| --- | --- | --- |
| 分析进行中 | 可以查看进度，必要时点击“暂停分析” | 已完成步骤持久保存 |
| 已暂停／失败且有可复用结果 | 点击“继续未完成步骤” | 继续尚未完成部分，必要时重新核对 |
| 已失败且没有可复用结果 | 检查错误后点击“重试分析” | 重新进行全文分析 |
| 页面暂时读不到进度 | 保留当前页面或重新打开项目 | 界面恢复状态读取，不等于再次提交分析 |
| 提示来源或配置已变化 | 按提示重新核对当前稿件和模型 | 不兼容的旧结果不会当成新结果采用 |

质量核对发现遗漏时，系统会依据原文修补并再次核对。出现反复无进展的情况会保留已有分析和诊断；查看问题后再决定继续或更换模型。

分析恢复只复用通过版本与配置检查的结果，不能保证每次都从界面上最后一项继续。更多规则见[任务恢复指南](script-task-recovery.md)。

## 常见问题

| 问题 | 说明 |
| --- | --- |
| 上传成功，为什么没有正式大纲？ | 上传只提供来源；分析只整理资料。点击生成并确认保存后，才有正式阶段文档。 |
| 有了剧本地图，模型还会读全文吗？ | 会。全剧关系、创作、修订及最终核对仍可能读取完整有效稿。 |
| 为什么有时只读取部分原文？ | 明确的局部事实查询可按原文位置读取；证据不足或涉及全剧时会补读或使用全文。 |
| 搜不到某个称呼，能认定人物不存在吗？ | 不能。字面零命中不证明全剧不存在，也不能仅凭称呼相同认定是同一人物。 |
| 小改一处，为什么还在核对全剧？ | 未变化目录可复用，但人物身份、因果或伏笔可能受远处修改影响，需完整新稿核对。 |
| 分析成功，为什么对话里还写着“未完成”？ | 对话保存的是当时结果，文件区域显示当前稿件的分析状态。 |
| 保存旧草稿时提示版本冲突？ | 当前有效稿、正式文档或场次已变化。旧草稿仍可查看，需基于当前资料重新生成并核对。 |

## 必要限制

- 文字提取、人物识别与分析可能出错，请用可展开的原文证据核对关键事实。
- “相关原文”和缓存不等于模型永久记住全稿，也不保证每次只发送摘要或减少固定比例的费用。
- 分析、修补、补读及最终核对可能产生多次文本调用；一次点击不等于一次 API 请求。
- 暂停和失败不会自动删掉原稿；主动替换或移除原稿会使相应旧分析与私有候选失效。

## 请求范围

| 路径 | 资料范围 |
| --- | --- |
| 明确的局部事实查询 | 分析匹配且可安全缩小时提供相关逐字原文、邻章和全局定位资料；只开放读取工具 |
| 全剧、身份、关系、因果、伏笔或创作修改 | 完整有效稿 |
| 指代不明、混合要求、索引失配或选中范围过大 | 完整有效稿 |
| 长稿人物整合 | 首批发现读取全文；后续已知人物批次可用证据包，不足时该批转全文核实 |
| 候选稿修补 | 保留完整有效稿及约束，预载问题关联的完整候选文档，其他文档按需完整补读 |

局部查询由服务端决定，用户或模型不能自行声明切换模式。须满足分析完成、质量检查通过、版本匹配和目录完整覆盖；字面目标必须在原文命中。

局部资料明确标记未覆盖全文，摘要与目录只作定位。工具可搜索、分页读取，或经说明原因后补读同版本全文；补读仍不构成修改授权。

## 版本和分页

- 原生读取的 `source_version` 绑定文件名、正文和替换时间；`analysis_source_version` 是分析标识，不能替代读取版本。
- 会话固定请求组装时的有效稿版本；换稿后旧位置失效，省略版本参数也不能绕过检查。
- 搜索游标绑定项目、查询和版本；`match_offset` 对应精确命中，`offset` 对应带上下文摘录，均为 UTF-16 位置。
- 搜索每页允许 1–20 条结果；`next_cursor` 用于继续。零命中不代表全剧不存在。
- 分段读取的 `complete` 仅表示到达文末；只有 `complete_source` 为真才表示该次返回覆盖全文。

## 观察与回退

处理记录说明采用完整剧本还是相关原文，工具记录显示实际读取范围。后台保留用量、字节数和耗时用于诊断，不能以单条请求估算整轮成本。

| 服务端环境变量设为 `0` | 作用 |
| --- | --- |
| `VIDEO_STUDIO_SCRIPT_TARGETED_CONTEXT` | 关闭普通查询与人物批次的局部资料策略 |
| `VIDEO_STUDIO_SCRIPT_CHARACTER_CONTEXT` | 单独关闭人物批次证据包 |
| `VIDEO_STUDIO_SCRIPT_INCREMENTAL_ANALYSIS` | 关闭确认修订后的目录增量复用 |

普通查询不支持原生工具时沿用原有路径，不模拟工具。关闭复用不会要求重跑已经核对且同内容、同配置的成功结果。

## 人物批次的原文资料包

原文超过 32,000 个 UTF-16 长度单位或目录超过 80 节时，长稿整合分任务执行。后续每批最多 12 个目录姓名可尝试证据包；短稿沿用全文整合。

证据包依据姓名和已核实别名的逐字命中，补入相关集、相邻章节、连续场景与结局。泛称、同名、身份疑义或证据失配时保留全文。

包正文超过 24,000 个长度单位或达到全文 75% 时使用全文，不截断证据。模型提出不足、遗漏目标或证据不合法时，该候选不保存，转当前批次全文核实。

人物批次修正后仍遗漏目标时，可拆为最多 3 人的小组，再拆为单人；完成小任务即保存进度。最终聚合仍须通过原批次覆盖、身份和全文独立核对。

分析管线、全剧整合及人物证据包各有独立策略身份。旧检查点按兼容规则恢复，不因诊断措辞或失败信息变化而重算语义身份。

## 候选稿修订的目录复用

修补会话绑定不可变候选版本与有效稿版本。搜索只定位证据；完整读过的文档才允许修改。提交校验逐字唯一定位、非重叠补丁、实际内容变化及版本。

工具 `get_repair_context`、`search_repair_context` 和 `submit_repair_patch` 负责补读、搜索与精确修补。不支持工具时可使用完整资料的结构化补丁回退。

新创作默认只写候选文档与具体决定，`source_edits` 默认为空。只有与本次决定直接冲突且需同步时，才提出最小有效稿修订；上传原稿不随之改写。

可复用基线来自当前有效稿已核对的分析或兼容私有候选检查点。候选、私有分析与正式内容分离；来源版本匹配且创作者确认后才正式提交。

私有记录使用 `source-proposal` 和 `source-proposal-base`。普通阶段清理保留它们，替换、重传或移除原稿会清除；只读预览不调用模型，也不提供直接保存旁路。

## 确认修订后的增量重分析

确认保存时，只为已完整分析、核对通过且模型配置可验证的旧稿保存复用依据；依据与修订在同一事务内提交或回滚。

比较新旧实际全文得到保守改动区间，而非相信模型声明。区间超过 8,000 个 UTF-16 长度单位或较短稿件的 20% 时完整重分析；受影响集、邻章和连续场景一并失效。

仅完整旧章节、逐字不变的目录页及可匹配证据可复用。长度变化后的后缀位置重新计算，已保存目录始终组成连续前缀。

跨版本不沿用旧全剧理解、人物批次和核对结论。新稿仍重新整合与全文核对；发现复用理解有实质问题时，丢弃复用目录并按原因重建。

复用依据存于 `source-revision-base`，绑定上传、修订、正文、模型、配置和分析管线。依据缺失、损坏、失配或开关关闭时使用完整重分析，不强行采用旧结果。

## 核对问题的修补与恢复

独立核对发现问题时，保留目录、全剧资料与证据并逐项修补。修改限定于指定分析字段，核对修改前值；修补不改写原稿正文、章节位置与边界。

每项校验成功后连同进度保存；中断后复用已保存修补，最终仍需完整原文和完整结果的独立核对。必须改变章节边界或无法安全定位时，明确说明原因并重建。

格式恢复、修补与必要重建以实际进展判断。相同正文及问题重复、无效修改或循环回到旧结果时，保留候选和诊断，结束自动循环，支持显式继续。

网络错误、提供商超时和用户暂停不会自行触发语义重建。恢复时检查来源、模型、配置与问题指纹；不兼容结果不能继承。
