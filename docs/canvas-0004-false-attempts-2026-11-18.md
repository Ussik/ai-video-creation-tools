## 根因与修复

旧 coverage 重试把上一次原答作为初始生成结果返回。数组根结构使局部 planner 无法定位，流程没有发出纠正请求，却仍保存 retry-failed 标记；共享对象重试计数器把标记数量当成新的模型尝试，三个点击即耗尽四次上限。

- 精确核对 v1 原始响应、完整交付、唯一响应槽、确定性 token 链和重复字节。v1 代码规定 retry 初始响应是本地 seed，只有 correction 能新增实际模型用量；真实 correction 即使文字相同仍计数。无法证明的历史不减免，也不自动重发。
- 状态读取为只读投影：两项分别显示 1 次实际模型请求、4 次本地校验。正式恢复操作追加 `coverage-migration-v2` 和 `coverage-attempt-v2` 审计，旧响应、失败标记、任务账本和真实用量均不删除、不重置。
- 恢复 token 绑定版本、旧单元身份、完整历史哈希、当前 prompt/Schema；单元身份已包含镜头证据和显式对象家族。每次请求在调用前保存 intent，记录请求及 Schema 哈希、完成/未知/未发送状态。只有可信的本地拒绝或提供方未发送证据才能排除计数；未知交付仍阻断再次调用。
- 达到原来的四次实际模型请求上限才显示达到上限。缓存读取、本地校验和可证明的历史回放不消耗模型次数。新请求不能建立安全补全目标时直接报告本地阻断，不再反复回放同一原答。
