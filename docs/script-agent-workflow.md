# 剧本智能体的任务与交付流程

实现核对：2026-10-25。以下描述当前工作区代码；供应商真实生成速度和故事质量仍需实际使用验证。

## 普通大纲先交付一份成果

上传提供原稿，不代表授权生成或保存。创作者点击生成大纲后，程序固定任务合同：

- 有原稿：`intent: source_outline`、`artifact_types: ['outline']`，完整读取原稿，忠实整理人物、事件与因果。写到原稿当前结尾，保留未揭示信息和开放结局，不补造规则或答案。
- 无原稿：`intent: stage_design`、`artifact_types: ['outline']`，依据已确认故事方向和创作要求设计大纲。
- 明确要求完整设计包：固定九份成果；只要求若干栏目时按明确范围交付。

明确按钮已给出阶段与范围，不再额外请求模型识别同一意图。自然语言仍由模型按语义判断目标、操作和成果范围。合同由服务端绑定到生成、接续、复核和确认草稿，工具不能自行减少成果或更换任务类型。

界面提供明确的普通大纲与“完整大纲设计 · 9栏”入口，配置面板按实际选择显示本次交付栏目。普通原稿整理只生成概要设计；需要钩子、伏笔、反转、分集大纲等完整成果时，可选择完整设计，或对已有大纲选择“补齐缺失栏目”。补齐范围按当前正式文档重新计算，只包含缺失项。

普通大纲直接读取完整有效稿生成，再独立核对该份大纲，不等待目录、人物、时间线、伏笔等整套分析完成。上传分析继续作为独立任务存在，未完成的分析不会被当成就绪。新的生成请求只附完整原文，不重复附加分析目录；分析运行状态变化不会让同一原稿的生成检查点失效。

## 完整设计按依赖执行

任务图由程序根据实际成果范围生成，不额外调用规划模型。

| 任务 | 成果 | 前置成果 |
| --- | --- | --- |
| 故事主线 | 大纲 | 无 |
| 叙事安排 | 简述、全剧分段 | 主线 |
| 背景规则 | 背景、创作约束 | 主线；可与叙事安排并行 |
| 剧情兑现 | 钩子、伏笔、反转 | 主线、叙事、背景 |
| 分集承接 | 分集大纲 | 以上成果 |

场景按地点与布局、氛围与连续性分两组；道具按道具与功能、外观与状态流转分两组。人物与单集正文保持整体编写。只交付单份大纲时只有一项任务。

每项读取完整原稿、完整创作要求及实际依赖成果。单次输出被截断时，沿用既有完整语义单元，只接续当前任务尚缺的内容。每组完成立即发布只读预览；预览不代表复核通过或正式保存。

补齐阶段由程序逐字保留已有标题正文及其空白，只让模型生成缺项；保留内容同时进入下游依赖。原生工具与 JSON 预览、确认保存均遵守此规则，补齐不能改写已保存文档，原有文档记录也不因补齐被重新更新。独立任务并行时，即使一项失败，也先保存另一项实际完成的成果。恢复时只重跑未完成或输入变化的任务；依赖变化同时使下游完整结果和续写半成稿失效。

## 复核按合同验收

仅本次实际成果属于验收范围。事实冲突、明确要求遗漏、影响当前交付的因果矛盾才阻断；文风或可选深化建议单独记录，不进入修补阻断队列。建议也必须通过真实来源与逐字证据校验。

小稿一次完整核对。多组候选总长达到 16,000 字符时，按完整逻辑组核对，再做一次完整成果与原稿的一致性检查。局部通过不能代替最终整体检查。修改一组后可复用无关组，但整体一致性必须重新检查；原稿或创作要求变化会使相关检查失效。该阈值只选择处理方式，不拒绝执行。

复核拥有独立的稳定检查点，不随修补工作区的候选版本一起清空。结构化请求统一负责传输重试，避免调用层叠加重试。供应商输出截断、证据定位及纯推理耗尽仍按原有专门恢复策略处理。

## 修补看实际进展

沿用精确局部补丁和按需读取工具。已加载关联文档完整提供，其余可批量读取或搜索；提交必须符合版本、已读范围、逐字唯一定位、非重叠和逐项决定要求。工具内部在相同已读资料上重复相同操作、无效补丁或未提交结果时返回明确停滞诊断，保留候选供继续。新读取、不同查询与有效补丁可以推进。续写先切换到下一个完整小节；同一内容在同一接续方式下仍无新增时保留检查点并停止重复请求。

不以轮数或累计消耗停止任务。独立复核后若正文及问题没有变化，或回到之前的同一正文与问题，先改为逐项对照“已有决定、当前正文、证据”的处理方式；同一方式仍反复停滞时保留候选和具体分歧，结束本次自动循环。新的独立事项仍需对应授权，不把已有委托扩大到其他问题。原稿大纲整理任务的原稿只读，程序拒绝非空 `source_edits`。

后台原稿分析同样依据实际保存的目录、全剧理解与问题证据检测重复；相同内容与问题再次出现、仅改诊断措辞或无效证据编号、修补与全文重建循环，都不能视为新进展。出现停滞时保留原稿、已完成分析和检查点，返回明确诊断，支持手动继续或更换模型；有实际进展的处理不受累计轮数限制。

## 界面与保存

默认显示任务清单、当前进展和逐项成果预览，支持停止与继续。不展示 token、请求用量、容量或累计消耗卡；内部指标保留用于诊断，不作为业务配额。旧活动中这些记录仅隐藏显示，不删除历史。

正式保存仍需创作者确认。阶段顺序、原稿版本、候选版本、已有文档与场次 ID、镜头关联、原稿历史及并发修改校验继续生效。离开页面和断线只取消订阅，明确停止才取消任务。

文档编辑器在目录和正文明确标记“未生成”，显示已有及缺失栏目数，并提供手动填写入口。空栏目使用紧凑提示，不再显示大片空白，也不会把概要设计、分场或生成设置复制成其他栏目的正式成果。本地空占位不随手动保存创建正式文档；已有文档及其正文继续保留。点击“补齐缺失栏目”只打开智能体配置面板，创作者点击生成后才执行，确认草稿后才保存；存在未保存编辑时需先保存。
