# 对话意图与分集创作

实现基线：2026-10-22，提交 `9ba5a25`。以下说明当前入口、授权和保存契约，本轮按源码核对，未运行真实模型创作。

新项目可直接探索故事方向；首次故事大纲生成需要输入创意、提供项目简介或引用正文、已有故事资料或当前已核验的生成提议。空白对话、仅请求备选方向、未确认候选和集数配置不视为故事依据。阶段按钮与分阶段面板共用检查，缺少依据时提示先输入创意或选定方向；后续阶段仍按已保存进度开放。

明确生成、补齐或重新设计某阶段，包含该阶段范围内缺失虚构细节的创作权限。模型依据已确认事实和创作者限制确定身份、动机、世界规则、道具功能等核心设定，不因为没有逐项指定就留作“未定／待定”。普通讨论、单项回答和跳过仍不授权自动生成文档；现有主线、明确暂缓或由创作者亲自决定的事项、其他阶段和保存范围保持原边界。未指定集数时可以提出有依据的具体分集草案，不将项目默认值当成创作者确认或自动修改配置。

各阶段共享 `script-setting-completeness.ts` 的创作权限和核心设定标准。交付前独立调用当前文本模型进行 `script_draft_completeness` 结构化核对，报告须覆盖本次新写文档，并逐字引用候选正文或分场；核对正文缺失、核心规则、作者视角的真实答案和跨文档一致性。文字标记只作线索，不靠关键词禁用悬念、角色未知、有理由不适用的内容或开放表达。作者未决定的核心事项不能冒充观众悬念。核对不改数据、不自动保存，不能宣称作品质量已获保证。

工具调用和 JSON 返回路径均执行核对。发现问题后把具体证据与修正要求交回写作模型，最多自动修正两次，沿用同一阶段、授权及完整候选内容；成功后才提供待确认草稿。失败或上游异常如实反馈，不把未完成稿当成通过；只读模型请求可按统一执行策略有限重试，工具写入与媒体提交不因传输失败自动重放。核对增加独立模型调用，修正时增加写作调用，仍受当前步骤和整轮任务时间上限约束。

补齐阶段中原样保留的历史文档只作一致性背景，不因旧正文存在待定就自动改写。采用已有正文保留原字节，不走会重写该正文的自动完善。手动编辑和确认保存仍沿用现有流程；统一修订已有任务继续使用原有逐批全文与关联内容核对机制。实际格式、保存范围及版本保护仍由原有 Schema 和工具校验执行。

自由对话不再用固定措辞或关键词路由。后端先使用当前选中的文本模型独立判断讨论、澄清、生成、修订或采用已有正文，再把已确认的要求交给写作调用。集数和单集时长同样由模型结合上下文理解；制作片段时长与单集时长分别处理。

点击明确的阶段生成按钮时，阶段和范围来自结构化参数，不能由意图判断改变按钮选择。大纲、人物、场景和道具阶段属于全剧，使用 `scope: project, episode_number: 0`；只有指定集正文使用 `scope: episode`、目标集数和单集时长。兼容旧请求时会清除全剧阶段误带的集数/时长，所选集数也不会进入全剧任务的意图状态。全剧写作读取全剧文档和所有已保存分集的正式内容，不按当前集和上一集筛选；分集写作继续限定当前集和前集承接。保存全剧草稿不修改分集正文/场次，生成全剧资料也不推进下一集。剧本生成统一在对话中的分阶段入口进行，编辑器负责查看、编辑、保存与分镜制作；旧版整本生成接口保留兼容，不再提供界面入口。格式解析、模型可用性、参数范围、文档类型、目标集数和项目归属仍由程序校验。识别失败不回退到文字规则，也不自动保存。

阶段写作共用同一份完整文档要求，普通对话授权生成、明确阶段按钮和兼容的 JSON 写作路径一致：

- 大纲阶段：概要设计、故事简述、背景设定、全剧分段、钩子预设、伏笔与回收、反转预设、创作禁区、分集大纲，共九份独立文档。
- 人物阶段：人物小传与人物关系，包含动机、弧光、知情范围、关系变化与连续性约束。
- 场景阶段：场景清单（`locations`）、空间与动线（`location_layouts`）、视觉与氛围（`location_atmosphere`）、场景连续性（`location_continuity`），四份独立文档按统一地点名称关联到集数和场次。
- 道具阶段：道具清单（`props`）、外观与辨识（`prop_visuals`）、剧情功能与使用规则（`prop_functions`）、归属与状态流转（`prop_continuity`），四份独立文档按统一物件名称关联到人物、事件、集数和场次。
- 分集阶段：仅指定集的完整正文及对应分场，承接全剧资料、前集状态、伏笔和结尾钩子。

新生成草稿必须包含本阶段每一种文档且正文非空，不接受仅主文档、重复类型、越阶段文档或错误范围；模型得到具体缺项用于修正。JSON 写作仅允许一次格式修正，工具写作沿用有界诊断修复。内容要求追踪具体人物、事件、集数和场次，不以字数判断质量，也不将模板标题当作完整内容。

已有阶段缺少栏目时，工具须读完当前原文并原样保留标题、正文，再生成缺失栏目组成完整草稿。预览中仍可编辑，保存校验原文版本并原子写入，未改的文档不重复更新。整阶段重新设计使用 `workflow.operation: regenerate`，支持全剧资料与明确指定的已保存单集，先读完该阶段全部原文、按完整子文档契约生成待确认草稿，校验源版本后按原文档ID保存；未涉及文档、分集、场次和镜头保留，草稿显示关联核对提示。局部修改使用 `revise`，补齐使用 `supplement`，首次生成使用 `generate`（省略时默认）；这些操作随执行记录保存，重试沿用原范围。工具对话也先解析无结构化目标的自然语言意图；阶段按钮不重新解析目标，设定回答、跳过与已有草稿继续保持原操作边界。已有文档的定向修改仍使用局部修订。单集重新设计须读完完整正文和全部分场，提交完整正文及同步场次，已有场次用 `source_scene_id` 明确对应原 ID，全部保留且每个只出现一次；允许重排和补充新场次，不自动删除旧场次。保存复用文档与场次 ID，保留镜头、素材、视觉绑定和其他集。JSON 写作同样返回持久化版本草稿，先捕获完整源文档/场次，源内容在生成或保存期间变化则拒绝覆盖；不能通过旧版直接保存接口绕过草稿确认。历史草稿的编辑/保存及阶段进度保留兼容，不自动补写或要求旧项目重做。

文档类型枚举由共享阶段定义生成，编辑器目录、API/数据库类型、JSON/函数工具结构化输出和引用快照统一使用。场景与道具的专业内容要求在阶段、单文档和旧版整本生成提示中复用。旧版整本接口仍可返回不含项目文档的历史格式；一旦返回某个设计阶段的文档，该阶段必须完整且类型不能重复。素材设计来源与连续性核对包括全部设计子文档。

意图协调、阶段写作、独立完整性核对及接镜检查使用各自任务提示。阶段写作保留本轮请求窗口内完整原始对话，并把最后一条标明为本次要求；整理后的创作说明不能替代原话。创作者最新明确修改优先于对应旧要求，未变更约束继续有效；未被接受的模型建议、备选和问题仅作上下文，不能升级为已确认设定或保存授权。接镜检查读取当前制作范围、人物场景资料和镜头状态，不代表检查实际视频像素。

分集流程：创作或采用正文 → 草稿预览 → 确认保存 → 分集目录/编辑器 → 选择本集场次加入画布或制作分镜。采用已有消息会逐字保留正文，只让模型整理场次。待确认草稿不会被新的创作请求覆盖。

镜头站位、武器、姿态、面具和道具连续性由显式触发的模型文字检查判断，不再靠关键词。基础素材/时长检查保持本地执行。语义检查结果按镜头与剧本资料快照缓存，变化后显示过期；普通刷新不会再次付费调用模型。检查不代表实际视频画面已经通过审核。

模型目录的输出类型以提供商能力元数据或用户明确选择为准，不根据模型名称猜测。题材的创作描述与展示分类独立：已知分类使用共享目录中的封面；自定义题材通过独立的 `/script/themes/visuals` 模型调用匹配已有分类，仅接受目录内名称，低信心或无合适类别时使用中性雾纹。匹配不会改写 generation_options、文档或对话，不新增全局分类。设定器保留原始题材并单独显示“自定义”，固定分类轨道不插入模型生成的自由文本。未匹配、加载中和封面加载失败都使用柔和的中性水球；切换题材会清除旧图片，旧请求不得覆盖新选择。展示映射不加入编剧上下文。

成本按实际路径计算，不能固定为每轮两次调用。自由请求可先做意图协调，工具对话可能包含多轮读取及决策；阶段写作还包含独立完整性核对，问题修补和必要格式修正会增加调用。明确的按钮、设定回答、已有草稿和采用正文各走对应入口，采用正文逐字保留原文并整理场次。调用记录显示实际任务与用量；这些流程不会自动调用图片或视频模型。步骤预算、持久任务、断线重连及继续未完成步骤见 [script-task-recovery.md](./script-task-recovery.md)。

“采用为分集剧本”仅对模型确认包含单集正文的助手消息展示。普通讨论、摘要、选项和通知不展示；未知内容先隐藏入口，再由独立文本识别调用判断。模型明确识别出集数时采用窗口预填该集，未明确时由创作者选择。

模型另行识别单集准备资料（明确集数的具体设定、节奏或试写），为当前回复提供“开始创作第 N 集”操作。点击才以结构化阶段和集数启动完整正文创作；准备资料不显示采用按钮。新的用户发言或待回答选择题会取代旧操作，不通过关键词猜测。识别版本为8，旧版本（包括误判为普通讨论的缓存）会重新识别。只有前置全剧资料已保存时才自动推荐开始分集正文；手动可选择已保存集修订或最早缺失集创作，后续未保存集不能越序生成。

收起预览只隐藏界面。待确认草稿保留“查看草稿”入口；保存后保留“查看第 N 集剧本”和“全部创作文档”入口，重开对话时从项目文档恢复。集数选择使用统一的应用下拉菜单，不再调用系统原生 select。

同一次回复识别也判断普通文字是否在请创作者选择原文中的具体方案。识别为选择题后，原回复逐字保留，底部输入区显示原有方案；不使用问号、列表符号或关键词规则补判，不新增、拆分或合并方案。模型结合后续对话判断待回答、已回答或已结束；只有当前最新的待回答问题打开选择面板。明确提交或跳过期间保留面板，模型回复成功后关闭；失败或停止时保留原问题和填写内容。有效的结构化 choices 回复直接渲染，无需补充识别调用。

历史消息通常按最多10条、40KB批量识别，单条长回复允许独立识别，接口总量上限640KB、单条正文上限80,000字符。结果按识别版本、项目、消息ID和正文哈希缓存；所有问题类型的状态另外包含最多8条后续消息的上下文快照。首条创作者回答保留最多40,000字符，以免丢掉多项回答的末尾；其余后续消息保留300字符。正文或相关上下文变化后重新识别，旧缓存不能直接打开面板。识别失败保持入口隐藏并提供重试；识别不修改或保存剧本。尚未识别的普通回复会增加一次文本识别调用，选择题修复复用这次调用，相同内容与上下文重开时复用缓存。

最新回复先单独识别，再处理历史状态；整理当前回复期间隐藏默认快捷建议，避免让用户误以为没有待回答问题。模型必须区分上轮已确认事项和本轮新追问；混合开放问题与明确选择时用 question_set 保留全部不同的待回答事项，不因开放问题整体漏判，也不只保留其中一道选择题。原方案若需要补充具体人选或范围，模型输出 `requires_details:true`，选择后显示补充输入，填写后才能继续；程序只校验结构和必填状态，不猜测人物组合。

最新一轮回复提供“重新生成”（失败时为“重试生成”）。沿用最后一条创作者问题与引用快照，排除不满意的回复，不重复添加用户消息，不消耗尚未发送的输入或引用。成功后形成新的对话分支，原版本以“原回复”保存在历史对话（最多20个历史分支），可切换查看；失败或停止时恢复原回复。待确认草稿须先保存或放弃，已保存的剧本不会被重新生成直接覆盖；新正文仍需确认保存。新回复使用新消息ID，独立重新识别选项与分集入口。

新生成的每条模型回复显示处理用时：从提交请求起实时计时，包含网络等待、意图判断和回复/草稿生成；完成、失败或停止后固定本条耗时，不包含后续的独立回复识别。重新生成独立计时，原回复与其用时保留在历史分支。`processing_duration_ms` 随对话持久化，刷新、关闭重开和切换历史仍显示原记录；用户消息、系统通知和未记录用时的旧消息不显示估算值。浏览器显示实时计时，服务端持久任务也保存实际用时及继续执行的累计主动时间；计时不增加模型调用。

“重新识别选项”只针对最新普通文字回复，独立调用识别模型，不重写内容。显式单条 `force:true` 绕过缓存；成功时同时替换本条对应的普通缓存和当前上下文缓存，避免旧正负结果在刷新后重新覆盖修正。失败时保留服务端旧缓存并允许再次强制重试。

开放追问使用 `input_request`（识别协议 v7），与 `choice_request` 分开。独立识别模型从回复语义提取 1–4 个待填写字段，参考项仅来自原文示例，不为缺少备选的问题编造选项。前端在底部显示字段和可多选参考，允许自由填写；全部必要字段填写后才能继续。字段值本地保留，提交时逐项带上字段名称，失败保留原表单。创作模型也可直接输出 `kind: input_request`，避免对明确结构再次识别。历史问题状态与后续对话一起缓存，旧版本的 `other` 不再阻止开放追问交互；角色对白、比较说明、已确认事项不因含问句而弹表单。

“跳过”按钮文案保持不变，含义为创作者明确授权模型决定当前事项。为兼容已有请求仍发送 `question_response: { status: "skipped", question }`，同时发送可见的授权消息，直接接续讨论模型。模型结合已确认事实和约束选择方案或补齐具体设定，说明决定及简短理由后继续推进，不保留待定、不重复确认；后续讨论、创作要求整理和文档生成沿用这一具体决定，创作者后续修改优先。未提交的选择和填写内容不当成确认，委托本题不自动生成或保存文档。“跳过”与继续共用提交锁，可停止、失败可重试；无可用模型时不允许提交。历史问题显示“已跳过”；识别协议 v7 区分明确委托与暂不决定，避免旧缓存重新追问已委托事项。输入区域使用中性底色标示聚焦，移除边框、外轮廓及全局表单焦点阴影。

讨论请求使用最近最多32条有效消息、256,000个UTF-8字节的正文窗口，前后端限制一致。普通发送、回答、跳过和重新生成共用窗口选择；保留连续的最新消息，不截断消息正文，不把失败或生成中的消息发给模型。历史记录的保存与请求窗口分开，选择窗口不删除历史。引用文档仍按独立的600KB预算发送完整快照，已保存剧本资料仍由后端补充。保存和下一轮请求都允许助手消息最多80,000字符，创作者消息最多40,000字符，覆盖多题合并回答。回复语义识别属于另一接口，不是整个创作对话的长度上限。


确认提议使用 `kind: confirmation`，普通文本补识别使用 `confirmation_request`，底部提供固定“同意”“需要调整”及自由补充。接受故事框架不代表自动授权生成或保存整份文档。单轮确有2–4个不同待决定事项时使用 `question_set`，每项可为 confirmation、choices 或 input_request，问题ID唯一。界面逐项回答、支持返回修改，全部完成后统一提交一次；选择和填写本身不触发模型。每项“跳过”只委托对应事项，忽略这项未提交的选项或输入，不委托其他问题。答案与局部跳过状态本地保存，刷新后恢复；失败保留整组回答，支持重试。组提交发送 `question_response: { status: "answered", question }`，只接续讨论，不启动文档生成。

创作建议按已保存的非空正式文档计算：故事方向 → 全剧大纲 → 人物与关系 → 场景 → 道具 → 分集正文 → 分镜。人物、场景、道具文档必须是全剧范围；草稿、分集客串人物和通用场次/结构文档不能冒充完成的全剧资料。旧版 outline/characters 字段仅在没有对应全剧文档时兼容使用。分集按已保存正文/场次找首个缺失集数，达到已确认集数后停止自动推荐新集。

保存草稿后从实际保存响应重新计算进度，快捷建议与协调/讨论/写作模型使用同一规则。已有人物先保存、随后保存或修订大纲时，复用人物并推荐下一个缺失阶段。大纲更新不使其他文档自动失效；仅明确要求修改或发现具体冲突时建议针对性修订。阶段按钮直接显示已保存资料的处理菜单：局部修改、补齐缺失栏目、重新设计。未保存阶段按顺序开放；只有最早缺失的阶段可以首次生成，后续阶段锁定，指定分集首次生成也必须补最早缺失集数。已保存分集可按所选集数局部修订或重新设计完整正文与分场，保留场次和分镜关联，不推进下一集。未确认的草稿须先保存或放弃，才启动其他阶段。


剧本对话现在按程序给出的当前阶段组织交互。默认阶段由已保存的正式资料决定；故事方向作为大纲准备，第一份正式产物是全剧大纲。每个问题携带 `interaction`（目标阶段、setting/generate/revise 用途，分集需带集数），阶段指问题服务的文档，不按人物、地点等关键词判断。大纲阶段的人物目标问题可正常回答，完整人物档案的生成提议不能越序出现。结构化 JSON 和普通文字的语义识别使用同一阶段校验；缺少标识的旧回复会重新识别，无法提供有效标识时显示识别失败和重试入口，不显示未验证按钮。多题只保留当前阶段的设定问题。

生成或修改文档的提议使用 `workflow_action`，由程序核对目标后展示明确的生成按钮，不变成“同意／跳过”的设定题。单题、多题回答及跳过统一只继续讨论；生成草稿不改变已保存进度，待确认时禁用新文档推进，确认保存后才计算下一阶段。普通“继续”产生的生成意图必须匹配当前阶段和集数，不得重做已完成资料；创作者明确的阶段按钮与自然语言修改要求可以返回已保存阶段处理；未完成阶段仍须顺序生成。明确转入某阶段的讨论可保留为临时范围，阶段和识别缓存随消息保存，回答、跳过、重试及刷新均沿用，新的保存进度会使旧范围和旧操作失效。

阶段控制保留原有 Skill 注入：启用的剧本规则仍参与讨论和阶段写作，视觉资产及图片／视频提示词的 Skill 入口保持原有机制。程序阶段约束和创作者明确要求优先于 Skill 中的流程建议。

## 原稿问答、草稿和画布的范围

明确的原稿局部事实问答，在有效分析索引匹配当前稿件、工具可用且范围能安全缩小时，可携带相关逐字片段和邻接章节；这是只读查询，只注册读取工具。资料包标明未提供全文，目录、摘要和名称匹配仅供定位；证据不足可搜索、分页读取或说明原因后补读同版本完整有效稿。不满足安全缩小条件时使用全文，不能把搜索零命中说成全剧不存在。完整策略见 [script-source-context.md](./script-source-context.md)。

文档草稿绑定生成时的有效原稿、文档与场次版本。上传或确认原稿修订后，旧草稿保留但不能越过版本检查直接保存；缺少原稿版本证据的历史草稿需重新生成并核对。上传原稿、分析就绪、生成候选、独立核对和确认保存是不同状态，确认保存才正式采用内容。

分集「加入画布」先读取所选场次的分镜规划状态，显式规划后确认镜头，再检查并整理视觉设定文字，最后导入节点。已有规划仅在来源仍有效时复用；每次最多规划 10 个场次。「更新已有分镜」保留原 ID，变化后增加修订并重置当前媒体选择；「重新设计」创建独立方案及专属画布，旧方案与历史资产保留。此流程不自动生成图片或视频，详见 [project-canvases.md](./project-canvases.md)。
