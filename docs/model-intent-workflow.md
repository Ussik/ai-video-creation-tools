# 对话意图与分集创作

自由对话不再用固定措辞或关键词路由。后端先使用当前选中的文本模型独立判断讨论、澄清、生成、修订或采用已有正文，再把已确认的要求交给写作调用。集数和单集时长同样由模型结合上下文理解；制作片段时长与单集时长分别处理。

点击明确的阶段生成按钮时，阶段和范围来自结构化参数，协调调用只整理已确认的对话资料，不能改变按钮选择。大纲、人物、场景和道具阶段属于全剧，使用 `scope: project, episode_number: 0`；只有指定集正文使用 `scope: episode`、目标集数和单集时长。兼容旧请求时会清除全剧阶段误带的集数/时长，所选集数也不会进入全剧任务的意图状态。全剧写作读取全剧文档和所有已保存分集的摘要，不再按当前集和上一集筛选；分集写作继续限定当前集和前集承接。保存全剧草稿不修改分集正文/场次，生成全剧资料也不推进下一集。分阶段生成与自定义完整草稿入口分别标明范围。格式解析、模型可用性、参数范围、文档类型、目标集数和项目归属仍由程序校验。识别失败不回退到文字规则，也不自动保存。

模型任务分别使用独立请求：协调调用读取项目状态和近期对话；写作调用读取相关已保存文档及协调后的创作要求，不携带整段备选方案；接镜检查读取当前制作范围、人物场景资料和镜头状态。它们使用同一个选中的模型，但不共享混杂的任务提示。

分集流程：创作或采用正文 → 草稿预览 → 确认保存 → 分集目录/编辑器 → 选择本集场次加入画布或制作分镜。采用已有消息会逐字保留正文，只让模型整理场次。待确认草稿不会被新的创作请求覆盖。

镜头站位、武器、姿态、面具和道具连续性由显式触发的模型文字检查判断，不再靠关键词。基础素材/时长检查保持本地执行。语义检查结果按镜头与剧本资料快照缓存，变化后显示过期；普通刷新不会再次付费调用模型。检查不代表实际视频画面已经通过审核。

模型目录的输出类型以提供商能力元数据或用户明确选择为准，不根据模型名称猜测。题材的创作描述与展示分类独立：已知分类使用共享目录中的封面；自定义题材通过独立的 `/script/themes/visuals` 模型调用匹配已有分类，仅接受目录内名称，低信心或无合适类别时使用中性雾纹。匹配不会改写 generation_options、文档或对话，不新增全局分类。设定器保留原始题材并单独显示“自定义”，固定分类轨道不插入模型生成的自由文本。未匹配、加载中和封面加载失败都使用柔和的中性水球；切换题材会清除旧图片，旧请求不得覆盖新选择。展示映射不加入编剧上下文。

成本：自由对话和阶段创作通常包含一次协调调用与一次回复/写作调用；仅需澄清时只执行协调调用。点击采用正文只进行一次场次整理。未自动调用图片或视频模型。

“采用为分集剧本”仅对模型确认包含单集正文的助手消息展示。普通讨论、摘要、选项和通知不展示；未知内容先隐藏入口，再由独立文本识别调用判断。模型明确识别出集数时采用窗口预填该集，未明确时由创作者选择。

模型另行识别单集准备资料（明确集数的具体设定、节奏或试写），为当前回复提供“开始创作第 N 集”操作。点击才以结构化阶段和集数启动完整正文创作；准备资料不显示采用按钮。新的用户发言或待回答选择题会取代旧操作，不通过关键词猜测。识别版本为8，旧版本（包括误判为普通讨论的缓存）会重新识别。只有前置全剧资料已保存时才自动推荐开始分集正文；手动指定集数创作仍允许。

收起预览只隐藏界面。待确认草稿保留“查看草稿”入口；保存后保留“查看第 N 集剧本”和“全部创作文档”入口，重开对话时从项目文档恢复。集数选择使用统一的应用下拉菜单，不再调用系统原生 select。

同一次回复识别也判断普通文字是否在请创作者选择原文中的具体方案。识别为选择题后，原回复逐字保留，底部输入区显示原有方案；不使用问号、列表符号或关键词规则补判，不新增、拆分或合并方案。模型结合后续对话判断待回答、已回答或已结束；只有当前最新的待回答问题打开选择面板。明确提交或跳过期间保留面板，模型回复成功后关闭；失败或停止时保留原问题和填写内容。有效的结构化 choices 回复直接渲染，无需补充识别调用。

历史消息通常按最多10条、40KB批量识别，单条长回复允许独立识别，接口总量上限640KB、单条正文上限80,000字符。结果按识别版本、项目、消息ID和正文哈希缓存；所有问题类型的状态另外包含最多8条后续消息的上下文快照。首条创作者回答保留最多40,000字符，以免丢掉多项回答的末尾；其余后续消息保留300字符。正文或相关上下文变化后重新识别，旧缓存不能直接打开面板。识别失败保持入口隐藏并提供重试；识别不修改或保存剧本。尚未识别的普通回复会增加一次文本识别调用，选择题修复复用这次调用，相同内容与上下文重开时复用缓存。

最新回复先单独识别，再处理历史状态；整理当前回复期间隐藏默认快捷建议，避免让用户误以为没有待回答问题。模型必须区分上轮已确认事项和本轮新追问；混合开放问题与明确选择时用 question_set 保留全部不同的待回答事项，不因开放问题整体漏判，也不只保留其中一道选择题。原方案若需要补充具体人选或范围，模型输出 `requires_details:true`，选择后显示补充输入，填写后才能继续；程序只校验结构和必填状态，不猜测人物组合。

最新一轮回复提供“重新生成”（失败时为“重试生成”）。沿用最后一条创作者问题与引用快照，排除不满意的回复，不重复添加用户消息，不消耗尚未发送的输入或引用。成功后形成新的对话分支，原版本以“原回复”保存在历史对话（最多20个历史分支），可切换查看；失败或停止时恢复原回复。待确认草稿须先保存或放弃，已保存的剧本不会被重新生成直接覆盖；新正文仍需确认保存。新回复使用新消息ID，独立重新识别选项与分集入口。

新生成的每条模型回复显示处理用时：从提交请求起实时计时，包含网络等待、意图判断和回复/草稿生成；完成、失败或停止后固定本条耗时，不包含后续的独立回复识别。重新生成独立计时，原回复与其用时保留在历史分支。`processing_duration_ms` 随对话持久化，刷新、关闭重开和切换历史仍显示原记录；用户消息、系统通知和未记录用时的旧消息不显示估算值。计时只在浏览器进行，不增加模型调用。

“重新识别选项”只针对最新普通文字回复，独立调用识别模型，不重写内容。显式单条 `force:true` 绕过缓存；成功时同时替换本条对应的普通缓存和当前上下文缓存，避免旧正负结果在刷新后重新覆盖修正。失败时保留服务端旧缓存并允许再次强制重试。

开放追问使用 `input_request`（识别协议 v7），与 `choice_request` 分开。独立识别模型从回复语义提取 1–4 个待填写字段，参考项仅来自原文示例，不为缺少备选的问题编造选项。前端在底部显示字段和可多选参考，允许自由填写；全部必要字段填写后才能继续。字段值本地保留，提交时逐项带上字段名称，失败保留原表单。创作模型也可直接输出 `kind: input_request`，避免对明确结构再次识别。历史问题状态与后续对话一起缓存，旧版本的 `other` 不再阻止开放追问交互；角色对白、比较说明、已确认事项不因含问句而弹表单。

“跳过”按钮文案保持不变，含义为创作者明确授权模型决定当前事项。为兼容已有请求仍发送 `question_response: { status: "skipped", question }`，同时发送可见的授权消息，直接接续讨论模型。模型结合已确认事实和约束选择方案或补齐具体设定，说明决定及简短理由后继续推进，不保留待定、不重复确认；后续讨论、创作要求整理和文档生成沿用这一具体决定，创作者后续修改优先。未提交的选择和填写内容不当成确认，委托本题不自动生成或保存文档。“跳过”与继续共用提交锁，可停止、失败可重试；无可用模型时不允许提交。历史问题显示“已跳过”；识别协议 v7 区分明确委托与暂不决定，避免旧缓存重新追问已委托事项。输入区域使用中性底色标示聚焦，移除边框、外轮廓及全局表单焦点阴影。

讨论请求使用最近最多32条有效消息、256,000个UTF-8字节的正文窗口，前后端限制一致。普通发送、回答、跳过和重新生成共用窗口选择；保留连续的最新消息，不截断消息正文，不把失败或生成中的消息发给模型。历史记录的保存与请求窗口分开，选择窗口不删除历史。引用文档仍按独立的600KB预算发送完整快照，已保存剧本资料仍由后端补充。保存和下一轮请求都允许助手消息最多80,000字符，创作者消息最多40,000字符，覆盖多题合并回答。回复语义识别属于另一接口，不是整个创作对话的长度上限。


确认提议使用 `kind: confirmation`，普通文本补识别使用 `confirmation_request`，底部提供固定“同意”“需要调整”及自由补充。接受故事框架不代表自动授权生成或保存整份文档。单轮确有2–4个不同待决定事项时使用 `question_set`，每项可为 confirmation、choices 或 input_request，问题ID唯一。界面逐项回答、支持返回修改，全部完成后统一提交一次；选择和填写本身不触发模型。每项“跳过”只委托对应事项，忽略这项未提交的选项或输入，不委托其他问题。答案与局部跳过状态本地保存，刷新后恢复；失败保留整组回答，支持重试。组提交发送 `question_response: { status: "answered", question }`，只接续讨论，不启动文档生成。

创作建议按已保存的非空正式文档计算：故事方向 → 全剧大纲 → 人物与关系 → 场景 → 道具 → 分集正文 → 分镜。人物、场景、道具文档必须是全剧范围；草稿、分集客串人物和通用场次/结构文档不能冒充完成的全剧资料。旧版 outline/characters 字段仅在没有对应全剧文档时兼容使用。分集按已保存正文/场次找首个缺失集数，达到已确认集数后停止自动推荐新集。

保存草稿后从实际保存响应重新计算进度，快捷建议与协调/讨论/写作模型使用同一规则。已有人物先保存、随后保存或修订大纲时，复用人物并推荐下一个缺失阶段。大纲更新不使其他文档自动失效；仅明确要求修改或发现具体冲突时建议针对性修订。阶段列表标记已有资料，仍可手动选择阶段，不以推荐顺序阻止创作。未确认的草稿须先保存或放弃，才启动其他阶段。


剧本对话现在按程序给出的当前阶段组织交互。默认阶段由已保存的正式资料决定；故事方向作为大纲准备，第一份正式产物是全剧大纲。每个问题携带 `interaction`（目标阶段、setting/generate/revise 用途，分集需带集数），阶段指问题服务的文档，不按人物、地点等关键词判断。大纲阶段的人物目标问题可正常回答，完整人物档案的生成提议不能越序出现。结构化 JSON 和普通文字的语义识别使用同一阶段校验；缺少标识的旧回复会重新识别，无法提供有效标识时显示识别失败和重试入口，不显示未验证按钮。多题只保留当前阶段的设定问题。

生成或修改文档的提议使用 `workflow_action`，由程序核对目标后展示明确的生成按钮，不变成“同意／跳过”的设定题。单题、多题回答及跳过统一只继续讨论；生成草稿不改变已保存进度，待确认时禁用新文档推进，确认保存后才计算下一阶段。普通“继续”产生的生成意图必须匹配当前阶段和集数，不得重做已完成资料；创作者明确的阶段按钮、自然语言生成／修改／采用要求仍可跳转。明确转入某阶段的讨论可保留为临时范围，阶段和识别缓存随消息保存，回答、跳过、重试及刷新均沿用，新的保存进度会使旧范围和旧操作失效。

阶段控制保留原有 Skill 注入：启用的剧本规则仍参与讨论和阶段写作，视觉资产及图片／视频提示词的 Skill 入口保持原有机制。程序阶段约束和创作者明确要求优先于 Skill 中的流程建议。
