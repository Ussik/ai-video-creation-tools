# 阶段创作：从讨论到保存

在项目的“剧本”中打开创作对话，可讨论故事、生成大纲和分集正文，再将确认的场次交给分镜。开始前，请在“模型设置”中配置并启用一个支持工具调用的文本模型。

**模型回复、任务预览和待确认草稿都不等于正式剧本。确认保存后，内容才进入项目文档并推进创作进度。**

## 1. 讨论故事方向

输入故事创意、主角目标和你希望保留的限制。有现成剧本时，先按[原稿指南](script-source-context.md)上传，不必重新描述整篇故事。

例如：

> 我想写一部 6 集短剧。主角是夜班公交司机，在最后一班车上遇到十年前失踪的姐姐。先讨论故事方向，暂时不要生成正文。

模型可能提出选项、填写问题或确认提议。回答后会继续讨论；接受方向本身不会自动生成大纲，也不会保存整份文档。

“跳过”表示**把当前问题交给模型决定**。如果你想保留决定权，请直接说明“这件事暂不决定”，不要用“跳过”代替。

**你会看到：** 当前待回答的问题位于对话底部；已经确认的决定可在“项目文档”中查看。只选择选项、尚未提交时，不会调用模型。

## 2. 选择本次成果

使用对话中当前有效的生成按钮，或打开输入区菜单中的“分阶段生成”。确认“创作阶段”和“本次交付”，再点击生成。

首次创作按“大纲 → 人物与关系 → 场景 → 道具 → 分集正文”推进。未保存阶段按顺序开放；已经保存的阶段可返回修改。

### 大纲可以先做一份

| 选择 | 适用情况 | 本次成果 |
| --- | --- | --- |
| 生成初步大纲 · 仅概要设计 | 从创意开始，先确认主线 | 一份概要设计 |
| 整理原稿大纲 · 仅概要设计 | 已上传剧本，先梳理原故事 | 一份忠实原稿的大纲 |
| 完整大纲设计 · 9 栏 | 需要完整的全剧设计资料 | 九份大纲设计文档 |

完整九栏为：概要设计、故事简述、背景设定、全剧分段、钩子预设、伏笔与回收、反转预设、创作禁区、分集大纲。

普通原稿大纲会直接依据完整有效稿整理，不等待整套后台分析完成。其他功能若提示依赖原稿分析，请按界面提示先完成相应步骤。

### 后续阶段交付什么

| 阶段 | 成果 | 范围 |
| --- | --- | --- |
| 人物与关系 | 人物小传、人物关系 | 全剧 |
| 场景 | 场景清单、空间与动线、视觉与氛围、场景连续性 | 全剧 |
| 道具 | 道具清单、外观与辨识、剧情功能与使用规则、归属与状态流转 | 全剧 |
| 分集正文 | 指定集的完整正文和分场 | 仅所选集 |

生成分集时，检查集数与单集目标时长。保存全剧资料不会自动生成下一集；首次生成分集时，从最早缺失的集数开始。

**你会看到：** 任务清单、当前处理步骤和已完成成果的预览。多份成果可逐项出现；这些预览仍待核对和确认，不代表正式保存。

## 3. 查看草稿并确认保存

1. 打开“查看草稿”或“查看待确认草稿”，逐份检查正文；分集还要检查分场、对白与时长。
2. 需要调整时，在草稿中编辑，或在对话中明确指出修改对象与要求。
3. 确认本次修改范围和内容后保存；不采用时选择“放弃草稿”。

例如：

> 只修改第 1 集结尾：姐姐不要直接说出真相。保留前面的对白和场次，其余集数不变。

**保存后：** “项目文档”中可阅读正式内容，编辑器与阶段建议会更新。已有待确认草稿时，先保存或放弃，才能开始另一项文档创作。

收起预览只是隐藏窗口，不会放弃草稿。模型返回“已完成”也不能代替保存动作。

## 4. 修改已有文档

打开“项目文档”，选择文档后可用“模型评审”“对话修订”或“编辑文档”。在“分阶段生成”中，还可为已保存阶段选择处理方式。

| 处理方式 | 会做什么 | 适合的要求 |
| --- | --- | --- |
| 局部修改 | 修改你指定的内容，先交付草稿 | “补齐林晚的职业，保留其他角色” |
| 补齐缺失栏目 | 只生成尚缺栏目，原有标题与正文原样保留 | 已有初步大纲，补足其余设计资料 |
| 重新设计整阶段／本集 | 在原阶段或指定集范围内重新编写 | 主线已变化，需要完整重做该阶段 |

重新设计仍需确认保存。重做已保存分集时保留原场次关联，可重排或增加场次，不会自动删除旧场次，也不会推进到下一集。

如果一条助手回复已包含可采用的单集正文，可能出现“采用为分集剧本”。检查目标集数后采用：正文逐字保留，模型整理对应分场，随后仍需确认保存。

## 5. 将已保存分集加入画布

在分集目录或编辑器选择场次，点击“加入画布”。检查本次范围、模型和分镜要求；未规划场次需点击“开始规划”，再检查镜头并确认加入。

已有分镜且来源仍有效时可以复用。加入画布会整理所需视觉设定文字并导入节点；图片和视频由你后续显式生成。

**你会看到：** 画布中的镜头与生成节点。不同方案、旧镜头和媒体的保留规则见[项目多画布](project-canvases.md)。

## 常见问题

| 现象 | 如何处理 |
| --- | --- |
| 生成按钮不可用 | 检查可用文本模型、故事依据、前置阶段和待确认草稿；按按钮旁提示处理。 |
| 只生成了一份大纲 | 当前选择可能是“仅概要设计”；需要九栏时选择完整设计，已有大纲可补齐缺失栏目。 |
| 后续阶段锁定 | 首次生成需先保存最早缺失阶段；草稿不会计入正式进度。 |
| 草稿收起后找不到 | 使用“查看草稿”重新打开，或到“项目文档”查看草稿入口。 |
| 希望重写刚才的回复 | 使用最新回复的“重新生成”；原版本保留在历史分支。已有草稿须先处理。 |
| 文字里有选项但没有操作按钮 | 等待回复识别；失败时可重试识别。重新识别不会改写回复。 |
| 断线、停止或执行失败 | 先查看原任务和已保留成果，按[恢复指南](script-task-recovery.md)继续；避免重复新建相同任务。 |
| 保存提示来源已变化 | 重新读取当前文档或原稿，再生成并核对草稿；旧草稿保留供查看，不强行覆盖新版本。 |

## 原稿问答、草稿和画布的范围

| 内容 | 何时生效 |
| --- | --- |
| 上传原稿与分析资料 | 为讨论和创作提供来源；上传、分析不会自动生成阶段文档 |
| 对话中的方案或模型建议 | 供讨论；未经接受，不当成已确认设定 |
| 待确认草稿 | 可查看和修改；确认前不覆盖正式内容 |
| 正式文档与分场 | 确认保存后成为项目资料，参与后续阶段 |
| 分镜、图片和视频 | 各有独立的规划、生成与审核步骤，不因改稿自动重做 |

草稿绑定生成时的有效稿、文档和场次版本。上传替换、确认原稿修订或其他窗口修改资料后，旧草稿必须通过版本检查才能保存。

## 必要限制

- 剧本流程需要接口实际支持工具调用；能返回普通文本不等于能完成本流程。配置见[模型交互机制](model-interaction-controls.md)。
- 阶段生成包含核对，发现问题可能继续修补；一次操作可能产生多次文本模型调用。查看任务进度，费用以实际服务账单为准。
- 独立核对帮助发现缺项和矛盾，仍需你判断故事质量。接镜文字检查也不能代替审看实际视频。
- 已安装 Skill 可参与创作，但项目阶段、明确创作要求和确认保存规则仍有效。

### 阶段与任务范围

全剧大纲、人物、场景和道具使用全剧范围；分集正文使用指定集范围。按钮明确给出的阶段和成果范围不由意图识别改写；自然语言请求由模型识别目标。

任务合同在生成、接续、核对及保存之间保持一致。完整设计按依赖任务交付；补齐时逐字保留已有文档。具体任务分组、恢复及复核策略见[任务与交付流程](script-agent-workflow.md)。

首次生成、局部修改、补齐与重新设计分别对应 `generate`、`revise`、`supplement`、`regenerate`。保存核对原稿、文档、草稿及场次版本，不允许旧接口绕过草稿确认。

重新设计单集时通过 `source_scene_id` 对应原场次，保留文档与场次 ID、镜头、素材和视觉绑定。未涉及的文档和其他集不在本次保存范围内。

### 对话与识别

问题包括确认、选项、开放填写及多题组合。回答或跳过只接续讨论；生成提议单独展示明确操作。最新有效问题与阶段一起校验，过期操作不能自动执行。

讨论请求保留最近的有效消息窗口，历史保存与本轮模型输入分开。阶段写作保留窗口内原话；最新明确修改优先，未接受建议不升级为已确认要求。

重新生成沿用最后一条创作者问题与引用快照，成功后形成新分支；失败或停止时恢复原回复。重新识别选项为独立只读识别，不重写或保存剧本。

题材封面的展示分类不改变创作设定。模型目录的输出类型由能力元数据或用户选择决定，不从名称推断。
