# 剧本候选稿分析与用量记录

> 实现核对：2026-10-24，当前工作区实现。创作对话与上传后台分析不再设置应用层的累计请求、累计 token、模型决策、工具操作、修订轮数或业务时长上限。用量账本只统计，不作为执行门禁；模型配置和供应商真实容量仍生效。

普通上传原稿大纲先按单份成果直接生成与核对，不等待整套原稿分析；完整设计按成果依赖执行，见[智能体任务与交付流程](script-agent-workflow.md)。

候选稿修订仍读取完整当前有效稿，但候选文档改为按问题位置预载相关完整正文，其余关联文档通过只读工具批量读取、搜索，再提交精确补丁。创作补充落实到候选文档与具体决定，不默认扩写原稿；只有有效稿确需最小同步修改时才生成拟修订，随后分析新稿。修订前不再生成没有被修订请求使用的目录。

候选稿可以复用已通过质量核对、模型和配置一致的旧稿目录页。基线取自当前有效稿的已保存分析或兼容的 `source-proposal-base`；程序检查原文范围、逐字证据和版本绑定，变化范围及关联章节重新分析。每份内容变化的新稿仍重新进行全剧综合、全文质量核对和独立阶段设定复核；同内容、同配置且已通过的私有分析可直接复用。原始上传文件与显式保存确认保留，具体复用与完整回退条件见[原文资料策略](script-source-context.md)。

全剧时间线、伏笔和不确定事项按目录事实的预计输出容量分组：累计预估超过 12,000 字符或已有 32 段时开始下一组，单章保持完整。每个任务仍读取完整原文与目录。新布局使用 `source-story-parts-v4`；匹配的旧 v3 checkpoint 按原每 12 章布局继续，避免丢失完成结果。跨组合法引用由程序校验、精确去重并合并引用；不合法结果不会发布，先按下述规则恢复。人物批次另按最多 12 个目录姓名规划，后续批次可保守使用原文证据包，最终质量核对仍读取全文。

## 分析内部恢复

来源理解中的遗漏、误读和模型返回格式错误属于系统内部处理，不作为新的创作决定要求用户反复点击“继续”。上传后台分析和候选修订稿分析在同一次执行内，依据原文定点修补已保存的分析，再独立复核；只改变分析，不据此补写原稿。质量修补、分析格式恢复及全文目录重建不再按累计次数停止，已完成目录页、全剧任务和单项修补均沿用检查点。结构化单次请求仍执行实际格式校验；网络、鉴权和配置等真实错误正常返回，用户可随时停止。

不能安全定点修补时，依据核对证据重建全文目录；重建后的问题继续按真实诊断处理。恢复按实际保存的目录、全剧理解、任务结果和问题证据判定进展，不把轮次、时间戳或诊断换措辞当作进展。同一保存结果与同一问题再次出现，或回到此前相同结果时，结束本次自动循环并保留检查点，返回 `script_source_analysis_stalled`；创作者可明确继续当前步骤或更换模型。无效证据编号不断变化不能绕过该判断，局部修补与全文重建之间也不能反复空转。取消、鉴权、网络故障及来源与配置变化保留进度和原因，不伪装成需要用户回答的故事问题。

目录与全剧理解明确保留数量及分配、容量已满或资源用尽、规则前提与例外、人物动机转折、事件先后与最终状态。独立核对要求一次列全可确认的实质问题，并接受其他位置或等价表述已保留的事实，减少逐轮挑出同义问题。格式纠正按实际修改目标返回字段级诊断；结局修补必须返回完整对象。

## 阶段核对输出超限恢复

阶段独立复核发送完整当前有效稿、全剧综合理解、全部候选正文和分场、保存文档、创作决定与完整对话要求；上传稿的重复目录、逐字分析证据和恢复运行态不再次作为原稿发送，减少重复输入。保留全剧综合理解用于导航，完整原文仍是事实依据。原稿整理任务直接核对完整原文；完整设计需要的来源分析由复核阶段准备，不作为每次对话和普通大纲生成的统一前置条件。模型返回的问题采用最短充分引文和简洁说明，不复述故事。

已核实且有非空具体 `decision` 的历史处理记录，只有在决定和作者答案均不依赖历史引用时，发送给模型才移除旧 `problem` 和批次 `summary_id`，保留具体决定、作者答案、处理方式、事项标识及其他字段。`decision` 或 `answer` 含“采用方案二”“同上”“按上述”等引用时保留整条记录及其引用的批次摘要；其他仍被保留记录引用的摘要也继续发送，没有引用的批次摘要不发送。未核实记录、缺少具体决定的旧记录及未知数据结构保守保留。提示词明确历史问题和整批修补摘要不是当前缺陷证据；同一事项的冲突决定只能依据明确采用时间判断，不能按数组顺序推定。原稿、当前候选、创作者原话和所有具体决定不压缩。该处理只改变发送内容，完整原始请求仍用于整体、维度、证据及推理恢复的检查点身份；不会仅因这次投影使已通过的核对失效，也不改写历史数据。

整体复核收到供应商明确的普通输出长度终止时，在同一次执行内改用三个固定核查维度：核心设定与作者答案、全文因果与跨文档一致性、原稿忠实度与既有决定落实。下述已确认的纯推理耗尽使用独立策略。每个维度仍读取同一份完整原稿、全部候选和完整背景，不按片段审查，也不把摘要当全文。各维度必须返回完整合法的结构化结果、覆盖全部送审文档，并通过逐字证据校验；全部完成后合并发现，才能判定整体结果。每项最多 200 条发现，最多暂存三项共 600 条报告再语义归并，保留重复事项的不同证据；最终仍以最多 200 个独立事项为交付边界，超出时明确停止，不静默截断。被截断的 JSON 即使看似合法也不直接采纳。

策略切换与已完成维度分别保存检查点，继续时沿用同输入的已完成结果，不重跑原先超限的整体请求或已完成修订。首次填写方案或委托 AI 时固定完整的创作者对话与引用资料；该授权下的“继续”控制消息不作为新增创作要求，不使已完成维度失效。调整方案或明确重新委托时重新绑定创作上下文；原稿、候选或模型配置变化仍按原版本校验处理。旧任务缺少固定上下文时使用其已保存的原请求，不从历史失败回复推断新增要求。某个维度再次发生普通输出超限就保留进度并停止；符合下述条件的纯推理耗尽切换直接答复策略；不把真实失败当作完成。已完成维度保留，尚未完成维度可继续，不写永久阻断检查点。剧本作用域取消应用层单步和总期限，真实网络重试与格式校验仍区分执行错误。

DeepSeek 官方文档说明相关模型默认使用 `high` 推理。只读阶段复核和引文定位现在使用独立的请求策略，仅适用于 HTTP 文本适配器、精确的远端模型 ID `deepseek-flash` / `deepseek-v4-pro`，以及实际生效的 HTTPS `api.deepseek.com` 官方 Responses 或 Chat Completions 端点（含可选 `/v1` 前缀）。判定包含模型单独配置的地址和请求路径，不只看模型名称。其他网关、未知模型、普通创作及原生工具请求沿用自身配置，不写回模型设置。

| 只读请求 | 推理参数 | 输出额度 |
| --- | --- | --- |
| 整体或维度语义复核 `script_review` | 沿用模型配置，不注入默认值 | 沿用模型配置 |
| 纯推理耗尽后的答复 `script_review_answer` | `none`，覆盖该次请求原 effort | 沿用模型配置 |
| 引文句段定位 `script_evidence` | `none`，覆盖该次请求原 effort | 沿用模型配置 |

不再注入 32,768 / 16,384 等额外额度，也不压低显式配置；非法配置仍交给原有校验。Responses 使用 `reasoning.effort`，Chat Completions 使用 `reasoning_effort`。这里的输出额度包含推理，不代表保证预留等量正文。

只有供应商明确报告输出超限、正文严格为空、输出 token 是大于零的安全整数，且 `reasoning_tokens === output_tokens` 时，才识别为纯推理耗尽。支持策略的整体或单个维度先持久化 `review:reasoning:<stepId>` 的 `answer` 状态，再用同一核对内容直接答复。整体再次输出超限时按三个维度恢复；单维度仍失败时返回真实错误并保留成功步骤，继续时只处理未完成部分。旧 `blocked` 状态视为已选择直接答复策略并可恢复，不再永久拒绝请求。网络中断保留 `answer`，恢复不回到已耗尽的初始推理。聊天旧任务继续固定原模型配置；更改模型配置后应从候选稿入口发起新处理。

缺少纯推理用量证据或不支持该请求策略时保留原有普通超限规则，错误不会被误判为推理耗尽。取消、鉴权及传输错误不触发推理策略切换。输出超限不是可通用重试的网络故障；此恢复仅发起只读核对，不重放保存或编辑工具。协议参考：[DeepSeek 模型与价格](https://api-docs.deepseek.com/quick_start/pricing)、[Chat Completions 参数](https://api-docs.deepseek.com/api/create-chat-completion)。

## 阶段核对引文定位恢复

单条 `findings` 或 `facts` 的引文未逐字匹配候选稿时，不再让模型携全文重答整份审读。结构、全部文档覆盖及真实来源先单独校验，合格的审读结论保存为待核实结果；这不是复核通过。系统仅发送有错误引文的条目及其对应候选文档，每份文档只出现一次。模型选择原文句段的起止编号，程序从同一候选正文连续截取引文，再执行原有长度、来源和逐字匹配校验；问题的事项、类型、说明、建议、顺序及数量保持不变。

一批多条引文同时处理。若某条没有支持原问题的证据，明确返回无法定位，保留该问题并停止，不能删除或换成无关原文来通过；同批其他已成功定位的引文保留。格式或编号错误仍按单次结构化生成流程校正；真实网络错误正常返回，已完成定位保留。局部定位的输出超限不会触发三个维度的全文重审。

待核实结果绑定完整审读请求及候选正文；中断后只继续尚未核实的引文。候选、原稿、创作要求或模型配置变化时，依照原缓存规则重新核对。全部引文有效后，才将本轮结果交回原来的全文或分项复核流程，不额外重做语义审读。既有成功复核检查点保持兼容。旧版本已失败且未保存完整审读对象的任务不能从截断错误日志重建结论，首次继续仍需一次独立审读；已完成的候选修补不因此重写。

## 用量记录

后端创作对话入口建立本轮账本，覆盖意图判断、普通对话、原生工具决策、历史压缩、阶段生成、修补、来源分析、独立复核、格式修正与网络重试。同一持久任务断线或服务重启后沿用 `current`；新的主动执行另建账本。嵌套阶段账本同时记录对应阶段范围，两者不能相加。

同一个不可变上传版本，以 `[stage, scope, episode_number]` 保留阶段累计。候选版本变化、自动修订、连接中断和点击继续不清零；其他范围独立计数。替换、重传或删除上传文件清理对应私有账本，确认保存修订稿不重置它。无上传原稿时不创建阶段候选分析私有账本。

旧 `VIDEO_STUDIO_SCRIPT_EXECUTION_MAX_REQUESTS`、`VIDEO_STUDIO_SCRIPT_EXECUTION_MAX_TOKENS`、`VIDEO_STUDIO_SCRIPT_ANALYSIS_MAX_REQUESTS`、`VIDEO_STUDIO_SCRIPT_ANALYSIS_MAX_TOKENS` 不再作为执行限制，旧快照和内部兼容选项中的同名额度也忽略。旧高用量任务可继续，无需清空历史。`unknown_output_tokens` 仅用于无供应商用量时估算，不限制执行。

请求发出前持久化输入估算和输出预留；供应商上报实际用量后逐字段替换。推理 token 属于输出，不重复相加。无用量上报的请求保留估算；缺少输出配置时初始预留 4096 tokens，观察到更大输出后可上调。预留不作为输出截断值。usage 活动和响应身份在派发、轮询与结算时同步保存，恢复不重复计费或漏算。后台响应轮询和取消另计传输次数，不计作新生成请求。

界面仅显示任务进展和成果，不展示本轮或累计用量、token、容量与请求统计；历史用量记录保留在内部账本。补丁完成、目录完成均不代表最终复核已通过。

## 修订收敛

候选修订的结构契约按本次真实问题数指定 `decisions` 的精确数量，每项问题都须有具体采用决定，即使多项问题共用一处正文修改也不能合并或省略决定。数量、补丁定位等内部输出错误不构成新的创作提问。

新的修补采用绑定候选与有效稿版本的只读工作区，提供 `get_repair_context` 批量读取、`search_repair_context` 字面搜索和 `submit_repair_patch` 提交。问题及关联问题所指文档完整预载，位置未知或不属于目录时扩为全部候选正文。搜索结果不能代替完整读取；只有预载或完整读过的文档可以修改，重复读取已加载文档只返回版本引用。当前有效稿、原始创作要求、用户方案与既有决定仍完整提供。

修补和普通创作工具会话均不再按模型轮数、工具次数、连续失败次数或文字回复次数停止。成功提交有效补丁后立即结束，无额外总结。失败操作将具体诊断反馈给模型，要求补读或纠正；未提交补丁的文字不能当成功。同一已读资料上重复相同操作、无效补丁或仅返回文字时，停止本次工具会话并保留候选；不同查询、有效读取和实际修改仍可继续，不以轮次、调用 ID 或总结措辞判断进度。补丁仍须通过版本、已读范围、逐字唯一定位、非重叠、决定数量和场次校验；空修改不能冒充进度。独立复核后若正文与问题均重复，先切换为逐项对照决定和证据；同一策略仍无进展时保留具体分歧并结束本次自动循环，不重复消耗于同一结果。每次读取、搜索及补丁提交记录开始、成功、失败或取消，只公开数量和短诊断，不记录剧本正文或完整补丁参数。

提供商或协议明确不支持原生工具时使用完整资料的结构化补丁路径；仅首轮明确的工具能力拒绝可自动切换，网络、鉴权和普通格式错误不触发协议回退。已经开始且匹配的旧修补检查点继续沿用旧请求。完整修订请求在一次格式修正后仍不合法，或供应商明确报告输出超限时，自动持久切换为两个只读生成步骤：先按问题标识生成完整具体决定，再依据已校验决定生成精确修改。两个步骤保留完整原文、全部候选稿、问题、原始授权和已有决定，不能用摘要或活动总结替代决定。新流程的创作补充优先落入候选正文和决定，`source_edits` 默认空数组；有效稿确有直接冲突且需同步时才提交最小修改。

决定和补丁检查点分别保存；补丁生成中断后只继续补丁，已通过的决定不重新选择。旧版完整合法修订检查点继续校验后复用。恢复过程发出实际进度，任务保持执行，不要求用户再次点“继续”或重复委托 AI；每次结构化生成仍校验真实输出格式；取消、鉴权/配置、网络及不可恢复的数据错误保留成果并正常返回，不使用累计额度或业务期限阻断后续工作。

已授权事项进入下一轮自动修订时，新候选版本与持久任务的继续请求、恢复校验值在同一事务内保存，避免服务中断后任务仍引用旧候选。原始提交的幂等身份、人工答案或 AI 委托及累计轮次保留；外部原稿或模型配置变化仍会阻止沿用旧任务。内部恢复完成后，同一逻辑步骤显示最终状态，底层请求记录保留实际失败与用量。

同一处理方案按原授权自动修订与独立复核，不设四轮累计上限。轮数仅用于进度诊断，旧累计轮数也不会禁用继续按钮。新独立问题仍需要对应的创作授权；最终保存仍需明确确认。阶段内容接续默认也不再按 16 / 32 轮停止；无进展先缩小为下一个完整小节，相同保留内容在同一接续方式下仍无新单元时，停止重复请求并保留检查点，支持显式继续及随时取消。

局部补丁通过程序校验后仍执行独立全文语义审读，不能把工具成功或内容指纹变化当作故事正确。有效稿没有变化且已有分析仍匹配时沿用分析，不为候选文档自身的改动重做原稿分析。候选稿在修补期间可只读预览，预览校验候选版本，不发起模型请求，也不提供编辑或保存入口；复核通过后的正式确认流程保持独立。

已回答或委托 AI 的同一事项，再次发现未落实时按候选稿保留的精确问题标识复用原决定，包括之前轮次已处理的事项。新的独立创作问题仍提供人工填写或交给 AI 的入口，不因自动恢复而扩展授权。
