# 剧本分析、补齐与复核增强

> 实现核对：2026-10-22，代码基线 `9ba5a25`。以下是当前行为及保存边界；外部模型质量、速度与费用不由本页保证。

## 全文输入与上传上限

剧本正文最多 100,000 字符（JavaScript UTF-16 长度），超过上限直接拒绝上传，不提示拆分上传。文件仍限制为 10 MiB（10 × 1024 × 1024 字节）；支持 TXT、Markdown、DOCX 和有文字层的 PDF。

上限以内的目录分析、阶段生成、补齐与独立复核读取完整有效稿，不再按 6,000 字符安排模型阅读批次，也不再根据 12,000 或 24,000 字符阈值切换阶段生成的片段检索。长稿全剧整合的后续人物批次可保守使用原文证据包，普通明确局部查询也可选择相关原文；范围和全文回退规则见[原文资料策略](script-source-context.md)。模型整理的剧情段落、目录及原文证据继续保存，供展示、核对和精确修订。目录分页只限制返回的目录范围，每页仍保留全文；全剧整合按任务维度控制输出，不使用片段摘要层层归并。

每个阶段先一次生成本阶段候选文档，不预先拆成逐栏目或每八集一次的生成请求。若上游明确报告输出长度耗尽，保留完整且通过结构校验的成果，再以完整有效稿、创作要求和已有成果继续未完成内容。单个栏目也可按模型理解的完整语义块接续，残缺 JSON 与未闭合文本不直接拼接。接续次数、主动执行时间和无进展检测均有界，不能无限请求。各阶段仍按已有工作流推进，全部生成后独立复核，最后由创作者预览并确认保存。已配置模型容量且请求估算超限时在发送前返回错误；未配置容量时保持未知，供应商仍可能拒绝请求。两种情况均不静默删减原文。

流式正文保留每个增量中的全部空格、Tab 和换行，包括只包含空白字符的增量，防止已保留的文档与结束事件的同一份全文产生字节差异。推理、分析、拒绝和工具元数据仍不进入正文。达到输出上限后，流中已保留的完整文档必须与结束事件正文一致；真实不同的正文仍阻止覆盖，不能以忽略冲突的方式继续。

一旦已有完整文档或接续单元，仅因外壳损坏或缺少必需栏目而触发的格式修正不再要求重新返回整份阶段对象，而改为使用已保留正文补齐缺失目标；接续 Schema 与提示词明确限定当前目标和相同文档标题。重复类型、错阶段文档、真实正文冲突与业务校验失败直接拒绝，不能先过滤错误单元再把剩余内容当作成功结果。所有栏目齐全后，原有阶段范围、场次与业务校验仍重新执行，已有事实或原文证据不合格时继续拒绝。尚未接收到完整单元的情况仍允许原有有界格式修正。

## 分析就绪条件与恢复

当前全文分析管线为 v6，兼容重新校验通过的 v5 全文检查点；片段摘要旧流程不能冒充完成。分析依次完成目录与证据、全剧整合、独立语义核对，全部通过才标为 `ready`。全剧整合必须保留目录已识别的人名或有证据的别名，有关键事件的章节必须进入时间线。独立核对再次接收全文和完整分析结果，检查实质遗漏、无依据的结论与因果误读，特别关注后半部、伏笔和结局。返回的章节和原文证据 ID 必须真实、完整且不重复；纯设定资料或没有给出结局的原稿不被强迫编造剧情。

长稿采用可持久的有界输出：原稿正文超过 16,000 字符时，目录按约 8,000 字符范围分页，优先语义标题并保持完整句段；每页均收到完整原文，仅产出明确窗口内的目录，校验后保存。超过 32,000 字符或 80 段目录的全剧整合按概览、人物、时间线、伏笔和不确定事项分别输出；每项合法结果单独保存。首批人物及非人物任务读取全文，后续人物批次满足条件时提供完整目录和相关逐字原文，证据不足只让当前批次转全文核实。续跑重新验证已保存任务与输入哈希，损坏结果只重做受影响项，未完成目录或整合不能解锁创作发送。

人物整合每批必须覆盖指定名单。模型附带其他批次的目录已有角色时，逐个检查姓名、别名和引用章节证据，合格后保留补充事实并在全剧结果中统一去重，不因跨批重复而拒绝整批；目录之外的独立人物仍仅在首次人物任务中补充。无证据身份、非法章节和当前批次遗漏继续拒绝，修正说明包含具体批次和人物。归并描述或别名超限时使用可恢复的归并任务，不截断已有事实。此项兼容此前合法的整合检查点。

姓名与每个别名分别核验所引章节：目录记录或该章节原文字面命中任一成立即可，名字已在其他目录段出现也不能屏蔽本章原文证据。错引章节仍拒绝；修正信息列出人物、别名、实际引用及可核验的章节 ID 与标题，区分“引用不匹配”和“全文目录均未找到”。名称出现不等于同一身份成立，身份关系继续结合全文独立核对。失败任务的私有检查点保存具体姓名、引用章节和候选证据章节，不保存完整模型返回或复制原文；显式继续时带入定位提示并重新校验，不能自动补贴章节或据此认定身份。合格结果清理对应失败诊断，取消与持久化错误不覆盖原始失败原因。

语义核对发现问题后保留原文、完整分析与问题证据，分析停止。创作者明确继续时，依据完整原文逐项修补受影响的分析字段，修改前的值必须匹配，每项通过来源、覆盖和引用校验后保存进度；中断只继续未完成问题，修补后仍须全文独立核对。最终核对连接失败只重做核对，不会循环请求直到模型声称通过。核对与修补检查点绑定来源、目录和全剧信息的哈希，输入变化后不得沿用旧结论。有效稿修订的私有分析采用相同规则；确认修订后旧目录理解失效，或修补任务明确说明必须改变章节边界等无法安全局部修补的原因时，执行一次受控重建。格式、证据或网络错误不触发语义重建。重建已开始的任务保留该轮已完成的页与整合项，重建后再次发现问题则停止，不自动循环。

后台分析默认同时运行 2 个项目；`VIDEO_STUDIO_SOURCE_ANALYSIS_CONCURRENCY` 可设为 1–4。队列显示等待位置，运行中或排队中均可暂停；暂停保留原稿和已完成步骤，输入框仍可填写要求，明确继续后再处理。服务重启恢复未完成运行任务，保持主动暂停的任务暂停。该队列面向当前单服务进程，不提供多进程分布式租约。

分析界面按真实后台状态展示“全文分析 → 全剧整合 → 质量核对”，不再把阶段映射为 0/85/92 等固定百分比。全文目录和证据校验通过后才完成第一步，全剧整合结果保存后才进入质量核对，独立核对通过才显示就绪。失败、暂停也保留步骤和上次具体处理项，恢复说明依据可复用检查点生成；只有原稿时显示“重试分析”，有有效分析结果时显示“继续未完成步骤”。前端继续约每两秒查询状态；单个模型请求内没有可量化的完成比例，不推算剩余时间。状态读取失败时保留上次确认的已完成步骤，显示重试提示，暂停当前步骤和计时的展示。

服务端在每次实际进入运行时记录 `started_at`，界面据此显示“本次已用时”，刷新页面仍沿用同一次运行的起点。排队不计时；继续、重试和服务恢复后的新运行重新计时。旧快照没有起点时不补造耗时，原稿时间与状态更新时间均不作为开始时间。

独立核对至少需要一个单独的全文模型步骤；格式修正、网络重试或后续修补后的核对可能增加请求、耗时和费用。它是不同请求中的审读步骤，仍依赖所选模型，不能保证真实剧本零遗漏。

## 阶段创作的对话与来源版本

阶段编写请求携带本轮提交的完整消息及角色，保留尚未写入决定表的创作者要求。最新明确修改只替代对应旧要求；未接受的助手建议不成为已确认事实，也不授予其他阶段生成、原稿修改或保存权限。前端历史消息数量与请求体上限仍生效，不代表无限历史记忆。

工具草稿和普通阶段草稿记录生成时的有效稿版本，包括当时没有上传原稿的 `null` 状态。相同文本重新上传、替换、移除、新增或独立修订原稿后，旧草稿保存返回 409，候选内容保留且正式资料不写入。原稿修订与阶段文档仍在确认后原子保存，上传原稿保持独立保留。独立视觉资源草稿不因无关原稿变更而被锁定。

旧草稿缺少来源记录时仍可查看、编辑和放弃，需要重新生成核对才能保存。普通保存接口 `PUT /api/projects/:id/script/director/draft` 要求返回生成结果中的 `source_version`（无原稿时显式传 `null`）；携带有效 `source_update` 的旧调用可采用其 `base_version` 校验，不能将页面当前版本当成旧草稿的生成版本。版本检查在保存事务写入之前执行。

保存阶段草稿本身不会重新分析原剧本。若同时确认了有效稿修订，系统优先采用保存前已完成的私有分析：项目、完整正文及文件名、分析管线版本、模型与实际请求配置必须一致，全文覆盖、原文证据、全剧信息及独立质量核对必须全部通过。命中后直接显示当前有效稿的剧本地图已准备，不新增模型请求或本次分析计时。私有分析检查点独立保留至后续使用，生成步骤清理和内存缓存淘汰不再导致重复分析；上传替换或移除会清理相应私有检查点。结果缺失、未完成、质量不合格或身份不匹配时仍执行正常分析，界面说明是在为修订后的有效稿更新剧本地图。

预览修订稿时，先单独显示“分析修订稿”，成功后才进入“核对阶段设定”。来源分析中断明确提示尚未开始阶段设定核对，候选稿及兼容的修订检查点保留；修订条目全部处理完成不代表分析或独立复核已经通过，也不会提前写入正式文档。

## 对话画风的即时同步

普通创作对话的意图识别结果可同时携带本轮已确认画风及其真实消息索引、逐字引文。只有来源属于最后一条创作者消息且引文匹配时，服务端才复用现有画风工具直接保存，不等待后续模型选择“读取画风—写入画风”。画风与来源决定在同一事务写入，只同步画风和表现细节，不带入客户端默认值或其他临时设置。

纯画风设置在这次意图模型调用后直接回复保存结果；混合剧情讨论或文档生成要求继续走原有流程，后续状态查询立即读到新画风。保存完成即发送更新后的设置，最终结果也返回设置与项目刷新标记。来源缺失或不匹配时回到原有工具流程，不自动写入。意图识别前捕获画风版本，期间其他操作更新画风时返回 409；取消后不执行写入。

同轮合法保存画风后，候选缺口保留和持久任务恢复使用保存后的版本，避免把自己的操作当成外部修改；保存前仍核对完整项目与原稿状态。同一来源、同一画风和细节的重试复用已有决定，不改写时间与检查点身份。仅带服务端同步标记的该操作允许原本可恢复的任务继续，普通模型工具的写入保护保持生效。

明确指定、接受与否定、未选方案及只分析不保存的区别仍由意图模型按语义判断，程序只验证来源、引文、结构与版本，不使用画风关键词代替语义判断。显式阶段按钮、文档评审、结构化问答或已有待确认草稿继续采用各自路径，不为了同步画风新增一次意图调用。

活动记录保存调用时的快照。画风查询摘要写明“查询时已保存”或“查询时尚未保存”，详情说明后续保存另有记录，不将旧查询结果伪装成当前设置。

## 问题状态与方案复用

独立审读为问题返回具体的 `topic`，例如“铜钥匙使用后的记忆代价”。程序结合文档来源生成初始 ID。长稿复核通过受约束的 `script_finding_groups` 归并共同事项，保留跨文档引文、说明、建议，并将改名后的同一事项关联到已有决定。程序校验每项必须且只能属于一个组，模型不能删除发现、改写证据或编造历史授权 ID。不同事件或同一引文中的不同属性必须分开；未提供 topic 的旧结果仍使用保守身份。

候选稿保存每个事项最近一次方案、处理摘要、修订次数和审读状态。用户的手动答案会带入后续修订和输入框；AI 委托也会保留。修订完成先记为 addressed，独立复核后才标记 verified 或 still_open。处理记录不是正式保存，也不能代替当前正文证据。

同一处理授权最多累计四轮“修订—独立复核”后仍未通过的结果；点击“继续处理”、候选版本变化或传输恢复不重置已完成轮次，传输中断本身不增加轮次。未到上限时继续沿用具体决定；新创作选择不自动扩展授权。达到四轮上限后保留候选稿和方案，要求创作者手动调整处理方案，或重新明确委托 AI 处理，才能开启新的轮次额度。自动继续不追加相同的用户消息。

同一候选稿版本持久保存授权方式、手动答案和修订进度。运行状态不进入精确文本检查点身份，因此中断和进度变化不会让已校验步骤失效。`draft_resolution_progress` 同步进度，重新进入项目也能读取。技术失败或取消后不自动打开决定弹窗；“继续处理”通过 `strategy=continue` 读取服务端原方案，不能无授权启动，也不能沿用其他候选稿或过期来源版本。用户仍可主动查看问题、调整方案或放弃候选稿。

补齐读取完整有效稿和完整候选文档，结合归并问题的原文引文实施修订。修订后携带位置变化，仍使用编号绑定和精确替换。原稿保持不可变，正式文档与有效稿在用户确认保存时更新。

修订结果单独记录每项具体 `decision`，例如首次见父的集数和人物知情状态；历史无该字段时兼容原有步骤摘要。后续修订沿用具体决定，避免只记住“交给 AI”却重新选另一套方案。

## 原文证据与精确修订

全文分析的目录附带人物、事件位置、未完线索与连续剧情信息。程序校验目录覆盖与证据引文，模型不能用摘要代替原文事实，也不能编造引用位置。

生成与补齐均直接携带当前有效稿全文和所需的候选文档，不先让模型选择章节、片段或额外八处段落。共同上下文只保留一份，相关事项合并保留各处证据和已确认决定，避免重复拼接材料。

修订使用受约束的结构化结果和精确替换；引文、编号、修改范围与版本继续由程序检查。虚构位置或不匹配的原文仍拒绝，并保留有界格式修正；不通过忽略校验来继续生成。

原稿未写、且已授权创作的细节不被当成必须找到的原文证据；新的独立创作选择仍需创作者决定或授权。

全文分析、生成和修订结果继续使用版本绑定的检查点，恢复时重新验证位置与任务输入。

## 全文独立复核

独立复核一次接收完整有效稿与本次完整候选文档，检查正文完整性、跨文档人物和设定一致性，以及候选内容是否忠实于源文稿。取消逐段正文审读、原文与候选事实交叉切批及 32,000 字符材料分组。

同一来源只传一份全文，问题归并保留各自证据及不同含义。完整源文稿、候选文档、结构、引文和版本校验继续生效；生成请求成功不等于复核通过。

## 提示词与接口能力

工具提示词分为公共约束、统一修订协议和视觉资源协议。明确的阶段任务携带所需规则；开放对话和相关修订继续加载完整协议。权限和保存检查继续由程序执行。

剧本分析、生成、修订、审读和相关授权判断共用文本传输层的结构化能力识别。未配置模式时优先尝试原生 JSON Schema；明确收到格式不支持错误时回退到提示词 JSON，后端仍检查结构和语义。能力缓存按模型、接口、配置和凭据隔离，仅在当前进程内保存。

显式指定的输出模式保持优先。网络、鉴权、额度和无效 Schema 错误不触发格式降级。格式兼容尝试计入原有模型步骤预算，不变更已配置模型，也不影响原生工具调用协议。

输出预算不按模型名称写死；显式参数按当前模型模板透传，未配置时保留供应商默认行为。技术详情展示实际发送的输出上限与供应商提供的推理 token 用量，帮助区分正文过长、推理消耗与网关默认额度。当前协议及历史外部能力研究见[文本模型输出上限](text-model-output-limits.md)；历史研究未经本次联网复核，不能当成模型配置的默认值。

模型设置可显式配置 `context_window_tokens` 与 `output_reserve_tokens`。传输层在每次发送前估算最终请求，包括全文、历史、工具定义及返回值和结构化格式；输出预算优先采用请求实际输出上限，否则使用显式预留。已配置窗口但缺少输出预算、或合计超限时在网络请求前停止，不截断原稿、不改变输出参数，也不对相同超限配置自动重试。未配置窗口的模型保持容量未知；Unicode 估算不等同于供应商 tokenizer，也不保证请求一定能被供应商接受。技术详情将末次输入估算、容量、输出预留与供应商实际用量分开展示，配置说明见 [文本模型上下文容量](text-model-context-capacity.md)。

## 实现位置与验证边界

上传解析及正文限制位于 `backend/src/modules/script/script-source-documents.ts` 和 `packages/shared/src/script/script-source-document.ts`；分析、检查点和全剧任务位于 `backend/src/modules/script/script-source-analysis.ts`、`script-source-checkpoints.ts`、`script-source-story-parts.ts`。候选修订与独立复核的编排及确认保存接口位于 `backend/src/app.ts`，累计四轮规则位于 `backend/src/modules/script/script-draft-repair-rounds.ts`。

阶段候选、修订后私有分析、来源分析 `ready` 与正式保存是不同状态：私有分析通过后仍要核对阶段设定；阶段复核通过后只产生待确认草稿；创作者明确确认且来源版本仍匹配，才写入正式文档与有效稿。候选修订与复核的累计模型预算见[用量控制](script-analysis-cost-control.md)。

自动化回归使用模拟模型响应，检查全文输入、容量拒绝、分析语义核对、暂停与队列、事项归并与证据保留、历史答案复用、有限自动修正、新问题授权边界、精确位置校验、来源变更保存拦截、检查点恢复及跨任务格式兼容。真实长稿的生成质量、耗时和费用仍需结合实际模型运行评估。
