## 原始外部实测记录

实测地址：成熟项目公开画布页面（具体调研链接不纳入项目文档）

实测工具：Ego Lite（TaskSpace 32），视口 1500 × 845 CSS px。通过画布中剧本节点的“编辑”按钮进入编辑器。

## 页面骨架

编辑页面使用全屏固定容器，顶部工具栏高度 52px，正文区占据剩余高度。主体正文区不是页面整体滚动，而是独立的 `overflow-y-auto` 容器；目录和正文在同一层网格中，目录滚动不会推动正文。

正文区域的网格列定义为：

```css
grid-template-columns: minmax(216px, 1fr) minmax(0, 680px) minmax(24px, 1fr);
```

编辑正文列宽固定上限 680px，视口 1500px 时正文起点 x=410，右侧结束 x=1090。正文容器 y=52，高度 793px，内容列使用：

```css
max-width: 680px;
padding: 60px 0 96px;
display: flex;
flex-direction: column;
gap: 36px;
```

因此正文第一页的主标题“故事大纲”位于 x=410、y=112，字号 20px、行高 30px、字重 600。标题后的正文内容从 y=178 开始。

页面背景为深黑：body 背景 `#141414`，全屏编辑器遮罩为约 `rgba(10,10,10,.95)`。

## 左侧目录

目录是网格第一列中的正常占位元素，不是覆盖正文的 fixed 浮层。其实际容器样式：

```css
z-index: 10;
col-start: 1;
row-start: 1;
width: 168px;
max-height: 80%;
margin-right: 24px;
justify-self: end;
align-self: center;
overflow-y: auto;
padding: 12px 20px;
border-radius: 12px;
backdrop-filter: blur(2px);
background: rgba(255,255,255,.05);
```

在 1500 × 845 视口中，目录卡片位置约为 x=218、y=220、w=168、h=456。它与正文列起点 x=410 之间保留约 24px 的网格空隙。目录纵向居中于正文可视区，即使正文内部滚动，目录仍保持在 y≈220 的位置。

目录卡片内部：

- 一级分类字号 13px，行高约 31.2px（`line-height: 2.4`），分类之间 gap 10px。
- 展开后的子项字号 12px，行高约 22.8px（`line-height: 1.9`）。
- 子项容器左侧有 1px 竖线，`padding-left: 8px`、`margin-left: 4px`。
- 当前选中项颜色 `#5ddcff`；普通子项颜色 `#919191`；未选中的一级分类颜色 `#f7f7f7`。
- 点击目录项会滚动正文独立滚动容器，并切换选中颜色。例如点击“故事简述”后正文容器 `scrollTop` 约为 570。

## 正文排版

正文使用 Tiptap/ProseMirror：页面中存在 `.tiptap.ProseMirror.sp-editor` 的 `contenteditable=true` 元素，DOM 中直接使用 `<h2>`、`<blockquote>`、`<ul>`、`<ol>`、`<strong>`、`<em>` 等语义标签。

核心排版规则：

```css
.sp-editor {
  color: #a8a8a8;
  line-height: 1.8667;
  letter-spacing: .01em;
  word-break: break-word;
}
.sp-editor > * + * { margin-top: .9em; }
.sp-editor p { margin: 0; white-space: pre-wrap; }
.sp-editor strong { color: #f7f7f7; font-weight: 600; }
.sp-editor h2 { font-size: 1.3em; line-height: 1.4; font-weight: 600; margin-top: 1.9em; }
.sp-editor ul, .sp-editor ol { padding-left: 1.4em; margin: 0; }
.sp-editor li:not(:first-of-type) { margin-top: .35em; }
.sp-editor blockquote {
  border-left: 2px solid #525252;
  padding-left: 1em;
  color: #919191;
  margin: 1.4em 0;
}
```

正文基础字号是 15px，系统字体栈为：

```css
-apple-system, system-ui, "PingFang SC", Inter, "Noto Sans SC", "Microsoft YaHei", sans-serif
```

实测正文颜色 `rgb(168,168,168)`，行高约 28px，字距约 0.15px。段落没有额外 margin，块之间统一按 `.9em` 处理。标题颜色为 `#f7f7f7`。

## 顶部工具栏

顶部 header 高度 52px，左右 padding 24px，底部 1px 边框。左侧标题“编辑器 - 直播中”位于 x=24，字号 14px、行高 21.7px、字重 500。

中间工具组使用绝对居中容器，位置约 x=541.5、y=3.5、w=417、h=44，内部 `display:flex; gap:4px`。按钮高度 32px，图标 16px：

| 功能 | x | 宽度 |
| --- | ---: | ---: |
| 撤销 | 541.5 | 32 |
| 重做 | 577.5 | 32 |
| 缩小 | 626.5 | 24 |
| 100% | 654.5 | 54 |
| 放大 | 712.5 | 24 |
| 标题格式 | 753.5 | 40 |
| 列表格式 | 797.5 | 40 |
| 粗体 | 854.5 | 32 |
| 斜体 | 890.5 | 32 |
| 删除线 | 926.5 | 32 |

按钮默认颜色 `#919191`，激活状态为 `bg-btn-ghost-active` 与 `#f7f7f7` 文字色；激活按钮带 `aria-pressed="true"`。悬停背景约为 `rgba(255,255,255,.1)`。

“标题格式”是带 `aria-haspopup="menu"` 的下拉菜单，选项为“标题 1”“标题 2”“标题 3”“正文”。菜单宽 140px，背景 `#242424`，padding 4px，圆角 8px；每个选项宽 130px、高约 33.48px，字号 13px、行高 20.15px、左右 padding 12px。

“列表格式”下拉菜单选项为“无序列表”“有序列表”，宽 140px、高约 76.95px，其他菜单尺寸相同。

实测在编辑区选中文字后点击“斜体”，DOM 会直接变为 `<em>`（与已有 `<strong>` 嵌套时保留两者），点击撤销会恢复原状态；因此它不是在文本中插入星号或其他 Markdown 标记。

## 与本地旧实现的差异

本地编辑器原先使用普通 textarea/文本转换思路，工具栏格式化依赖保存选区后把 Markdown 标记写入字符串，容易出现斜体无效果、失焦后选区丢失、页面直接显示 `*`/`**` 等问题。成熟项目使用 contenteditable + Tiptap 文档模型，按钮调用编辑器 mark/heading/list 命令并通过语义 HTML 渲染。

本地旧布局将目录作为 fixed/覆盖层，正文采用较宽的 920px 居中内容，导致目录可能盖住正文，且正文左右间距和字号明显大于成熟项目。复刻时应改成“第一列目录 + 680px 正文 + 右侧弹性空列”的三列网格，目录卡片占位并垂直居中，正文独立滚动。

本地旧排版的标题字号、段落间距与正文行高偏大；应以 15px 正文、28px 行高、680px 内容宽度、`.9em` 块间距为基准。

## 保存机制边界

本次只从客户端页面和 DOM/CSS 实测编辑器行为，没有对成熟项目的网络接口或服务端状态做写入测试，因此无法仅凭本次检查确认其自动保存触发时机、保存请求格式、版本冲突处理或是否有草稿/发布两阶段。可以确认顶部存在撤销、重做和编辑器内直接修改，但保存机制需要在授权环境中通过网络面板或实际编辑后观察请求才能进一步确认。

## 一级目录章节切换（补充实测）

通过同一页面分别点击左侧一级项“人物小传”“场景设计”“道具设计”验证：这些按钮不是继续滚动“故事大纲”的同一篇长文，而是切换到独立的剧本文档产物。

- 点击“人物小传”后，正文滚动位置重置为 0，编辑区首个标题变为 `人物清单`（`<h1>`），后面是角色标题（如 `林野`、`老周`）和各自的列表内容；左侧“人物小传”变为青色激活项。
- 点击“场景设计”后，首个标题变为 `场景清单`（`<h1>`），随后出现 `白楼正门` 等场景条目；编辑区滚动位置仍为 0，激活项切换为“场景设计”。
- 点击“道具设计”后，首个标题变为 `道具清单`（`<h1>`），随后出现 `直播设备（手机与补光灯）` 等道具条目；编辑区滚动位置仍为 0，激活项切换为“道具设计”。
- 再点回“故事大纲”后，正文恢复以概要设计为起点的长文档，滚动位置重置为 0；其内部的“概要设计 / 故事简述 / 背景设定 / 全剧分段 / …”才是同一大纲文档内的滚动锚点。

所以本地应把一级目录切换实现成“切换当前 artifact 文档并重置正文 scrollTop”，只有故事大纲下面的子项使用同一文档内的 `scrollIntoView` 锚点。三类文档共用同一顶部工具栏、缩放值和 contenteditable/Tiptap 编辑体验；切换文档不会隐藏工具栏，也不会把人物/场景/道具内容拼接到故事大纲后面。

## 缩放与工具栏作用范围（补充实测）

成熟项目 顶部显示一个全局 `100%` 缩放控制（缩小、恢复 100%、放大），位于固定顶部工具栏中央。编辑页切换“故事大纲 / 人物小传 / 场景设计 / 道具设计”时，顶部工具栏保持不变，当前章节仍使用同一编辑器视图和正文列宽；从页面结构看，缩放值属于编辑器容器级状态，而不是某个章节独有的设置。标题、列表、粗体、斜体、删除线同样是当前章节编辑器的通用命令。

本次只做章节切换与 DOM/滚动观察，未点击格式和缩放改变按钮，以避免改动远端内容；之前已在另一轮验证斜体点击会在当前文档生成 `<em>`，撤销可恢复。

### 缩放实测

在“故事大纲”点击一次“放大”后，顶部原先 `100%` 变为 `110%`；正文列宽仍为 680px，但 `.sp-editor` 基础字号从 15px 变为 16.5px、行高从约 28px 变为 30.8005px，正文总高度随之增加。随后点击“人物小传”，人物清单同样保持 110%（字号 16.5px、行高 30.8005px），说明缩放状态属于编辑器全局而非单个章节。最后已点击“恢复 100%”还原远端页面显示。
