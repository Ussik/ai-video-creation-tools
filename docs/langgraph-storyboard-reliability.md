# LangGraph 分镜可靠性

场次分镜现在通过 LangGraph 1.7.4 / Core 1.3.4 执行准备、生成、独立复核、按复核问题修复、复查和完成。图只负责阶段路由，SQLite 原有任务和 `control.steps` 仍是唯一恢复依据；不使用额外 checkpointer，也不增加图重试。

## 生成与恢复

包括短场在内，新的规划均先生成完整大纲，锁定场次调度、镜头身份、台词分配、动作边界、接镜和时长，再逐镜补充画面、视频和摄影。每个单元必须完整通过 Schema 和业务校验才保存；恢复只请求缺失部分，旧两镜检查点通过完整验证后可以转换复用。只有组装后的完整候选能进入独立导演复核和正式保存。

结构定向修复仅在这两个新生成单元中启用。首轮输出可可靠解析、且错误能定位时，程序选择最多八个互不重叠的目标，第二轮只接收固定 `repairs` 字段。合并时逐值保留未报错内容，再执行原始完整 Schema 和业务校验。数组数量及其他无法精确定位的容器错误退回整单元格式修正；非法 JSON 不猜测、不补造内容。

格式修正仍最多一次，单步骤仍最多三次实际尝试。导演复核发现的内容问题继续使用已有按目标镜头修复机制；修复后必须重新复核，未通过的候选不能正式保存。没有自动换模型或修改推理配置。

## 持久预算

`storyboard_task_budget:v1` 随任务保存累计真实请求、保守 token 预留、额度和耗尽原因；既有任务从持久观察账本迁移用量。损坏账本会拒绝恢复，不能清零后重发。浏览器重连、幂等重放和普通故障恢复不增加额度。

初始额度按所选场次和预期镜头数计算。令场次数 `s` 限制在 1–10，每场预期镜头数限制在 2–30（未设时为 8），总镜头数为 `h`：

- 生成请求上限：`12 + 6h + 3s`，包含实际重试与格式修正。
- token 上限：请求上限乘 64,000，包含尚未核实的保守预留，不能据此计算费用。
- 活跃时长上限：`10 + 2h + 2s` 分钟，暂停时间不计入。
- 后台查询另计传输次数，生成和传输合计也有上限；只有明确的远端取消请求可以在本地中止后派发，且仍计入合计上限。

额度耗尽后会保留验证结果并停止。只有创作者显式继续耗尽任务才增加一份额度，最多三份累计额度；跨恢复保留历史用量和活跃时间。取消或结束后禁止旧执行继续派发新请求，旧执行晚返回不得覆盖恢复后的新任务状态。迟到的精确计量仅结算原请求记录及其 Langfuse 子记录；累计预算保留尚未核对的保守预留，避免跨执行改写用量而低估消耗。

## 追踪与验证

继续使用现有 Langfuse 导出，图中只存三个布尔路由状态，创作正文不进入图状态。每次调用使用隔离的回调上下文和本地 tracer，即使外部存在 LangSmith 开关、父 RunTree 或环境回调，也不启用云端追踪。升级固定 SDK 版本时需重新验证这些边界。

自动测试覆盖图分支、恢复、取消、旧检查点复用、字段修复边界、累计预算和严格保存门禁。真实模型结果另见验收记录；自动测试通过不代表上游一定成功。
