# 模型交互机制与本轮增强

更新：2026-10-09。此清单描述当前代码的实现，包含本轮增强；之前的模型输出审计报告描述的是增强前状态。

## 如何区分

- **提示词**：规定专业角色、创作要求、已有事实、风格与判断标准。正文可以是自然语言或 Markdown。
- **结构化输出**：模型返回符合任务契约的数据，例如场次、镜头、选项、评审发现。程序校验字段以及真实 ID、范围、版本等业务条件。
- **Function Calling**：模型按需调用应用提供的函数，读取真实项目资料，或提出文档、视觉设定与分镜操作。函数参数也有结构契约，实际执行由程序完成。
- **程序控制**：保存、版本、阶段、引用、媒体参数、任务状态、布局和渲染的确定性逻辑。普通 API 返回 JSON 不属于模型结构化输出；用户点击按钮直接调用 API，也不等于 Function Calling。

这些机制经常组合。剧本主对话向模型提供函数，但普通解释可以直接返回文本，不要求每轮都调用函数。Skill 当前提供专业规则和参考资料，加载规则会影响提示词，并不自动执行其脚本，也不等同于 Function Calling。

“全能创作／剧本创编／导演执导”的名称和角色重点由 [script-creation-mode.ts](../packages/shared/src/script/script-creation-mode.ts) 统一定义。原生 Function Calling、兼容对话和发送提示词编辑共用完整模式要求。模式调整专业观察重点；工具注册、Skill 按创作环节加载、当前阶段与操作授权继续使用原有逻辑。

### 接口级结构约束如何启用

文本模型设置增加了“结构化输出”和“严格函数参数”。能力由明确配置决定，不根据模型名称推断。

| 设置 | 用法 |
| --- | --- |
| `structured_output_mode: "prompt"` 或未设置 | 默认兼容模式：提示词要求 JSON，解析后执行本地 Schema 和业务校验；不主动添加厂商输出格式字段 |
| `structured_output_mode: "json_object"` | 固定任务发送接口 JSON 模式；仍需本地校验具体形状 |
| `structured_output_mode: "json_schema"` | 固定任务发送该任务的严格 JSON Schema：Responses 使用 `text.format`，Chat Completions 使用 `response_format` |
| `strict_tool_arguments: true` | 原生函数发送严格参数 Schema；未开启时仍在执行前做本地参数校验 |

兼容模式同样使用结构化**结果契约**，但不能宣称服务商已强制约束输出。调用原生函数时会移除冲突的文本输出格式配置，让函数参数协议承担操作表达。

严格 Schema 将可选字段转换为可为空的必填字段；收到结果后恢复原应用的可选字段和默认值，并保留具有实际含义的 `null`。根联合类型通过 `result` 包装，保持定义引用可解析。

固定任务的格式／业务校验不通过时，最多请求一次带诊断的修正。两次均失败返回可诊断的 422 错误；网络错误和取消不触发该修正，也不重复保存或媒体提交。这不代表任何厂商已通过真实能力测试，配置应与其接口文档一致。

### 草稿、评审和交互的实际行为

1. 原生文档生成只要求函数提交，与旧版“只返回 JSON”内容要求分开，避免两套协议相互冲突。
2. 模型没有调用 `ask_creator` 而直接写出问题时，普通回复保持未分类，可进入已有的有界识别路径。不会默认标成 `other` 导致按钮永远不出现。原生、推断和程序分类记录不同来源。
3. 已有文档存在但仍含待定内容时，可以先评审，再定向补齐。报告显示证据、原因和建议；不把待定关键词直接当作质量结论，也不重置创作阶段。
4. 文档修订草稿展示下游文档、源场次、分镜和视觉引用的核对线索，并区分阶段依赖、实际绑定和文字匹配。只保存草稿内的改动，不自动改写其他资料。
5. 视觉设定与分镜草稿复用预览、编辑、确认、放弃流程。手动编辑先同步当前草稿，后续对话和保存使用同步后的版本；来源变化会拒绝过期保存。
6. 视觉设定修订保留原图为候选，已有镜头保留旧绑定快照。新设定版本需重新确认对应图；刷新引用使用独立绑定草稿明确提出。
7. 新分镜确认后追加到当前镜头列表，保留已有镜头；带上真实源场次 ID，重复确认不能再次创建。已有镜头修改保留其素材关联。
8. 文档操作、视觉／分镜操作与讨论／评审模式相互检查作用范围。不能在只修订一份文档的请求中保存或放弃其他视觉草稿。
9. 评审报告、交互来源和实际执行记录随对话保存；后续回答会使旧的待回答交互重新进入上下文识别。报告覆盖的文档版本变化后，其当前健康状态会标为需重新评审。

### 统一补齐待定设定

可以直接说“所有文档中的待定设定由你确定并补齐，统一人物、场景、道具和分集正文”。模型先建立统一修订任务；`scope: all_documents` 由程序取得完整已有文档目录，选定范围使用真实文档 ID。范围随任务保存，后续继续不会重建任务或要求逐批确认授权。

读取结果包含版本和段落 `paragraph_id`，定位绑定精确原文与偏移。修改可整段替换，或在指定段内精确查找。禁止模糊替换。重复文档项自动合并、相同修改去重；按八份一组处理，每份最多四十处修改，整次参数验证通过才写入。后续批次携带任务 ID 和当前草稿版本，累积一份草稿；已修改文档从 `source: draft` 读取，避免覆盖前批结果。

错误返回 `diagnostic`：原因代码、可修复性、失败文档／项目序号、参数路径、实际数量／限制和修复建议。可修复错误促使模型重新读取或修正；相同参数在没有新进展时停止重复执行，同一失败最多三次，提前结束后的程序续处理最多两次。每轮最多十六次模型回复、六十四次函数操作；达到上限保留任务，可继续处理。续处理使用协议中的正常消息，真实函数结果只回传一次，不伪造调用 ID 或创作者授权。

拟定决定留在草稿中，确认保存时才与正文一起采用；放弃草稿不会写入决定。最终核对必须读完有效草稿与全部有效分场，并查看实际受影响镜头／视觉档案等。文字标记只提供线索，完整性与一致性由模型专业评判；报告证据必须来自当前有效正文。作者待定、缺失、矛盾阻止完成，刻意保留的剧情悬念必须说明理由。整组内容、拟定决定、原文版本、项目画风／创作配置／已确认决定或相关对象变化会使对应核对失效。

前端显示范围、已核对数、批次、待处理文档／关联内容、拟定选择与理由、当前正文的前后差异。中断和未核对完成显示“部分完成”，可点“继续统一修订”。手改后先同步再核对。全部通过才启用统一确认保存；原文变化需读完新原文与旧草稿，明确 `rebase: true` 重新整理，不能覆盖新版本。正式写入、决定和评审状态仍在同一事务中提交。

关联镜头／视觉对象的核对是文字与引用信息核对，未授权资源不会自动改写，也不会自动提交付费媒体生成。发现范围外需同步项会显示待处理，处理后可重新核对。语义质量取决于实际模型；程序核验读取、版本、证据及操作结果，不宣称能机械证明所有故事设定无矛盾。

## 保持程序控制的地方

| 功能 | 当前实现与原因 |
| --- | --- |
| 创作顺序与底部操作按钮 | 已保存成果、当前草稿和有效下一步决定；提示词指导模型，函数提出动作，程序核验可执行性。故事方向在讨论中确认，首份正式产物是全剧大纲 |
| 手动预览编辑、确认保存、放弃、阶段按钮 | 明确 UI 操作直接调用对应 API；不需要另一次模型决定是否点击 |
| 场次／镜头引用、候选图采用／归档、实际图像选择 | 明确对象和绑定 API；新增对话函数只提出可审阅的设定和绑定草稿 |
| 图片→视频衔接、已有视频节点连接、自动参考连线、缺图定位 | 画布关系和镜头来源算法；视频使用对应视频提示词与实际参考图，不由普通段落猜测来源 |
| 节点创建、位置避让、尺寸、拖动和点击区别、提示词编辑同步 | 画布状态、布局及组件实现 |
| 图片比例、尺寸、画质、背景、数量、视频时长和生成模式 | 节点设置、模型请求模板和服务端参数校验；不把结构化文本输出当成媒体尺寸保证 |
| Skill 搜索、GitHub 扫描、安装、更新、启停与应用环节 | 目录／仓库 API、文件和配置逻辑；启用表示可用，主技能与明确选择的辅助技能决定实际加载，默认配置支持全局、项目和单次切换 |
| 模型目录、认证、请求模板和能力设置 | 程序配置与实际服务商接口；不凭名称判定能力 |
| 调用明细、用时、任务心跳、超时、取消、失败恢复和下载 | 实际服务端事件与任务记录；不是模型文字描述的状态 |
| 候选比较、接镜审核、首中尾帧查看 | 媒体展示和人工评审；尚无自动像素级视觉评判 |
| 时间线、入出点、音量、转场、制作范围和 MP4 导出 | 时间计算、编辑 API 与渲染程序 |
| Markdown 标题、文档导航、弹窗、下拉框、按钮、水球样式 | 富文本解析、组件与 CSS／图形代码 |

实际图片／视频生成仍通过原有 API 和任务系统提交，尚未开放模型自主提交生图、生视频、付费任务或导出操作的函数。读取参考图的“存在／缺失”不等于让文本模型看过图片；连续性检查仍是文字语义检查。

## 项目画风如何贯穿制作

画风独立于题材保存为 `visual_style`，可包含明确确认的媒介、渲染、线条、配色和排除表现。模型通过读取／更新画风函数同步真实决定；记录其他设定时，不会把旧客户端表单中的画风覆盖进已保存规范。直接在创作设置中更改画风仍是明确 UI 操作。

旧项目如果只在题材或已确认决定中记录过“日漫”，生成上下文会逐字带入这些资料，明确只继承其中的画风要求。模型可读取真实来源后规范化保存，不根据某种题材、参考作品或默认值自动认定为日漫，也不补造尚未确认的绘画细节。

人物、场景、道具提示词整理，信息图生成，分镜规划，画布图片和视频生成及 Skill 提示词整理均继承项目画风。最终提交前统一替换项目画风约束块，包含手改提示词和 `prompt_is_final` 路径，约束同时覆盖手部、材质样本与辅助视图。比例、画质、电影感光影及真实材质描述不会改变视觉媒介；参考图与画风冲突时，明确区分外形连续性和画风要求。

预览与任务请求保存画风快照和版本。预览后画风变化会拒绝旧版本提交；模型请求模板若丢弃完整提示词，会在入队前报错。画布显示继承画风、完整可编辑内容及生成信息；手改内容和画风约束共同进入实际请求。已排队和重试任务保留原请求快照。

已确认信息图与镜头绑定也保存画风版本。项目画风变化后，原图保留为候选，需人工核对或重新生成，再确认使用；冻结的镜头引用另行刷新。手动上传或无记录的参考图显示核对提示。重新确认只记录人工选择，不会重绘图片；目前没有自动的像素级画风判定，也不保证厂商模型一定遵守提示词。

实现：[visual-style.ts](../packages/shared/src/visuals/visual-style.ts)、[project-visual-style.ts](../backend/src/modules/visuals/project-visual-style.ts)、[visual-profiles.ts](../backend/src/modules/visuals/visual-profiles.ts)、[ProjectCanvas.tsx](../web/src/features/canvas/ProjectCanvas.tsx)。

## 验证与使用

本轮回归覆盖接口 Schema、可选值恢复、定义引用、有限修正、普通问题的识别补救、真实项目范围、原文证据、过期版本、视觉／分镜草稿编辑、重复保存、历史报告和交互来源。测试使用临时数据库与模拟提供商，没有调用真实收费模型或修改现有用户项目。

使用方式：在剧本主对话中提出具体要求，例如“读取人物设定，评审林晚是否还缺少职业和动机”“只补齐林晚的待定职业，保留其他人物”“读取雨夜车站这一场，准备分镜草稿”“修改这个镜头的视频动作提示词”。模型需按函数协议读取资料并提交结果，草稿出现后可以编辑，再确认保存。

剧本对话每轮显示任务卡片：实际请求、处理范围、当前步骤与用时、结果状态。完成后区分回复、待回答问题、待确认草稿、已保存、已放弃、评审与中断；回答过的历史问题不会继续显示待回答。任务信息、处理范围与结果随消息保存，恢复历史时仍可查看。

执行步骤默认折叠，按查阅资料、专业规则、模型处理、草稿与操作分组。来源统计只计入真实成功读取的文档、场次、镜头与视觉档案，重复读取同一对象不重复计数；原始预览被截断时仍保留独立来源标识。文档名称可打开查看，Skill 明确标记为规则已加载，不声称模型执行了 Skill 中的每条要求。函数名、参数、公开返回、版本、轮次与时间保留在独立的技术详情中，不展示模型内部推理。

草稿卡片直接打开预览、编辑及确认保存流程。模型步骤超过 45 秒尚未返回时，显示真实等待时间并提供停止入口，不伪造进度百分比。只读或询问操作中断后可沿用原问题、引用资料、文档范围、创作阶段和模式重试；可能写入决定、草稿或正式资料的操作先检查实际状态。恢复时优先查询调用记录中的确切草稿 ID，不能把之前已有的草稿当作本轮成功结果；失败重试的原版本保留在历史对话中，新尝试的失败记录也会保留。

识别来源仍保存在消息元数据中。固定任务的格式修正目前由所在操作的失败诊断反映，旧版阶段生成另有修正过程条目，并非每个固定任务都提供独立的逐次修正 UI。

## 默认主技能与切换

五个环节（剧本创作、视觉设定、图片提示词、分镜规划、视频提示词）各有一个默认主技能。已有启用的推荐技能优先成为初始默认，之后新安装的同类技能只作为备选。无可用外部技能时使用应用基础规则；用户也可明确选择基础规则。单次使用一个主技能和最多五个辅助技能，辅助技能不能取代主流程，项目事实、用户要求和输出契约优先。当前没有自动判断第三方技能语义冲突的能力。

“技能中心 → 默认技能”可保存全局或项目默认。创作表单中的选择仅影响当前操作，明确点击保存默认才影响后续操作；项目覆盖优先于全局默认，可恢复继承。停用或卸载当前默认后，全局选择回退到可用技能；无可用技能时回退到基础规则。项目主技能不可用时会提示并继承全局默认。本次明确选择的技能若失效，提交报错并要求重新选择，不悄悄替换。

剧本主对话先加载其主技能；本轮其他环节的选择与版本被固定，模型不能自行切换。`read_visual_profiles` 和 `get_storyboard_context` 只读取资料，不会附带多个环节的技能正文。需要创作对应资源时通过 `load_creation_skills(stage)` 显式读取已选规则；新资源草稿入口检查相应规则是否已读取。纯绑定、资料浏览、加入画布与节点定位不额外加载规则。图片和视频的直接生成使用最终提示词，不自动启动技能整理。

执行记录显示实际加载的主技能／辅助技能名称、版本和参考文件，表示规则提供给模型，并不保证模型逐条执行。提示词预览后切换技能，最终提交会替换预览中的旧技能前缀，保留任务正文编辑，避免重复加载旧规则。

阶段入口使用明确的 `workflow.operation`：generate首次生成、revise局部修改、supplement补齐栏目、regenerate整阶段重新设计。未保存阶段须依序生成并确认保存；已保存阶段可以从对话下方按钮直接处理。整阶段重新设计读完原文后通过create_document_draft提交全部栏目，源版本与项目范围由程序校验；待确认保存时更新原文档ID，其他阶段及分集保留。已保存分集可选择局部修改或“重新设计第 N 集正文”。重新设计只处理所选集，完整读取原正文及分场，已有场次通过 `source_scene_id` 保留原 ID，可改写、重排和追加，不删除旧场次或改动其他集。原文版本与场次快照保护草稿编辑和确认保存，镜头与素材关联保留；JSON 与原生工具路径统一使用持久化版本草稿。
