# 生成提交去重与任务恢复

普通画布图片、视频节点提交生成前，浏览器保存一份固定的提交记录，包含来源节点、审核后的请求和每个候选的提交标识。服务端将提交标识与任务一起保存。同一次提交遇到重复点击或网络重试时，返回已经创建的任务。

## 使用与恢复

正常生成仍先检查提示词、参考素材和生成参数，再手动启动。页面重新打开时只查询已有任务，将它们关联回来源节点，不自动提交新的生成请求。任务进度与结果沿用现有任务记录和项目刷新流程。

多个候选分别记录接收状态。若只接收了部分候选，继续提交时复用原请求和原标识，仅提交尚未接收的候选。已经失败或完成的任务仍属于原提交，不因恢复查询而重新排队。失败任务的继续查询、恢复下载和重试仍遵循任务记录中已有的规则。

原节点会显示已接收数量，并提供「检查已有任务」「继续原提交」。检查仅查询；继续会沿用原提交的参数和候选数量。若首次请求已明确被参数校验拒绝，界面会保留已接收数量和拒绝原因；此后再次生成属于全新一轮。若曾出现无法确认的响应，仍保留原提交身份，不因后续查询为空或校验失败而默认为从未接收。

若状态一直无法确认，且原模型或参数已不可用，原节点不会直接换标识重新提交。需要更换参数时，可另建或复制生成节点，明确开始独立一轮；这不会取消旧提交，旧任务仍可能稍后出现，请先检查任务记录。

首次生成前需要创建镜头时，镜头创建也使用固定提交标识，避免镜头创建响应丢失后重复创建。任务已入队但画布关联保存失败时，任务仍保留在服务端，原提交记录可用于再次关联。

## 服务端接口

- `POST /api/projects/:id/generate`：可选 `Idempotency-Key` 请求头。同项目、同标识、同规范化请求返回原任务；同标识的不同请求返回 `409`。
- `GET /api/projects/:id/generation-submissions/:key`：只读返回 `{ job }`，未接收时 `job` 为 `null`。
- `POST /api/projects/:id/shots`：可选相同格式的请求头，镜头创建与生成任务使用各自独立的标识空间。
- `GET /api/projects/:id/shot-submissions/:key`：只读返回 `{ shot }`，未接收时 `shot` 为 `null`。

标识允许 8–128 个字母、数字、下划线或连字符。请求指纹使用规范化后的字段，保留参考素材等数组的顺序。提交记录与对应任务或镜头在同一数据库事务中创建，验证期间的并发请求也会在事务内再次检查。标识长期保留；若对应记录被删除，返回冲突提示，避免将曾经接收的提交当成新请求。删除整个项目时一并清理所属记录。

服务启动时自动创建 `resource_submissions` 表；现有任务、镜头和 `jobs` 表字段不改写。旧任务不补造提交标识。

不带标识的旧调用继续按原行为创建记录。标识不以提示词代替：用户明确发起新一轮生成时使用新标识，即使提示词相同也可创建新候选。

## 范围与限制

本轮产品入口为普通画布生成节点；视觉档案设定图、参考图、配音、导出和导演资产任务继续使用各自现有提交流程。

本功能保护本地服务端的任务接收与浏览器关联恢复。它不代表厂商接口支持幂等，也不保证厂商在进程中断、超时或手动重试时只计费一次。已运行图片、视频任务在服务重启后依据编号和结果链接恢复；没有可确认执行结果的任务停止并显示待核对，详见[生成任务重启恢复](generation-restart-recovery.md)。

浏览器恢复依赖当前浏览器保存的提交记录；清除站点数据、切换浏览器后仍可在任务记录查看服务端任务，但不能据此承诺自动恢复原画布关联。验证使用临时数据库与模拟生成，不代表真实厂商费用、质量或时延测试。

提交前必须能写入浏览器存储，并支持 Web Locks 来串行处理同一节点在多个标签页的操作。缺少这些能力时停止新提交并显示原因；仅检查已有任务仍可使用。请通过 localhost 或 HTTPS 使用支持该能力的现代浏览器。
