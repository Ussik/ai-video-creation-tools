# 文本模型能力与请求预算

> 实现核对：2026-11-10。能力数据来自当前渠道目录或用户覆盖；未按模型名称推断。验证使用离线模拟接口，没有调用真实收费生成。

## 配置位置与语义

进入“模型设置 → 编辑提供商 → 自定义设置 → 展开文本模型”。沿用 Harness 表单，基础配置无需编辑 JSON。

“模型与渠道能力”记录服务实际可用的上限和来源，包含容量计算方式、上下文或最大输入、模型最大输出，以及输出是否包含推理。数据保存在 `text_capabilities`，目录发现与手工覆盖分开。目录值绑定有效 API 地址、协议、模型 ID 和获取时间；改变身份后旧发现值不参与请求预算。自定义模板发送另一个 `model` 时，也不能复用旧模型的发现值。手工覆盖由用户管理，刷新目录不会改它。

| 容量规则 | 实际检查 |
| --- | --- |
| 输入与输出共享上下文 | 输入加本次输出额度不得超过窗口，同时检查独立报告的输入、输出上限 |
| 输入与输出独立限制 | 分别检查输入和输出，不把两者相加 |
| 未知 | 只检查已确认的独立限制；不把上下文数值冒充输入额度 |

“本次请求输出额度”决定实际发给接口的参数，与模型能力上限分开：

| 模式 | 行为 |
| --- | --- |
| 自动安排 | 根据任务用途和已知能力计算，并明确发送参数：普通文本/工具等目标 8192，审读目标 32768，生成/修复目标 65536；均受能力和共享窗口可用空间限制 |
| 固定额度 | 精确发送配置值，不因上下文紧张或中间适配器而降低；超出已知能力则提示修改 |
| 沿用上游默认 | 不发送输出参数；实际默认仍未知，不能标成完整容量验证；Messages 不提供此模式 |

自动模式的最低可用额度按用途检查（普通 1024、审读 4096、生成/修复 8192，且不超过目标额度），空间不足时提示核对能力或按完整单元拆分。它不静默删除原稿，也不把几十 token 的剩余空间当成可用长篇生成额度。模型能力未知时，已知业务用途仍能提供明确任务额度，但容量检查仍显示未知或部分检查。

Responses 使用 `max_output_tokens`；Chat Completions 使用所选的 `max_completion_tokens` 或 `max_tokens`；Messages 使用必填 `max_tokens`。同一份请求计划同时用于最终 HTTP 参数、用量预留和诊断。

## 目录能力和保存

获取可用模型只更新编辑草稿；保存才提交整张提供商卡片，取消丢弃草稿。导入、刷新均保留用户额度、自定义模板及能力覆盖。模型独立 API 地址与提供商目录不同，不套用该目录能力。

只有模型 ID 的 OpenAI 目录不会产生能力。OpenRouter 官方渠道提供的窗口与生成限制可记录其共享规则；同形兼容网关缺少明确预算规则时仍为未知。Anthropic `max_input_tokens` 与 `max_tokens` 分别保存，不把最大输入变成共享窗口。当前支持三种文本协议，尚未加入 Gemini 原生协议；Gemini Responses 网关不会因为名称而套用 Google 原生能力。

## 输入计数与诊断

所有普通、流式、结构化、工具、Messages 和后台请求，在最终历史、格式和媒体组装后预检。输入包含原稿、指令、Schema、工具定义及返回值、历史和接续要求。局部历史去重/压缩保留原有读写证据保护；原始创作资料不做静默裁剪。

本地计数使用 Unicode 估算并标明来源；图像保留每张估计额度，媒体 Base64 不作为正文 token。未知视频成本、独立推理成本等不标成完整验证。推理已包含在总输出时不重复加算，缓存命中不代表免除窗口占用。

可选“渠道输入计数”仅支持与当前协议一致的 Responses 或 Messages。接近已知输入边界的 80% 时，调用同一请求地址的 `/responses/input_tokens` 或 `/messages/count_tokens`，使用实际模型、完整输入及相同认证，禁止重定向。它不占用生成次数；失败或端点不支持时明确回退估算，用户取消直接终止。计数本身也不能保证随后生成必然被上游接受。

执行详情记录输入计数来源、容量规则、检查状态、实际输出额度与来源。上游返回的输入/输出/推理用量另行记录；未知值不猜测。后台生成与轮询仍分别记账。

## 旧配置兼容

没有新能力配置时，`context_window_tokens` 继续表示旧共享窗口。没有显式输出模式时，旧 `text_api.max_output_tokens` 有值即固定，无值即上游默认。既有 Gemini 固定 65536、窗口 1000000、高级预留 128000 均保留，不进行后台迁移或改写。

`output_reserve_tokens` 仅在未发送输出额度时用于本地估算，不发送给接口，不代表已知上游默认。有实际输出额度时优先使用它，历史预留不会再叠加或误拦固定额度。只有旧窗口、没有实际输出和预留的旧配置仍提示补充；新能力模式可以仅检查输入并明确标为部分检查。

容量不足不可无条件自动重试。原稿、已完成单元和检查点继续保留；上游真正截断时走已有语义续写与独立复核，确认前不写正式文档。单请求容量与累计用量预算分开。

## 验证与实现

核心契约为 `packages/shared/src/models/text-capabilities.ts`、`text-api-settings.ts`、`text-context-settings.ts`；预算为 `backend/src/infrastructure/providers/text-context.ts`，临界计数为 `text-request-plan.ts`；发送路径为 `providers.ts`、`text-anthropic.ts`、`text-background.ts`。界面为 `HarnessTextModelOptions.tsx`，高级配置保留旧字段的兼容解释。

回归覆盖三种协议最终参数、共享/独立/未知边界、能力范围失效、固定65536、历史预留、Schema和历史媒体、计数失败/取消、后台账本、目录草稿保存取消、真实创作入口的分场接续与确认前无正式写入。真实渠道的硬限制和计数端点可用性仍以该服务返回为准。
