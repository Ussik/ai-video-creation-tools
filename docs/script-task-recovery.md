# 剧本任务的超时、恢复与质量边界

> 实现核对：2026-10-25，当前工作区实现。本页说明当前恢复契约；检查点存在不代表生成完成、质量通过或已经正式保存。

后端持有任务，浏览器订阅 SSE。离开页面、刷新和网络断开只移除订阅；“停止生成”才取消任务。前端每连续 60 秒收不到服务事件会重连同一任务，重连间隔按指数退避并加入抖动，最大约 37.5 秒。后端每 15 秒发送心跳。

## 执行与停止

创作任务和上传剧本分析运行在剧本专用执行作用域内，不按本地总时长、步骤时长、单请求等待时长、累计请求数、token 数或业务修订轮数截停。旧版本的 180 分钟任务上限、步骤 5–30 分钟期限、32 次请求限额及自适应 token 限额不再作用于剧本任务，历史快照和旧环境变量也不会重新启用这些限制。其他图片、视频或通用生成流程保留各自原有策略。

后端仍处理真实断网、供应商超时、鉴权、账户额度及配置错误，保持用户取消和来源版本校验。网络故障仍按传输错误策略重试，429 遵守 Retry-After；工具写入不会因传输失败自动重放。单次结构化返回保留格式纠正与契约验证，纠正失败不会被当作完成；来源分析可从同一步继续恢复格式，不按累计恢复次数停止。同一已保存分析与同一问题重复时停止本次自动循环，保留成果并报告具体原因；继续仍复用兼容的检查点，不以旧轮数拒绝执行。

等待创作者回答或预览确认时，本轮任务正常返回。用量和耗时仅在内部记录，界面显示任务进度和成果，不展示消耗；详情见[用量记录](script-analysis-cost-control.md)。

## 三种操作

- **重新连接**：查看正在运行的同一个任务，不发起新推理。
- **继续未完成步骤**：保留任务和对话 ID，重新检查来源、模型配置、技能、候选与待确认草稿版本。复用仍匹配且重新校验通过的步骤。
- **重试本轮/重新生成**：新一轮请求，兼容的阶段检查点仍可能复用；原回复保留在历史记录。

服务重启会把运行中的创作任务标为中断，之后由创作者明确继续；上传分析队列会保留与当前全文流程兼容的分析检查点并重新排队。已保存文档不盲目重放。任意工具对话不提供自动重放承诺，只有已知可恢复的阶段、补齐或只读讨论任务开放继续入口。

“继续统一修订”是沿用同一待确认草稿的新工具会话。按钮显式传入 `revision_task_id`，服务端先校验项目归属、任务状态及独立操作范围；普通聊天、只读查看或设定回答不因此自动继续修订。有效正文、分场和关联对象的已读版本及范围随草稿保存，读取本身不改变创作草稿版本或更新时间。`manage_revision_task(read).reading_progress` 给出下一未读位置；旧任务没有读取断点时，首次继续需重新取得真实读取凭证。

`read_documents` 按整个 JSON 结果的 48,000 字符预算自动缩页，返回逐文档 `continuations` 和明确的未返回文档列表；调用方逐项继续，不能将请求长度当作已读长度。超大分场使用带版本的 JSON 字符片段，只有全部范围覆盖后才算读完。修改另一份文档不会抹掉未变正文的读取范围；整组决定、内容或已核对分场变化仍会使相关专业核对失效，必须重新核对，读取凭证不等于核对通过。

工具历史改为本地提取有界元数据检查点，保留真实参数、版本、偏移、错误及最新完整调用结果，不再逐段请求模型生成压缩摘要。被省略的原文和参数明确标记，精确证据仍需通过原工具读取。统一修订中的相同失败、重复读取、空回复、反复提前结束或正文循环会触发停滞检测，保留同一草稿并显示具体中断原因；有真实新增读取、有效修订或核对进展时不按总轮数截停。同版本草稿刷新保留该原因，不能只显示笼统的“可继续”。

同一持久任务恢复会读取已保存的 `usage.current`，不导入 `usage.cumulative` 的历史计数，也不因重连、继续或服务重启清空本轮用量；旧快照中的请求及 token 限额不再用于截停。`current` 为本轮完整执行，`cumulative` 只覆盖该阶段分析、修订及复核，不包含所有普通对话和首次生成，两者不能相加。请求预留、实际结算与响应身份引发的 usage 更新同步写入任务快照，不走普通活动的延迟合并保存；上游实际输入、输出用量逐项替换估算，推理已包含在输出中。后台查询、轮询及取消单独计传输，不算新的模型生成请求。

阶段候选稿、补齐结果、全文分析和独立复核保存检查点，复核连接出错时不必重写已完成的候选稿。补齐后的拟有效稿也按全文分析流程处理。缓存匹配包括原文、创作要求、候选状态、模型及处理结构版本；各检查点命名空间分开存储，旧切批流程的中间结果不能冒充新版全文分析完成。

新的候选修补使用固定版本的只读工作区，相关完整文档预载，其余通过批量读取或搜索补充，最后提交精确补丁。工具会话成功提交即结束，不额外请求总结或压缩；重开未完成会话只承认本次真实预载或补读的文档，不继承上次未完成会话的已读资格。无实际正文变化的补丁、重复可纠正失败和未完成提交均返回真实诊断供模型继续；独立复核后，正文与问题一起重复时切换为逐项对照决定和证据；同一策略仍无进展则保留分歧并结束本次自动循环。工具决策、操作数和语义修订轮数没有默认硬上限；同一已读资料上重复相同操作、相同无效补丁或未提交结果时返回 script_draft_repair_stalled 并保留候选。有效读取新文档、改用不同查询或提交有效补丁可以继续，用户取消优先于停滞判断。每轮保留进度，用户可随时停止。版本、已读范围、唯一原文引文及非重叠修改要求继续严格校验，未完成的补丁不能被标为成功。

上传分析的目录输出在正文超过 16,000 字符时分页，目标每页约 8,000 字符的产出范围，优先集、章等语义标题，长连续正文按完整句段边界划分。每页请求仍发送全部原文，模型只返回本页目录和证据；完整合法的页及其证据修复结果持久化，中断只重试未完成页。正文超过 32,000 字符或目录超过 80 段时，全剧整合按概览、人物、时间线、伏笔与不确定事项分任务输出并保存。概览和非人物任务读取全文；后续人物批次满足条件时可使用相关原文证据包，不足时转为该批全文核实，详见[原文资料策略](script-source-context.md)。最后仍需全文覆盖、事实来源及独立质量核对全部通过。

失败与暂停保留具体阶段及上次处理项。恢复说明区分只有原稿、已有目录页、目录已完成、已有部分整合结果、逐项质量修补和只差独立核对；没有合法分析检查点时不会宣称已保存分析成果。当前分析管线版本为 v6；v5 全文流程的有效目录、整合及核对结果重新校验后保留，旧片段摘要流程不直接升级为就绪。普通质量问题不清空完整目录和全剧信息，同次执行内自动逐项修补并保存进度，全部修补后再做全文独立核对；复核连接中断只继续复核。确认修订后旧目录候选的理解失效，或问题涉及章节边界等无法安全局部修补时，按核对证据重建；中途失败保留该轮新进度，后续仍有问题继续修补，需要时可再次重建。质量修补、分析格式恢复及必要重建不按累计次数停止，进度显示轮次和具体原因，并保持可取消。

剧本上传仍最多 100,000 字符（JavaScript UTF-16 长度），现有文档及场次仍遵守数据契约。普通原稿大纲仅生成和核对一份大纲，不等待整套原稿分析。完整设计按真实成果依赖分组执行，补齐仅生成缺项；每项读取完整有效稿及依赖成果，具体见[任务与交付流程](script-agent-workflow.md)。目录分页限制输出范围；上述人物证据包和普通局部查询按各自策略选择输入。所选模型已配置容量且预检不足时明确停止；未配置容量时仍属未知，供应商也可能拒绝请求。若上游明确报告输出额度耗尽，则保留完整合法单元，按完整语义块接续剩余成果，每次继续携带完整有效稿、要求和已有成果。生产接续不传内部可选的轮次或时间上限参数；有实际进展时持续处理，无新单元时先缩小到下一个完整小节。相同已保留内容在同一接续方式下再次无新单元，则返回 stage_continuation_stalled 并保留检查点，避免重复请求。显式继续可沿用全部完整单元重新尝试。用户停止或真实执行错误保留已校验单元，不复用残缺 JSON，也不自动裁掉原文。

阶段独立复核的普通输出超限另行处理：整体请求明确输出截断后自动切换为三个固定核查维度，各维度仍读取全文与全部候选。全部维度的完整结果通过覆盖及证据校验后才合并判定，不把零正文或截断 JSON 当成通过。策略与成功维度持久保存，后续继续只处理未完成部分；单个维度遇到真实输出截断或其他上游错误时返回具体原因，不递归拆分，也不将未完成部分标为通过。

已确认的纯推理耗尽有单独恢复方式：仅对实际请求命中 HTTPS `api.deepseek.com` 官方 Responses / Chat Completions 端点、且远端 ID 为 `deepseek-flash` 或 `deepseek-v4-pro` 的 HTTP 文本模型启用。普通复核沿用模型已配置的推理及输出参数，不另设 `low` 或输出额度。若明确输出超限、零正文，且正整数 `output_tokens` 全部等于 `reasoning_tokens`，先保存该整体或维度步骤的 `answer` 状态，再用同内容将推理切换为 `none`，输出额度仍沿用模型配置。整体答复仍报告输出截断时，转为三个维度恢复；单个维度实际失败时保留未完成状态和已通过维度，后续继续使用已选答复策略。旧版持久化的 `blocked` 仅视为已选择答复策略，继续时会转为 `answer`，不再永久阻断同输入任务。其他模型或缺少用量证据时仍按普通超限处理，取消、鉴权及传输错误不触发策略切换。该策略不写回模型设置，不重放写工具。需要切换模型或调整参数时，从候选稿卡片点击“继续处理”；聊天旧任务的“继续”固定原模型配置，不能用于切换新模型。

核对历史在发送时只省略已核实、有具体决定且不依赖历史引用记录的旧问题及不再被引用的批次摘要，保留全部具体决定、作者答案、未解决记录及完整创作材料。决定或答案含“采用方案二”“同上”“按上述”等引用时保留完整记录及引用摘要；未知格式保守保留。历史数据不改写，完整原始请求仍绑定既有检查点，因此这次发送投影及请求策略本身不会使已通过维度失效。具体条件和参数见[用量控制](script-analysis-cost-control.md)。

复核结果结构、覆盖和来源合格，但个别引文未逐字匹配时，保留审读结论，仅定位相关候选文档中的原文句段，由程序截取连续引文并严格复验，不携全文重新生成整份审读。上述受支持官方端点的定位请求直接使用 `none`，输出额度仍沿用模型配置。真实定位失败或用户取消保留待核实结果；继续只处理剩余引文。同批已核实引文保留，所有问题的说明、建议、顺序与数量不变；无法找到支持原问题的原文时仍不能通过。旧失败任务若没有保存完整对象，首次继续需要一次独立审读，但不重放已完成修补。局部定位本身的输出超限不触发全文分项重审。

## 可选的提供商后台响应

仅在提供商确认支持 OpenAI Responses 后台响应和按 ID 查询时，才在文本模型高级设置中配置 `background_responses: true`。默认关闭，不会更改已有模型设置。

该能力用于后端持久任务内的只读结构化请求，提交 `background: true, stream: false`，立即保存 response ID，随后轮询查询。网络断开或用户继续中断任务时，优先查询已有响应，不重建推理。当前采用查询模式，不依赖供应商的流事件游标兼容性；函数工具回合保持原调用协议。

明确停止会请求提供商取消已接受的响应；服务关闭保留 ID 供恢复。提交结果不明且没有 ID 时停止自动重发；响应过期或不可查询时显示原因，由创作者核对后重新发起。提供商存储窗口不是本地持久化保证。

## 创作质量

超时与恢复不减少原文证据覆盖，不修改不可变上传原稿，不跳过结构、精确定位、跨文档和独立复核。补齐保留完整有效稿与创作约束，候选文档按问题位置完整预载并按需补读；较大多组成果先分组核对，最终整体一致性仍读取完整有效稿、全部候选文档及关联资料。创作补充优先落实到候选文档和具体决定，不默认追加到原稿；只有确需同步的有效稿变化才触发拟修订稿分析，候选文档自身修补不使仍匹配的来源分析失效。恢复后沿用已接受的候选变更。

处理中即可只读查看已保留的候选稿，不需要等待复核通过，也不启动新模型请求。预览接口 `GET /api/projects/:id/script/director/resolutions/:resolutionId?version=...` 严格绑定候选身份与版本；404 或 409 提示刷新候选状态，旧请求返回不能覆盖新版本。预览没有编辑或保存操作。生成检查点、目录完成及修订补丁完成均不等于审核通过；只有全文独立复核通过后才提供可确认保存的草稿，正式文档及有效稿仍在用户确认保存时更新。
