# AI 接入可靠性与结果恢复

首轮增强基于已合并并推送的 main `2c2b700`，原增强分支为 `codex/ai-integration-reliability`。后续在 `codex/langfuse-observability` 接入本机 Langfuse，并引入 LangGraph 编排场次分镜；继续使用现有 Fastify、SQLite 和模型适配器。LangChain Core 仅为图运行依赖，不替换现有模型适配器；未接入 LangSmith。详见 [LangGraph 分镜可靠性](./langgraph-storyboard-reliability.md) 和 [Langfuse 配置](./langfuse-observability.md)。

## 已实现的行为

- 短 JSON 创作请求在执行前保存操作身份，发送响应前保存结果。已保存的最终结果可按原身份读取或重放；尚无最终结果的运行中或中断操作返回原状态，不自动重新生成。主动开始下一次生成使用新身份。浏览器保留未确认身份，同页并发合并，支持 Web Locks 时也协调跨标签页调用。已有画布候选 `Idempotency-Key` 继续由原提交协议管理。
- 覆盖剧本文档与聊天、场次/片段分镜、提示词整理与复核、原稿分析启动、视觉设定、画布分析和方案、连续性与成片复核、媒体及配音提交等当前 JSON AI 入口。入口清单位于 `packages/shared/src/api/ai-operations.ts`；长任务、SSE 和任务控制继续使用各自的领域任务身份。
- 错误保留安全的类别、原因、是否可恢复、结果确定性和恢复动作，区分鉴权、限流、上下文容量、输出截断、拒绝、契约、来源冲突、取消和未知结果。来源冲突、取消及内部校验器错误不会被当作格式错误再调模型修正。
- 原稿分析保存请求准备、实际派发、完整原始结果及 Responses 上游身份。重启时优先找回已完成结果或查询原响应；未知受理的普通请求不会自动重发。完成结果落库失败仍保留派发屏障；取消发生在完整响应之后时，先保留结果。旧版运行/排队记录缺少派发证据时转为待核对失败状态，保留旧成果。
- 分镜和提示词把“执行完成”与“质量通过”分开。复核失败或不能下结论时保留完整候选；可以编辑并只复核。编辑使旧凭证失效，但保留历史问题。分镜正式保存需要服务端签发、与候选、来源和模型配置一致的通过凭证；幂等提交仍可返回已保存结果。
- 分镜修复只替换有当前复核依据的目标镜头，程序复制其他镜头。身份、声音计划和未授权时长保持不变；重估模式下仅明确授权的目标可调整时长。场次分镜的修复和复查携带最新正式分集正文及来源优先级；独立片段使用片段原文、本次要求及适用的项目约束。
- 媒体任务区分本地准备与可能付费派发。派发登记失败会阻止 POST；已经生成的本地文件在最终事务前登记摘要和大小，可在原任务重试时校验后接管。视频必须完整解码且有有效画面和时长；HTML、JSON、音频文件及损坏视频不能作为视频成果交付。
- 失效结果链接可以查询原上游任务刷新一次，不会新建付费任务。TTS 使用持久请求编号，失败信息保留编号；没有可接管本地结果的未知语音请求不会自动重新合成。旧执行者不能覆盖已经取消或变更归属的任务。

## 使用与接口

任务记录中新增“AI 创作处理记录”，可查看已保留的创作内容及质量状态，并请求停止仍在本地运行的处理。场次分镜支持“复查当前草稿”和“仅修复已确认问题”；片段分镜支持复查当前草稿。质量尚未通过时不能正式保存。提示词候选同样可以只复查后应用。

- 请求身份：`x-ai-operation-id`。
- 读取原结果：`GET /api/ai-operations/:operationId`，或项目内同名路由。
- 项目列表：`GET /api/projects/:id/ai-operations`，最近 100 条。
- 本地停止：`POST /api/ai-operations/:operationId/stop`，返回 `remote_cancelled: false`，不表示上游已取消或免计费。
- 只有带机器码 `ai_operation_not_found` 的权威不存在响应，才允许用户下一次明确重试原身份；离线、未知响应和过期执行租约都不会自动重新派发。

## 浏览器请求身份存储（2026-11-14）

公共 JSON AI 请求身份现在优先持久保存于 IndexedDB，只有保存事务完整提交后才发请求；localStorage 配额满时，新增请求可继续使用已提交的身份。没有 IndexedDB API 的浏览器保留旧存储路径；数据库打开或事务失败不会改用内存身份继续发送。

旧版 pending 身份按原 ID、路由及输入指纹迁移，未知结果仍只查询原请求。终态使用同一事务校验原 ID，再将 pending 转为 completed；事务失败保留可查询身份。旧记录损坏、旧新身份冲突或迁移标记缺少数据库副本时停止派发，不删除记录或生成替代 ID。

升级后请刷新所有工作台标签页再重试，不要通过清空网站数据释放空间。正常迁移保留让旧客户端停止发送的兼容标记；localStorage 全满且原键不存在时可能写不入标记，旧版本标签页在后续释放配额后的行为无法完全约束，因此需统一刷新。原稿、未发送草稿、候选与任务不因这次存储修复被清理。

该增强覆盖公共入口清单中的所有功能；已有领域生成提交协议继续由原身份管理。验证与真实故障边界见[请求身份存储修复记录](./ai-operation-storage-repair-2026-11-14.md)。

## 验证边界

上述首轮自动化验证使用临时数据库、模拟网络和本地 FFmpeg，不调用真实付费端点，不修改正式项目数据，不启动或重启用户服务。自动测试验证防重、恢复、质量闸口、媒体完整性和界面行为；不据此宣称真实模型质量、网关稳定性或生成耗时已改善。

场次分镜规划由原领域任务保存候选并支持明确续跑；片段分镜在审查前保存完整候选到原操作记录，恢复后须重新复查。提示词虽保存内部步骤，但尚未提供审查期间进程退出后的候选直接恢复入口。

进程中断后若上游没有可查询身份，记录只能保留为未知并要求核对提供商记录。公共 HTTP 层不会接管领域任务执行，也不会自动从中断处重新生成。媒体本地成果和准备记录由原任务的重试入口接管，不新增启动时自动重排逻辑。当前脚本创作及原稿分析另有持久累计请求、token与活跃执行时长预算；明确续跑可在有限次数内增加受限额度，累计用量不会清零。追踪接入本身不新增这些业务限制。


## 跨模型适配与原稿审核增强（2026-11-14）

目前仍使用 Responses、Chat Completions、Anthropic Messages 三条适配路径；不按模型名称猜测协议或真实能力。以下改动修正已有适配与校验闭环，不替换现有适配器。

- OpenAI 兼容文本与工具流按 SSE 事件边界合并多行 data，保留 CRLF、跨网络块、Unicode、完成事件及原有非 SSE 的逐行 JSON 路径。无效 JSON 事件不能伪装成成功；单独 DONE 不授权执行未完成工具调用。
- 仅声明支持 json_object 的 OpenAI 兼容渠道可使用现有原生模式，完整任务与 Schema 说明仍保留；json_schema 仍优先，Anthropic 不选择 json_object。原生约束降级仍只允许明确的400/422不支持信号，不给鉴权、网络、无效 Schema 或未知派发增加重试。
- 已识别的 length、max_output_tokens、max_tokens、MAX_TOKENS 使用一致的文本输出上限错误类型，供既有保留与分段恢复入口使用；原始 reason 保留供诊断。工具参数截断仍使用不可继续执行的独立错误，未知结束原因不会被归为成功或已知截断。
- 原稿质量修补为人物、时间线、伏笔和未决问题提供显式零基索引，保存仍是原数组。expected/index不匹配时仅给精确匹配位置的数字诊断，不自动重映射。概要单处修改可用冻结完整基线哈希与唯一精确子串的片段替换，整体业务校验和原子保存不变。
- 有创作者反馈时，现有独立审核调用须逐项提交处置、真实原文短引及现文位置，不能只返回空findings就通过。清晰连续阿拉伯编号保真分项，否则保留完整单项；最多32分项，超限在派发前422提示拆批。直出与分页使用同一完成门禁。私有凭证绑定反馈与当前分析，不进入写作资料，也不使反馈成为原文事实。无法核实的意见保留人工状态，错误显示对应序号及有界说明。

以上适配与结构门禁通过离线响应、纯函数和临时数据库集成验证。实际Ego运行中，显式索引修补有一次首答即通过结构和业务校验的样本；这不代表整体语义验收，也不代表跨模型成功率已达到同一水平。其后独立审核仍有结构偏差，累计预算又中止一次已受理流，留下必须核对上游记录的unknown。第一集正式正文及非空分场的端到端保存仍未验收完成。

LangGraph负责已有步骤、检查点和恢复分支的编排；输出是否符合协议、来源事实与精确修改约束，仍需适配器、结构及业务校验、独立语义审核共同验证。

## 累计时长到期的在途收尾（2026-11-14）

累计活跃执行时长到期时，先关闭新请求入口；本次执行已受理的响应最多再收尾5分钟，耗时继续计入原active_ms。没有当前在途请求、只有历史未知账目，或请求已经完全结算时，不因此获得额外等待。新生成、格式纠正、重试与普通传输都不能越过该入口；派发前同步核对截止时间，避免计时器尚未调度时漏发请求。

唯一允许继续的查询是专用后台响应封装对原resp_身份的GET，且每层嵌套账本都须保留同一待核对身份。它仍受总派发次数和原定5分钟截止限制；持续轮询不会延长截止时间，用户取消立即终止本地执行。完整响应仍可先校验并保存，再关闭执行作用域；收尾超时后仍可能产生unknown，必须保留原有恢复屏障。

在途跟踪仅使用内存中的请求对象或响应ID，并为同一响应的并发GET维护在途计数。1000次同ID轮询稳定保留两个跟踪项（生成与原响应），不按轮询次数累积；恢复历史响应只需一个响应跟踪项。跟踪信息不序列化，不改变账务、请求身份或额度，也不新增模型调用。

该修复预防后续时长边界直接截断已受理流，不能替已有的未知请求确认上游结果。本轮真实流程仍待核对上游记录，原稿语义验收、各创作阶段正式确认及第一集正文与非空分场保存尚未全部完成。

## 未知分析请求的明确恢复入口（2026-11-14）

原稿分析遇到“需核对上次请求”时，现在可以打开“处理上次分析请求”窗口。打开仅查询本地阻断项、执行状态、累计额度及已有请求关联，不调用模型。旧记录没有精确关联ID时明确显示未绑定，不能按时间或最后一条attempt猜测请求身份。

正常查询接口为 `GET /api/projects/:id/script/source/analysis/request-recovery`。当提供商无法返回完整原响应时，用户可明确勾选理解重复计费风险，再选择“放弃等待并继续未完成项”。该动作不取消上游旧请求，也不把旧请求改成失败或成功。`POST`要求完整CAS身份、同一客户端决定编号、指定决定与明确风险确认；当前仅支持一个精确阻断项，多条阻断或无可用预算时拒绝。

恢复决定、原记录快照、一次派发许可、新执行身份与必要的有限预算授额在同一事务中保存。原unknown请求及原响应记录保留；累计请求、Token、活跃时间及原预算上限不清零。重复提交沿用同一决定，进程重启不能多授额度或重复消费许可。新请求再次结果未知时，原决定不能再次放行。已有可查询后台响应ID继续只查原ID。

服务端在提交和worker开始/每次派发前验证当前原稿、模型、提供商配置与反馈绑定；变化时拒绝旧许可，保留已完成分析。迟到旧结果只隔离存档，不覆盖当前执行。新的请求持久记录真实local/upstream ID；新表按项目和请求键建立索引。
