# 画布节点上下文与资源续读

## 把节点配置加入导演对话

选中图片或视频生成节点后，点击输入工具栏的「添加到导演对话」。系统与「生成信息」共用生成预览校验，整理当前模型、实际提示词、参数、固定参考素材 ID / 用途和任务状态，再打开导演输入区。此操作只准备文字快照，不发送消息、不创建生成任务，也不读取图片或视频像素。

已有未发送要求会保留。合并后不超过 8000 字符时，快照追加到输入框；超过时，通过现有引用附件加入，可打开阅读。附件沿用最多 4 份、合计 300 KB 的限制，满额时明确提示而不覆盖原稿。快照本身最多 48000 字符、96 KiB，超限会拒绝整次添加，不截断提示词。外部参考视频地址不复制，快照会标记缺失内容；项目内视频保留素材 ID。

预览期间切换项目、画布、节点，或修改模型、提示词、参数和参考，旧结果不会写入新目标。快照采用字段白名单，不包含提供商密钥或模型请求模板。它只是点击时的配置记录；后续配置变化不会改写已加入的内容。

内部能力模块只提供节点状态读取、实际引用读取和预览准备。当前没有向导演模型注册实时画布控制接口或 MCP 工具。

普通图片、视频节点可继续使用[导演节点修改方案](canvas-node-proposals.md)：通过明确操作让文本模型整理差异，确认后新建独立草稿，原节点保留。

## 导演读取大型视觉档案与分镜

`read_visual_profiles` 和 `get_storyboard_context` 对整个 `JSON.stringify(result)` 应用 48000 个 UTF-16 代码单元的上限，包含正文、参考状态、视觉目录和续读元数据。小结果保留原有 `profiles` / `objects` / `visual_profile_catalog` 结构。

调用方应原样使用返回的 `continuation` 参数续读，直到 `complete: true`。不要仅增加 `next_offset`：目录、项目画风和单个超大对象可能各有未完成的部分。已发送的目录和画风不会在后续页重复。

超大对象放在 `fragments` 中，每片包含 `section`、`index`、可用的 `id` / `version`、`offset`、`next_offset`、`total_length` 和 `serialized_fragment`。按同一 `source_version`、section / index 的偏移拼接所有片段，再 `JSON.parse` 还原；片段的 `complete` 仅表示该对象的末尾，不能代表所有区间已读。`project_visual_style: null` 可能表示本页未重复画风或正在分片，应结合片段与续读判断。

游标绑定项目、工具、查询和完整返回源版本。源数据变化会明确拒绝旧游标，必须重新读取，不能混合版本。只有实际完整返回的对象，或同版本所有片段都已返回的对象，才获得本轮修改所需的已读记录。目录中的档案名称与参考状态不替代档案正文读取；原有版本检查、草稿和确认保存流程继续生效。

此上限控制模型接收的响应大小。每次续读仍重建并核对完整匹配快照，尚未缓存数据库读取结果；资源很多时，优先传入具体的 `profile_ids`、`scene_ids` 或 `shot_ids` 缩小范围。
