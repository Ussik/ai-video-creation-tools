# 接续完整单元的字段恢复

日期：2026-11-09。对应用户场景设计“编写空间与动线”失败截图，错误为“接续返回了不符合当前阶段的完整单元”。

## 实际证据与限制

只读核对任务和请求记录，近期重试均为 HTTP 200，输出 1,082 tokens / 1,485 字符，失败点是本地接续契约校验。这一次失败不属于 8K 输出截断；更早的长请求确曾经历约 8K 截断后进入接续。

该目标检查点保留七个完整空间设计单元。旧实现没有保存失败单元的原文，不能还原本次到底错在哪个字段。合成数据可确定性复现同一错误：合法前缀后有完整正文单元漏 `scenes`、返回 `scenes:null` 或多余保存元数据时，直接失败且绕过字段修复。非流式提供商返回终稿时，还可能尚未保留该页合法前缀。

## 修复

在保存合法前缀后隔离整页原始对象和字段诊断，包括未处理的合法后缀。对纯元数据问题发起一次受限补丁，响应只能返回候选标识、ID、标题、补空场次确认和移除保存元数据确认；正文和已有场次从原件还原，禁止改写。该请求只携带待修对象、已收 ID 和目标，避免为字段修正重新发送完整原稿。

缺正文、非空全剧场次、未知创作信息及无效场次语义不属于元数据修正，保留原页并明确停止。修复完成后对整页重新校验 `complete`、外层字段和精确冲突确认；修好字段不能绕过完成判定。失败或取消后显式继续先处理待修页，同次执行相同异常页不反复修复。旧版断点向后兼容，多栏目迁移按原目标保留待修页。

只读实测用户旧检查点通过新 Schema，七个已收单元的哈希保持不变。真实坏单元已不在历史记录中，因此该验证只证明旧断点兼容，不能称为实际坏响应重放或真实模型成功验收。

## 验证

新增模块测试覆盖元数据修正、逐字正文和场次冻结、已收 ID 冲突、补丁顺序及单次请求；接续集成测试覆盖七段历史内容、合法前后缀、失败恢复、无效外层完成、内容过滤、取消、页内 ID 冲突和反复坏页；迁移测试覆盖仅待修页、目标隔离和缺失目标拒绝。

统一回归 13 个文件共 177 项通过，日志 `/private/tmp/stage-block-recovery-final.log`。随后在已有提供商文件增加一项 Responses SSE 集成测试，3/3 通过，证明 HTTP 200 返回坏字段后走真实 provider 解析及补丁请求，不重送原稿；共 178 项不同测试通过。首次发现 4 项恢复测试沿用旧的全检查点 keys 断言，未考虑已有 `progress:source` 展示来源元数据；现只比较业务步骤并额外校验来源身份。另 1 项旧场次测试期望重新生成整页，现改为验证无效场次不能用元数据补丁改写、原页保留。相关断言更新后统一重跑全部通过。

后端 TypeScript、架构检查、UI 组件 guard 及 `git diff --check` 通过。独立复核确认待修页、后缀、完成判定、过滤回退和迁移无阻断问题；另核对了仅待修页无前缀、无效外层标志与缺正文停止三组边界。

未调用真实模型、未修改用户数据或模型设置。最终生成质量和真实渠道响应仍需实际运行观察。
