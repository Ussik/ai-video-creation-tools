# 剧本生成按栏目保留与显示

日期：2026-11-09。

用户要求概要设计完成就先保存，后续栏目继续生成。原有生成检查点已逐项同步落库，但画布只显示确认后的正式资料，导致后续失败时看起来整阶段没有成果。

## 实现

- 项目详情新增独立 `script_generation_progress`。从已保存且通过字段校验的完整栏目读取，忽略未完成语义单元，不修改正式资料与阶段推进判断。
- 画布按故事大纲、人物、场景、道具各阶段连续展示全部已有栏目的正文，已完成候选显示“已保存草稿 · 待确认”。不再显示栏目选择按钮；重新设计时正式原文仍可查看、编辑。
- 栏目完成的持久执行事件触发去重、串行合并的项目刷新。整组完成或转入审读问题处理时，再刷新对应待确认稿，避免检查点交接后内容消失。
- 待确认创建草稿、审读候选稿分别成为检查点之后的读取来源。原稿版本变化会隐藏不再适用的展示，但不删除恢复内容。
- 非持久 JSON 草稿随完成结果携带原检查点版本，预览编辑和页面重载保留该版本。放弃只隐藏原版本；较新任务版本返回 409，保留新稿。普通确认后不再显示旧候选。

## 验证

- Backend `script-generation-progress.test.ts` 与 `script-work-contract-integration.test.ts`：23 项通过，使用临时 SQLite 和模拟模型响应。覆盖概要完成而后续阻塞/失败、读取恢复、正式资料不变、候选稿交接、确认与放弃、精确版本隔离、原稿变化以及 JSON/SSE 版本传递。
- Web `canvas-script-documents.test.tsx` 与 `canvas-shot-management-integration.test.tsx`：15 项通过，包含实际画布接线；覆盖全部阶段栏目、按顺序连续展示正文、正式原文与替代草稿并存和旧版正文。
- Web `director-initial-context.test.tsx`：16 项整文件通过，后追加的 resolution-only 完成刷新用例单独通过，共 17 项不同用例。覆盖完成即刷新、重放去重、合并并发刷新、原版本随流式结果持久化、恢复已编辑预览后放弃。
- Shared 构建、Backend TypeScript、Web 构建、架构与 UI 规范检查、`git diff --check` 通过。Web 构建仍提示现有大体积 bundle 警告。
- 独立复核推动修正了非持久 JSON 确认/放弃和审读候选交接边界，最终未发现阻断问题。独立复跑不重复累计用例。
