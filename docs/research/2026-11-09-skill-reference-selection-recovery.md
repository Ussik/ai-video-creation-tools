# 补充资料选择未收口的恢复

日期：2026-11-09。对应场景设计任务在正文创作前提示“模型未完成有效的补充资料选择”的截图；同张截图要求增加说明文字与继续按钮的间距。

## 只读证据

本地连续两次任务均在补充资料选择阶段失败。较新一次共请求六轮，累计约 101 万 input tokens、2,000 output tokens，用时约 27.7 秒。旧记录没有保存该环节的工具调用原文或精确失败类型，因此不能断言实际返回了哪种错误字段或哪种响应格式。

源码有两个可复现缺口：只认工具提交而完全忽略 `turn.text`，模型即使直接返回合法选择 JSON 也会重复六轮后失败；合法的资料读取与唯一提交在同一轮出现时，也会因“提交必须单独调用”被无条件拒绝。连续无有效调用或重复读取时没有进展判断，最终只给泛化的“请重试”。

## 修复边界

合法的完整 JSON 对象（或单一 JSON 代码块）与工具提交使用同一选择校验，第一轮即可结束。仍须精确目录 ID、去重、理由及总字符预算验证；不能将失败解析成默认空选。多调用一轮中，只有全部读取合法且唯一提交通过验证后才接受选择。

连续两轮没有新增资料或合法选择即停止，读取总轮数仍有上限，并在最后一轮明确要求提交结果。字段纠正提示携带具体字段路径，最终失败保存安全的错误码、轮数、响应类型、已知工具名和字段诊断，不保存或回显提供商正文、密钥或文件系统错误。资料版本冲突和取消保持直接传播。

界面仅为说明文字与“继续未完成步骤”增加 8px 间距。

## 验证

补充资料选择 47/47 项通过，相关六个技能文件共 99/99 项通过，日志 `/tmp/studio-skill-reference-recovery-tests.tap`。覆盖 Responses 与 Chat Completions 的首轮 JSON、格式纠正、无进展停止、同轮读取与提交、重复/越界/预算验证、调用顺序、读取上限、资料版本冲突与取消。错误字段诊断最多保留十二条。

独立复核无阻断项。后端 TypeScript、架构检查、UI guard 和 diff 检查通过。间距修改的两个现有 Web 组件测试文件共 12/12 项通过。持久任务链路在 `executePreparedDirector` 原样传播错误，`director-tasks.ts` 将错误码和诊断随失败事件保存；旧无持久化 SSE 路径只发送可读错误消息。

测试均模拟请求，不调用真实模型、不更改用户数据或模型设置；真实模型本轮是否成功仍需实际执行观察。
