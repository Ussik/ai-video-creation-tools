# 分镜可靠性与延迟优化：调研和验收要求

用户要求：同时优化分镜长等待、反复失败、失败后重做、错误信息失真，以及参考图准备和加入画布遗漏。保留创作者的模型选择、来源/台词/时长约束和必要导演复核，不修改已有正式项目资料。

## 调研证据（2026-11-13）

- [Claude：降低延迟](https://platform.claude.com/docs/en/test-and-evaluate/strengthen-guardrails/reduce-latency)：分别测量首个结果时间和最终完成时间，压缩输入/输出，提供及时反馈。此次不通过擅自换模型或降低模型设置来提速。
- [Claude：Streaming Messages / Error recovery](https://platform.claude.com/docs/en/build-with-claude/streaming)：HTTP 成功后流内仍会返回错误；应保存已经收到的内容。thinking/tool 内容不能作为可恢复的文本成果。结构化分镜仅在完整解析和语义校验后保存为可用阶段。
- [Microsoft：Asynchronous Request-Reply](https://learn.microsoft.com/en-us/azure/architecture/patterns/async-request-reply)：快速接受长任务、独立查询状态、明确取消、使用幂等键防止启动响应丢失后重复执行。
- [AWS：Timeouts, retries, and backoff with jitter](https://aws.amazon.com/builders-library/timeouts-retries-and-backoff-with-jitter/)：重试集中在一层、有限次数、带退避和抖动；不能自动重放带副作用操作。

## 当前证据

旧版规划主链只有一次生成，当前是生成→导演复核，必要时全量修订→再次复核；最终完成才缓存预览。复核断流会丢失内存中的有效候选。Messages 的 stream_read_error 未列入暂态错误，上游消息丢失，通用“已完成结果保留”并不保证当前草稿已经保存。

独立规划刻意只保存方案，但已有画布的若干加入/导入入口不按参考设定创建节点。参考准备允许空结果或全部 none 且没有充分性说明，遗漏也可能成为有效准备缓存。

## 验收要求

1. 同一输入重复启动只运行一个任务；页面断连不取消后台工作；显式取消不再派发后续阶段。
2. 每个已验证阶段立即持久化；生成后的复核失败只续复核，修订后的复核失败只续复核；重启和取消仍保留已验证草稿。
3. 输入、模型配置、来源、技能或目标模型变化时拒绝错误复用；新任务断点不被剧本任务清理误删。
4. 页面展示真实阶段、阶段/累计耗时、已保存草稿和可继续状态；未完成复核的草稿不能伪装为可提交结果。
5. 暂态读取错误只对只读生成有限重试；保留脱敏错误/请求标识/部分可见文本，绝不执行不完整工具调用或接受半截 JSON。
6. 减少不必要的串行准备和重复复核上下文，先展示已验证候选；质量契约保持。
7. 所有制作入口为所选方案创建/复用参考图节点和镜头节点，目标画布准确、重复导入幂等，保留历史参考快照。
8. 参考准备输出明确覆盖实际出镜对象，合理无依赖必须有结构化说明；空/全 none 不得未经说明就清空有效绑定并写成功缓存。
9. 回归覆盖临时断流、复核失败、重启、取消、设置变化、合理空镜、遗漏对象、已有/新建/历史画布和重复导入；测试使用隔离数据库，不写用户正式项目。

## 已实施方案

- 以私有任务断点保存技能准备、合格候选、复核、修订候选和再次复核；明确查询、恢复与取消。成功任务清理中间大文本，仅保留最终结果及请求身份。浏览器只观察任务，启动响应丢失仍复用同一请求身份。
- 生成、片段分镜和导演复核的暂态读取失败使用既有统一预算内的一次重试；原生 Messages 的流内错误保留脱敏信息及明确标记不完整的可见文本。工具执行不会重放。
- 独立技能准备并行；复核保留一份完整编译文本和必要导演元信息，去掉重复的完整提示词。保留必要复核及一次语义修订上限，没有擅自改模型或推理配置。
- 页面显示真实阶段和耗时；候选只读暂存，复核完成后才可正式保存。恢复时先查询准确的任务/请求身份，再考虑旧预览；未确认取消不会宣称后台已停止。
- 已有、目标及历史画布的剧本分镜导入统一消费完整制作结果，恢复原有任务/素材后补齐参考节点。片段继续使用独立制作路径。
- 自动参考整理新增逐镜对象、用途和来源说明，写绑定及成功缓存前校验；旧准备缓存版本失效。无依赖镜头必须说明理由，手工档案 API 保持兼容。

## 隔离浏览器检查与边界

使用临时前端 fixture 操作真实 StoryboardPlanner 组件，API 由内存响应替代，没有连接用户项目数据库或真实模型。观察到复核错误后候选仍在、字段锁定、保存不可用；关闭后重开查询原任务，续跑调用 `/resume`。该流程仅一次 `/tasks` 启动、一次 `/resume`，没有正式保存请求。

浏览器检查还发现重开时旧 context 抢先恢复任务、使新 context 响应被丢弃的问题。现已加当前打开周期的资料就绪保护，并以延迟 context 的组件回归验证：新资料返回前不查询任务，返回后恢复镜头预览。浏览器截图来自修复前的诊断，不作为修复后完整视觉验收。临时 fixture、服务及浏览器空间均已关闭。

当前运行的本地后端只读 context 接口已确认 `planning_task_version=1`。没有执行真实计费生成，也没有修改用户正式项目资料；真实模型成功率、参考判断质量和端到端耗时仍需实测，不能据此承诺固定加速倍数。
