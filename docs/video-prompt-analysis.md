# 视频反推提示词（豆包）

核对日期：2026-10-28。首版通过豆包视频理解接口分析真实视频，整理整体画风与逐镜头生成提示词。反推是对可见画面的描述，不承诺恢复原作者的原始提示词或复现同一视频。

## 配置

在“模型设置”中编辑支持视频理解的豆包**文本模型**：

1. 提供商使用 HTTP，模型协议使用 Chat Completions 或 Responses。
2. 开启“支持视频理解”，将“视频输入格式”设为“豆包视频理解 · Chat / Responses”。
3. 使用服务商实际支持的模型 ID、地址、认证和上下文容量；若通过中转服务，需确认该服务支持相应视频字段和请求体大小。

对应模型设置字段如下，合并到原有设置中即可：

```json
{
  "supports_video": true,
  "video_input_format": "doubao_ark"
}
```

仅模型名称含“豆包”、开启图片理解或选用视频生成模型，都不会自动获得视频理解能力。功能不会自动修改已有模型配置。

## 使用

1. 在项目画布工具栏添加“视频反推提示词”节点，上传 MP4/MOV；也可右键已有视频节点，选择“反推视频提示词”。从节点连接时固定当前视频版本。
2. 选择豆包视频理解模型，设置起止时间和可选的反推要求。上传文件不超过 300 MB，单次选择 1–180 秒，支持完整分析 90 秒视频；更长视频分段处理。
   没有可用模型时，可点击“去模型设置”完成配置，当前来源和输入草稿随画布保留。
3. 默认每秒采样 2 帧，可在 0.2–5 帧之间调整。更密的采样可能增加模型用量，快速动作和精确切镜点仍需播放核对。
4. 点击“开始反推”。结果包含整体画风、镜头时间、起止状态、主次动作、摄影机运动、特效与环境反馈、首帧提示词、视频提示词及待确认内容。
5. 选择镜头，编辑画风和两类提示词，复制当前或全部结果；也可“创建当前镜头视频节点”。只复制当前镜头及整体画风，原视频和其他镜头不会隐式加入新生成节点。该步骤创建草稿，不提交视频生成。

结果和人工编辑随画布保存。更换来源后保留旧结果并提示重新反推；分析期间切换画布、删除节点或主动取消会中止请求。来源、配置或人工内容已变化时，迟到结果不会覆盖当前内容。

## 输入与边界

后端从当前项目本地素材读取所选片段，经 FFmpeg 限定分辨率、体积并去除音轨后，以 Base64 视频送入模型。不会把文件名、已有生成提示词或素材元数据当作画面证据。

- Chat Completions 使用 `video_url`，Responses 使用 `input_video`，均显式传入 `fps`。
- 本次只分析画面，不做语音转写、逐字对白识别或口型同步检查。
- 输出最多 40 个镜头；镜头密集、遮挡和采样遗漏会降低时间与动作判断的精度。
- 片中镜头时长用于理解与剪辑。新建视频生成节点会按所选生成模型的允许时长调整，仍需用户检查后提交。
- 模型调用会使用所配置服务的额度。配置与接口测试使用模拟上游和临时媒体，未用真实付费模型验收。
- 上下文预检目前按每采样帧 2,048 tokens 保守估算，并非厂商计费公式。较小上下文配置可能拦截长片；遇到容量提示时缩小范围或降低采样帧数，不应把模型容量虚填更大。
