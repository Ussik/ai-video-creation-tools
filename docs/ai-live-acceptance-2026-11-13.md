## 验收发现与改动

1. **媒体调用次数漏计。** 辅助媒体传输有 attempts，但未进入文本 token 预留账本，UI 显示已派发 0 次。现在在本地观察层按实际 dispatch 计入生成或传输次数及已知 bytes，以 request ID 去重；不伪造媒体 tokens、pending 文本请求或估算费用。修复后真实语音正确记录 1 次、171 bytes。
2. **成功语音被追踪为未知失败。** TTS 解析到厂商成功终态后会主动取消剩余流，通用传输原来仅知 accepted。现在由协议适配器在终态及非空音频均验证后确认 completed，再清理尾流。普通取消、断流和已结算结果仍保持原语义。
3. **后台分镜用量重复归入 HTTP 接纳请求。** 模型回调已与浏览器请求分离，但文本用量 ALS 链仍继承 HTTP 账本。真实任务的 4 次生成被同时记到接纳/恢复请求，形成无 attempts 的重复统计。现在仅在持久分镜任务启动时隔离继承账本，普通嵌套阶段仍累计到执行预算；不会新增或重发模型请求。
4. **原生 Schema 格式修正缺少正文 Schema。** 上游 HTTP 200 并未保证符合 `output_config.format.schema`。保持首轮去重，若本地校验失败，则原有唯一一次格式修正保留完整文字 Schema 和具体诊断，接口原生 Schema 也保留。未增加格式修正预算、切换模型、填造字段或放宽校验。真实恢复仍出现 JSON 语法错误，效果不能宣称已经解决。

历史已完成记录中的旧零计数、重复用量及旧 TTS 追踪不自动迁移或改写；新请求应用修复。临时报告保留修复前后证据。
