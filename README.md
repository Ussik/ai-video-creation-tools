# AI 视频工作台

这是一个本地运行的 AI 视频工具。前端和后端都使用 TypeScript：React/Vite、Mantine 和 React Flow 负责创作界面，Node/Fastify 管理模型调用、项目数据与任务，SQLite 持久化，打包的 FFmpeg 负责 MP4 导出。模型调用是 HTTP 接口配置，不依赖 Python。

## 运行

需要 Node.js 22 或更新版本。分别打开两个终端：

```bash
cd backend
npm install
npm run dev
```

```bash
cd web
npm install
npm run dev
```

打开 [http://127.0.0.1:5173/](http://127.0.0.1:5173/)。后端默认监听 `127.0.0.1:8000`，前端开发服务器会代理 `/api`。生产构建可分别执行 `npm run build`，然后在 `backend` 执行 `npm start`；后端会托管已构建的前端。

项目、配置、任务和素材保存在根目录 `data/`。可用 `VIDEO_STUDIO_DATA_DIR` 指定其他目录。API Key 使用本机 `data/secret.key` 加密后保存到 SQLite；请一起备份数据库、素材和密钥文件。服务只监听本机，没有账号权限系统，不适合直接暴露到公网。

## 创作工作流

1. 创建项目，填写创作概述并设置横屏或竖屏。创建或打开项目后进入项目画布。
2. 在“模型设置”中手动添加提供商，配置 API Key 和模型。全新安装没有预置提供商或模型。
3. 在“剧本”中编辑大纲、人物与分场；可选用已配置的文本模型生成草案，检查并修改后再保存。点击“加入画布”进入统一分镜工作台，在左侧选择场次，再配置参考文档、文本模型和本次分镜技能；点击“开始规划”才请求模型。每批最多规划 10 场，左侧明确展示已选范围。每场建议镜头数默认留空，由模型按各场剧情与时长分别确定；也可填写 2 至 8 作为建议。可沿用场次时长或指定本次总时长，按对白、动作和情绪节奏拆分镜头。检查并编辑镜头时长、图片提示词、视频提示词与接镜要求后，点击“确认加入画布”保存方案并加入画布。已有正式分镜可直接预览复用；混合选择只规划缺失场次。重新规划复用已有镜头 ID，保留素材、参考关联与时间轴取段，按需新增镜头；叙事变化后需核对已有素材是否仍适用。
4. 在“项目画布”导入现有分镜，或添加文本、生成节点和素材节点。连线把文本与参考素材送入生成节点；选择目标镜头和已启用模型后，可生成文本、图片或视频候选。提示词编辑区显示完整实际提示词；生成按钮直接提交，旁边的信息按钮可查看参数、参考素材和已配置的费用。选中分镜图片后可选择“首帧生成”或“多图参考”，分别创建同一镜头的严格首帧视频节点或参考视频节点；同一图片、同一模式重复点击会定位已有节点。多图中的分镜图默认仅参考整体构图，不指定动作起点，可移除；开场、过程和收镜由视频提示词设计。参考模式按镜头已保存的视频出镜范围带入人物、场景与道具。已有明确选择的生成模式会保留，在视频节点底部的模式菜单统一选择“首帧承接”“首尾帧”或“多图参考”，菜单提供各模式的参考用途说明，生成中禁止切换。参考图清单支持预览、定位、排除或恢复可选设定图，以及逐图设置身份、服装、空间、结构、细节、尺度、动作、整体构图、开场、过程或结尾用途。用途随当前视频节点保存，不改素材档案；严格首帧和尾帧角色不可改为多图用途。必需引用需在“镜头引用”中调整；图片编号、完整提示词、技能整理上下文、生成预览和实际请求保持同步。源图重生成不替换固定参考，换图需明确移除参考并重新连接。故事板图片阅读器也提供这些入口，视频节点与结果可在故事板的视频列表查看。视频支持文生、首帧、首尾帧、参考、编辑、延长等模式，具体能力由所配置的模型 API 决定。画布自动保存节点、提示词、位置和连接；生成历史仍由项目任务记录保存。
5. 在画布中查看候选、记录审核意见并选入镜头。需要查看视频首、中、尾帧及并排比较候选时，进入“成片工作台”。拒绝已入片素材会将其移出时间线。“素材库”可导入图片、视频或音频，音频可设为全片配乐。
6. 在“成片工作台”选择入片素材、调整镜头顺序，在右侧“片段设置”调整素材入点、出点、原声音量和首尾淡变，并设置全片输出画幅。中间可对照上一镜实际尾帧与当前镜首帧，查看画布中记录的接镜状态。提示词、分镜规划和重新生成统一在画布完成；点击“在画布调整此镜头”会查找并定位对应画布节点，尚未加入任何画布的镜头会只补入当前镜头。候选审核、并排比较和接镜审核继续保留。
7. 在“制作范围”中选择本次要完成的连续镜头。完整剧本和范围外分镜会保留；连续预览、时长统计和导出只检查范围内的镜头。用“接镜审核”并排核对每处实际尾帧与首帧，保存“通过／需修改”和备注；换片或改切点后旧结论会提示重审。按实际入片区间审看整片，必要时重选素材、调整切点或重拍镜头。范围内镜头都选定有效片段后，导出裁剪后的 MP4。

剧本创作对话使用原生 Function Calling，向模型提供 11 项函数：读取创作进度、搜索项目资料、分段阅读文档原文、记录已确认设定、询问创作者、提出下一步创作、创建草稿、提出局部修改、查找关联内容、管理草稿和确认保存。创作顺序为故事方向 → 全剧大纲 → 人物与关系 → 场景 → 道具 → 分集正文 → 分镜。首次对话自然确认故事方向；信息充分时，模型通过 `propose_next_step` 提出大纲生成入口，后端核验阶段和引用依据。普通讨论和设定回答不会自动生成文档。

对话底部只展示当前有效的下一步操作，不重复显示历史消息中的生成按钮。生成入口与手动选择阶段都使用同一工具对话，草稿确认保存后才推进进度；已有文档继续复用，支持定向修订及创作者明确指定的阶段跳转。设定或文档变化后，过期操作会被拒绝并刷新，不自动重试。第 1 集正文与场次保存后即可制作该集分镜，同时继续编写后续集数。已启用的剧本 Skill 规则继续加载。

每条新回复的“执行过程”显示本轮加载的 Skill 名称、版本与参考文件，以及每次函数调用的状态、用时、参数和返回结果。处理时实时展开，完成后可点击查看；重复调用、失败与停止记录会随历史对话保存。Skill 的“规则已加载”表示规则和资料已提供给模型；函数调用表示程序实际执行了对应操作。长参数和结果显示前 4000 字并注明截断，不影响模型收到的完整工具结果。旧对话无法补回此前未记录的调用信息。

对话流收到完成事件即结束等待，不依赖连接关闭。后端每 15 秒发送连接心跳；页面连续 3 分钟未收到服务数据时提示连接中断。单次文本模型请求最多等待 20 分钟，整轮对话（包括多次函数调用）最多等待 30 分钟；超时会恢复发送入口、保留已收到的回复，并尝试恢复数据库中已有草稿的实际状态，不自动重新提交生成或保存。

打开对话中的“项目文档”，阅读已保存文档后选择“模型评审”或“对话修订”；也可以直接说“读取人物设定，补齐林晚的待定职业，保留其他角色”。修改先进入草稿，可查看原文、编辑、继续对话修改或放弃，确认后才写入正文。草稿和已确认决定保存在项目数据库；“跳过”授权模型决定对应设定，集数与单集时长等明确配置会同步更新。保存检查草稿和原文版本，分集修订同步相关场次并保留场次与分镜关联；已经生成的分镜与媒体不会自动重做。

工具对话要求文本接口实际支持 Chat Completions 的 `tool_calls` 或 Responses 的 `function_call`。请求模板需包含对应 `messages` 或 `input`，程序保留已配置的模型、地址、认证与其他请求选项。接口不支持工具时会报告错误；主剧本对话和分阶段生成使用工具链路，采纳旧回复、完整剧本专用生成及视觉创作等专门入口保留各自生成链路。

画布连线表示生成输入及素材来源，不决定成片顺序；分镜顺序、入片区间和最终导出仍以“成片工作台”的时间线为准。切换到其他页面再返回时，已保存的画布会恢复。

画布支持按住 Shift 从空白处拖动框选，或按住 ⌘ / Ctrl 点击多个节点。多选后可通过操作条、所选节点的右键菜单或 Delete / Backspace 一次移除；画布内 ⌘ / Ctrl + A 全选节点，编辑文字时仍由输入框处理全选。画布工具的“更多”菜单和空白处右键菜单提供“全选节点”和“清空画布”，删除与清空均只需一次确认，保留原始分镜、素材与任务记录，并支持 ⌘ / Ctrl + Z 撤销、⌘ / Ctrl + Shift + Z 重做。主动移除后不会自动重新导入分镜，可按需手动补回节点。

单张画布超过 32 个节点、超过 48 条连线（含自动参考连线），或包含至少 8 个图片/视频/生成节点时按可视区域渲染。缩小仍显示真实文字、图片和视频封面，45% 以下使用更小的缓存预览。单选节点的关联连线显示高亮和沿方向移动的轻量光点，同屏最多 24 个，密集连线分组轮换；多选、全选、离屏或后台时停止动画。单选时恢复原图、视频播放器或文本编辑器；视频离屏、切后台或取消选中时暂停。屏幕外节点仍参与搜索、全选、保存与撤销。单图容量仍为 500 节点、1000 连线，更多内容可分到多张画布。实现与验证见 [多节点画布性能](docs/canvas-performance.md)。

剧本对话、剧本编辑器和故事板统一使用“加入画布”入口。打开后先读取场次与分镜资料；未规划场次必须显式开始规划，预览并确认后才保存、加入。已有分镜可复用，不重复请求模型。旧的按场次初始镜头不会当作已规划分镜，不能绕过规划直接导入。已有视觉设定和镜头引用随分镜加入；不会自动整理设定。画布左侧“设定”列表点击条目可在右侧编辑，列表上方加号用于新增设定；条目旁的加号才会添加节点。“设定工具”菜单保留用户手动触发的批量整理草稿和场次 / 镜头引用管理。镜头节点的“镜头引用”直接打开对应的引用面板，可查看、移除必需引用和更新镜头设定版本。删除画布节点后仍可重新加入：工作台优先选中缺少节点的已规划场次，也可用“已规划”“待规划”“清空选择”切换批次。已规划场次直接复用原分镜，补回缺失的图片节点及仍可用的已选图片。重复加入会复用已有节点，保留节点内容与位置；明确保存并加入画布的新分镜方案会同步对应图片和视频节点的提示词与时长。

任务保存在 SQLite。异步视频提交后会保存外部任务 ID，重启后继续查询，成功时立即下载到本地。失败任务可在任务记录中重试。不要在真实任务运行中修改其厂商或模型配置。

队列默认同时执行 3 条任务，可在“任务记录 → 并行设置”调整为 1–10 条；设置保存在本地数据库，应用于所有项目的生成、配音和导出队列。每条任务完成或失败后立即补入下一条，降低上限不打断已运行任务。成片导出始终最多执行 1 条，等待导出的任务不会阻塞后面的生成任务。并行数应结合提供商的并发额度调整；失败不会自动重复提交付费生成。

## 配置厂商与模型

标准音色配音的配置、试听和候选选择见 [TTS 配音流程](docs/tts-standard-voice-workflow.md)。

添加提供商时填写名称、API 地址和 API Key；连接页可以修改 API 地址、替换或清除密钥，以及启停提供商。地址和密钥在输入框失焦或按回车后自动保存，点击“同步模型”也会先保存未提交的修改；保存失败时保留输入并在字段旁提示错误。API 地址仅填写域名时会自动补 `/v1`，已经包含 `/v1`、`/api/v3` 等路径时保留原路径。全新数据库的提供商与模型列表为空，按需手动添加；新增 DeepSeek、OpenAI、火山方舟或其他服务时，不需要修改后端代码。停用提供商后，其模型不会进入生成列表。API Key 不会在读取配置的响应中返回。

添加提供商后，可在模型设置页点击“同步模型”，从该提供商的模型列表接口预览模型目录。默认请求 `{Base URL}/models`，读取 `data` 数组中的 `id`；非标准目录可通过提供商 API 的 `model_catalog` 字段配置路径和字段映射。目录支持搜索、按文本/图片/视频类型筛选、按名称分组，以及单个、分组或全部添加；无法识别类型的模型可在添加时选择类型与接口协议。大量模型会按接口上限分批导入，已添加的模型不会覆盖。新导入模型默认停用，需核对生成请求 JSON 后再启用。没有模型列表接口的提供商仍可手动添加模型。

每个模型选择文本、图片或视频类型，并配置请求模板和响应映射。模板中的 `{{model}}`、`{{prompt}}`、`{{image}}`、`{{images}}`、`{{duration}}`、`{{ratio}}`、`{{resolution}}` 等变量由任务填写；完整匹配变量的字段会保留数组、数字、布尔值类型，空值会省略。新增模型时只有与所选接口协议对应的通用 JSON 结构，不预填厂商或模型 ID。可选填写模型单价，提交生成前按已配置价格显示预估费用；未填写时不会假设价格。

文本模型支持 Responses 和 Chat Completions 风格的同步 HTTP 请求。剧本导演对话会优先使用流式接口，按 SSE 或 NDJSON 增量显示回复；模型设置可用 `stream_request_template` 覆盖流式请求体，用 `stream_text_paths` 指定增量文本路径，未显式关闭时会自动补 `stream: true`。界面只展示供应商返回的公开摘要和创作阶段，不透传 `reasoning_content`、`<think>` 等隐式推理内容。图片模型支持返回 Base64 或 URL 的同步接口，也可通过 `async_image: true`、`get_path`、`id_path`、`status_path` 配置异步接口；模型的 `api_base_url` 可覆盖共享提供商地址。图片任务编号会先保存，查询中断或重启后继续查询原任务，避免再次提交生成。视频模型通过可配置的创建路径、状态路径、结果路径和轮询状态处理异步任务。不同厂商的特殊参数可写进模型的 JSON 请求模板或按生成模式设置覆盖值。

RightAPI 绘图按[官方文档](https://docs.rightapi.ai/docs/rc_draw/images-generations.html)配置为 `POST https://www.rightapi.ai/draw/v1/images/generations`，提交 `async: true`、`size: {{ratio}}` 和 `image: {{images}}`（Data URL 数组），再用 `GET https://www.rightapi.ai/v1/tasks/{id}` 获取结果。完整配置在 `backend/src/rightapi-image-settings.ts`；对现有 RightAPI 提供商的三种 `gpt-image-2.5` 模型，可在 backend 目录运行 `node --import tsx scripts/configure-rightapi-images.ts` 预览，添加 `--apply` 后应用并备份旧配置。该命令保留原来的比例选项、单价与共享提供商地址，不调用生成接口，也不会自动切换所选模型；厂商当前服务可用性请查看其模型列表。

画布图片参数默认提供五档画质、1K/2K/4K、自动/保留/透明背景和十三种比例，选择保存在节点上。模型可用 `image_qualities`、`image_clarities`、`image_backgrounds` 和 `ratios` 配置选项，用 `default_quality`、`default_clarity`、`default_background` 配置默认值。图片比例必须通过请求模板的 `{{ratio}}` 比例参数或比例完全一致的 `{{size}}` / `{{resolution}}` 尺寸提交；画布和设定信息图不会把所选比例替换为近似比例。缺少对应配置时会停止生成并提示补齐模型设置，通用初始比例选项不代表厂商的完整能力。最终提示词始终明确整张图片的宽高比例和横竖方向，其他图片要求没有原生映射时也会补充进实际提示词。模板中存在比例字段不代表服务商一定识别或执行，字段和尺寸应以服务商接口说明为准；提示词要求也不保证实际输出尺寸、清晰度或带 Alpha 的透明背景。提交确认会显示请求参数及完整提示词。

新建视频节点默认 480p。比例提供 Auto、16:9、4:3、1:1、3:4、9:16、21:9；清晰度提供 480p、720p、1080p、4K，同时保留模型配置中的自定义选项。图生视频也可选择固定比例，所选比例与清晰度会同步到实际提示词和请求模板变量，优先于生成模式的默认覆盖值；已有节点的明确选择继续保留。

视频模型编辑器提供“应用 Seedance 2.0 配置”，供使用对应官方接口时显式套用，保存后才生效。该配置启用官方图片角色和媒体校验：分镜图包含在最多 9 张参考图内，每图小于 30 MB，宽高为 300–6000 像素，宽高比为 0.4–2.5，含 Base64 的完整请求不超过 64 MB。首帧、首尾帧和多图参考互斥；多图参考中的分镜图默认引导整体构图，可改为开场、过程或结尾用途；这些是提示词引导，不等于严格首帧或尾帧约束。其他厂商的能力由其实际模板和显式配置决定，不通过模型名称推断，也不自动修改已有模型设置。

Seedance 2.0、Fast 和 Mini 视频节点的“整理提示词”会识别官方远程型号与显式方言，加载相应技能参考，并补充主体绑定、动作衔接、主要运镜和声音表达要求。已有模型可单独设置 `max_reference_images: 9`，保留视频参考、编辑和延长配置；图片上限在整理、预览和生成时校验。详见[Seedance 2.0 提示词工作流](docs/seedance-2-0-prompt-workflow.md)。

设定档案支持独立参考图：登记现有图片、从信息图裁切单个视角，或按角度生成 1/2/4 张候选；确认后可按镜头机位选择面部、侧面、背面、场景反向视角和道具细节。镜头保存有序的设定版本快照，分镜图片与视频继承同一份引用；更换默认图不会悄悄替换已有镜头。管理入口位于设定档案的“独立参考图”，镜头选择位于“镜头引用”。详见[多视角参考工作流](docs/multi-angle-reference-workflow.md)。

第一版的通用连接覆盖 JSON REST 接口与固定请求头认证；要求签名鉴权、Multipart 上传或 WebSocket 的厂商仍需增加对应协议实现。

注意：参考视频通常需要厂商可访问的公网 URL。火山方舟 Seedance 的 `asset://` 预置素材地址可在对应模型的 `reference_video_schemes` 中启用；普通本地视频路径或 Files API 的 `file-...` ID 不能直接替代。视频、图片服务返回的临时 URL 会立即下载到本地。

## 技能中心

模型交互机制（提示词、结构化输出、Function Calling、程序控制）的完整清单与使用示例见 [docs/model-interaction-controls.md](docs/model-interaction-controls.md)。

左侧“技能中心”支持搜索 skills.sh 公共目录，也可填写公开 GitHub 仓库扫描其中的 `SKILL.md`。查看技能文档与参考资料后安装，在“应用配置”中选择剧本创作、视觉设定、图片提示词、分镜规划或视频提示词环节，并打开“允许用于创作”。安装、可用状态和实际选择分开；可以启用多个同类备选技能，单次请求最多使用一个主技能和五个辅助技能。

“默认技能”页为五个创作环节配置全局主技能，也可为当前项目单独配置。初次沿用已启用的对应推荐技能，后续安装同类技能不会替换默认；没有可用技能或明确选择不使用外部 Skill 时沿用基础规则。项目配置优先于全局配置。剧本对话、视觉设定整理、分镜规划及图片／视频提示词整理都支持切换本次主技能与辅助技能；临时切换不修改默认，点击“设为项目默认”或“设为全局默认”才持久保存。“加入画布”工作台预选当前默认分镜主技能，点击“开始规划”才请求模型；打开面板和复用已保存分镜不会调用模型。图片与视频节点的“整理提示词”使用已启用的文本模型，查看、编辑整理结果，再点击“应用提示词”。信息图节点同样支持整理完整提示词；预览与生成使用同一份编辑结果，设定版本变化后清除旧的整理结果。整理不自动生成媒体，也不直接覆盖节点内容。

技能与参考文本保存在当前应用数据库的 `installed_skills` 中，记录 GitHub 的具体提交版本。仓库管理、检查更新、更新与卸载都在技能中心；更新保留启用配置，移除仓库来源保留已安装技能。当前执行创作规则，不运行第三方脚本、不接管 Codex/Claude 的全局技能目录；需要外部工具的技能会在详情中标明工具尚未接入。搜索依赖 skills.sh，源码安装依赖 GitHub 的公开接口；目录不可用时可切换到仓库扫描。

模型接口的能力、计费和参数范围由实际厂商决定。剧本草稿和分镜规划需要启用可用的文本模型；常见 JSON 代码块和带推理段落的结构化输出可解析，模型若只返回推理或缺少必需字段仍需检查其输出与配置。分镜一次最多规划 10 场，镜头数留空时模型逐场分析确定，填写时可建议 2 至 8 个镜头，实际按节奏分配；沿用现有数据约束，每场 1 至 30 秒、每镜至少 1 秒，镜头时长之和必须等于场次时长。生成的规划在确认前不会写入项目。旧项目选中的素材会进入时间线；已有分镜和素材可导入项目画布。原视频的动作和穿帮不会自动修复，需要重新审看切点并重拍不连续镜头。接镜审核记录帮助发现并追踪问题，不会自动修复画面，也不会阻止导出用于试看的版本。当前时间线每镜支持一个入片片段，未实现对白/音效轨、多轨字幕或角色一致性系统。需求来源和后续优先级见 [产品分析](docs/product-analysis.md)。
