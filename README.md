# AI 视频工作台

本地运行的 AI 视频创作工作台，将剧本、视觉设定、分镜、图片与视频生成、配音和成片导出组织在同一个项目中。支持自行配置模型服务，项目数据与素材保存在本机。

[快速开始](#快速开始) · [模型配置](#模型配置) · [文档](docs/README.md) · [问题反馈](https://github.com/Ussik/ai-video-creation-tools/issues)

## 核心功能

- **剧本创作**：导入原稿，与文本模型讨论和生成大纲、人物与分集内容，审阅草稿后确认保存。
- **视觉设定与分镜**：管理人物、场景、道具和多视角参考图，按场次规划镜头并调整提示词与时长。
- **节点画布**：连接文本、参考素材和生成节点，管理图片、视频候选及其来源；一个项目可使用多张画布。
- **生成任务管理**：记录任务状态与历史，支持异步任务查询和中断后的恢复。
- **配音与成片**：选择镜头素材、调整取段、加入对白或旁白与背景配乐，检查接镜并导出 MP4。
- **创作技能**：安装和管理 `SKILL.md` 创作规则，为剧本、视觉设定、分镜和提示词整理配置技能。

## 快速开始

需要 Git、Node.js 22 或更新版本，以及 npm。

```bash
git clone https://github.com/Ussik/ai-video-creation-tools.git
cd ai-video-creation-tools
npm ci
npm run dev
```

打开 [http://127.0.0.1:8888](http://127.0.0.1:8888)。开发模式会同时启动前端、后端和共享包监听，按 `Ctrl+C` 停止。

首次安装没有预置提供商或模型。使用 AI 生成功能前，请在“模型设置”中添加可用的模型服务和 API Key；调用费用由所选服务商收取。

### 构建后运行

```bash
npm run build
npm start
```

默认打开 [http://127.0.0.1:8000](http://127.0.0.1:8000)，由后端提供构建后的前端页面。开发模式使用 `8888`，构建后运行默认使用 `8000`。

FFmpeg 通过项目依赖提供，用于本地媒体处理和导出。

## 模型配置

在“模型设置”中添加提供商，填写服务地址、认证信息和 API Key，再同步模型目录或手动添加模型。核对模型类型、接口协议与参数配置后启用；可分别设置文本、图片和视频的默认模型。

| 模型类型 | 接入方式 |
| --- | --- |
| 文本 | Chat Completions 或 Responses；剧本工具对话要求接口支持相应的函数调用 |
| 图片 | 可配置请求模板与响应映射的同步或异步 HTTP 接口 |
| 视频 | 可配置任务创建、状态查询与结果解析的异步 HTTP 接口 |

参考图、分辨率、时长及视频生成模式等能力取决于实际模型和接口配置。模型目录可读取不代表所有生成能力都已验证，接入时应以所用服务的接口文档为准。

配置与协议说明见[提供商接入文档](docs/model-provider-integration-research.md)。该文档包含带日期的调研和兼容记录。

## 基本创作流程

1. 创建项目，填写创作概述并选择画幅。
2. 导入原稿或编写剧本，审阅并保存大纲、人物、场景与分集内容。
3. 选择场次，规划分镜，检查镜头时长与提示词，确认后加入画布。
4. 配置视觉参考，生成或导入图片与视频，比较候选并选择入片素材。
5. 在“成片工作台”调整顺序与取段，配置配音和配乐，审核接镜并导出 MP4。

画布连线组织生成输入和素材来源，成片顺序由成片工作台中的镜头与时间线决定。

## 数据与使用边界

- 默认数据目录为项目根目录的 `data/`，可通过 `VIDEO_STUDIO_DATA_DIR` 指定其他位置。
- API Key 加密保存在本地数据库中；备份时请保留完整数据目录，包括数据库、素材和 `secret.key`。
- 模型调用会将本次请求所需的提示词与参考素材发送到所配置的服务。
- 服务默认监听本机地址，没有账号与权限系统，适用于本机使用。
- 当前每镜支持一个入片片段；通用多轨剪辑、独立音效轨、字幕烧录、转场编辑和自动口型同步尚未接入。
- 生成内容和镜头连续性需要人工审核；参考设定不能保证实际生成结果始终一致。

## 开发与验证

使用 TypeScript 与 npm workspaces：`web/` 为 React/Vite 前端，`backend/` 为 Fastify 后端，`packages/shared/` 保存共享规则与类型。数据使用 SQLite 持久化。

```bash
npm run check
npm run build
npm test
```

可用 `npm run test:web`、`npm run test:backend` 分别运行对应工作区的测试。模拟接口测试不代表真实模型的质量、费用或时延验证。

已有[验证记录](docs/current-status.md)标注了日期与代码基线，阅读时请注意对应版本。
